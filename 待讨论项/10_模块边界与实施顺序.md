- 首期仅售出／删除专用撤销。

用户本次补充要求框架允许各项目自定义生成需求。需要讨论可替换的算法边界，不因此扩大为完整的跨项目通用框架建设任务。

## 仍属候选的工程安排

当前 _Plan 推荐普通 C# 核心与 Runtime 适配分开，以 UGUI 验证；外部宿主中的 Assets/Game/MergeTwo 是候选位置。它们尚未得到本次最终确认。

Tile Entity、Function／Effect 和数据恢复方式确定后，才能更具体地决定程序集、装配器与公开接口。职责先清楚，再决定是否需要单独的类、Manager 或程序集。

| 部分 | 候选职责 |
| --- | --- |
| Core | Entity、Function、候选 Effect、规则、空间关系与业务执行协议 |
| Runtime／Host | 宿主生命周期、输入、EntityView、资源、时间与 Profile 适配 |
| 项目规则 | 产出选择、次数与冷却机制、解锁条件、放置和其它具体玩法策略 |
| 外围适配 | 仓库、奖励队列、活动、钱包、广告等；在需要接入时展开 |

策略边界不自动要求每一个简单方法都建立接口。先用具体变体检查：替换一个生成算法、增加一类 Tile 外观、增加一个气泡变体时，哪些层需要修改，是否容易理解和验证。

## 实施讨论顺序

1. 确定 Tile、Item、Function 与候选 Effect 的职责和最小数据。
2. 明确 Command／Operation、业务结果与表现绑定。
3. 确定保存／恢复、时间输入和关闭协议。
4. 用一个明确标注为测试用途的项目配置，验证生成、移动、合成与关闭重开。
5. 根据已确认范围逐步接入锁、气泡、专用撤销及外围。

测试配置只是验证载体，不将其产出顺序或费用固定为所有项目的玩法。代码、资源、测试余额和宿主位置均应在对应接入方案明确后实施。

## 尚待确定

1. 最终模块位置与宿主接入入口。
2. 核心与 Unity／Profile／资源依赖之间的边界。

4. 用哪些最小变体验证扩展性，避免只验证单一固定玩法。
5. 仓库和待领取队列未来保存完整物品还是创建描述，在哪个阶段另建专题。
6. 什么时候接正式宿主经济与广告，如何沿第 6、7 项保留清楚的结算边界。
