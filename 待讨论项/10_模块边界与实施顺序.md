# 10. 模块边界与实施顺序

状态：**待讨论**。来源：前一轮讨论、_Plan 的 D01–D04／Q01／Q08／Q09；适用用户 2026-09-30 的 [综合选型与非 ECS 原则](../_Plan/02_架构与参考取舍.md)。工程安排待定。

## 讨论前提

需求范围、最终宿主与已有生成类由 [_Plan/09 的 D01–D04、D16](../_Plan/09_决策与接续记录.md#用户已确认)维护，具体路径见 [_Plan/02](../_Plan/02_架构与参考取舍.md#目录与程序集建议)。项目自定生成算法的边界见 [_Plan/05](../_Plan/05_生成器与时间.md)；本篇讨论可替换边界，不扩成完整跨项目通用框架建设任务。

## 工程安排（候选）

宿主及 Assets/Game/MergeTwo 位置已经确认。当前 _Plan 推荐普通 C# Core 与 Runtime 适配分开、用 UGUI 验证，这些内部组织与表现载体仍为候选；Tile 与 Function／Effect 基础职责已经收敛；按 _Plan/10 决定其宿主程序集、启动装配与实际服务接入。

| 部分 | 候选职责 |
| --- | --- |
| Core | Entity、Function、Effect、规则、空间关系与业务执行协议 |
| Runtime／Host | 宿主生命周期、输入、EntityView、资源、时间与 Profile 适配 |
| 项目规则 | 产出选择、次数与冷却机制、解锁条件、放置和其它具体玩法策略 |
| 外围适配 | 仓库、奖励队列、活动、钱包、广告等；在需要接入时展开 |

并非每个简单方法都需策略接口。以替换生成算法、增加 Tile 外观、增加气泡变体为例，检查修改涉及哪些层及是否容易理解、验证。

## 实施讨论顺序

1. 以 [_Plan/10](../_Plan/10_Function与Effect建模讨论.md)的 Function／Effect 模块实现基线对齐宿主工程入口。
2. 明确 Command／Operation、业务结果与表现绑定。
3. 确定保存／恢复、时间输入和关闭协议。
4. 用明确标注为测试用途的项目配置，验证生成、移动、合成与关闭重开。
5. 按已确认范围接入锁、气泡、专用撤销和外围。

测试配置只作为验证载体，不把其产出顺序和费用固定为所有项目规则。宿主位置已明确；后续代码、资源与测试余额仍按接入方案实施，本轮只补文档。

已确认模块的具体开工范围与不依赖宿主的起步顺序，统一见 [_Plan/08](../_Plan/08_实现顺序与验证.md#文档可实施性与当前开工范围)。本篇只裁定正式工程装配，不要求先解决全部外围问题才允许设计基础 Entity／Function／Effect。

## 尚待确定
