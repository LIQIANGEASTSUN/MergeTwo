# 1. Tile 的 Entity 与 EntityView

- _Plan 回写：未授权。

## 已明确的前提

后续使用 Tile 代替 Cell；Entity 表示逻辑层，EntityView 表示表现层。用户倾向 Tile 拥有自己的 Entity 和 EntityView，具体结构继续讨论。

用户描述的未解锁区域至少有三种外观：只有一种沙土图、使用另一种沙土图、沙土上叠有不同物品。外观差异与解锁程度不是同一个维度，同一级锁可以使用不同资源。

用户给出的两阶段示例是：一级锁时只见 Tile 图片，看不到物品或尚无物品；相邻 Tile 发生合成后解锁一次，进入二级锁。二级锁时物品部分可见且有蜘蛛网等遮挡，不能拖拽或点击，可以接收相同物品的合成；这次合成后完全解锁。具体阶段数量与名称可以继续调整。

当前没有可读取的截图附件，本篇仅依据以上文字。

## 对前一轮“轻量格子”建议的修正

多种图片可以通过配置和 Tile 的 EntityView 完成。用户补充的独立解锁进度、邻格触发、内容揭示和物品关系，为 Tile 成为逻辑 Entity 提供了更充分的理由。

“Tile 有 Entity”与“实现轻量”可以同时成立。一个 Tile Entity 可以只包含坐标、配置引用、占位关系和自身必要数据，再按需要装配 Function；无需因采用 Entity 就给每格预建所有物品能力。

## 候选结构

当前更值得验证的候选是 Tile Entity＋Tile EntityView，与 Item Entity＋Item EntityView 分开。以下是职责建议，尚未确认具体类或字段。

| 对象 | 候选职责 |
| --- | --- |
| Board | 建立 Tile 集合、空间查询和占位关系，协调跨 Tile 的操作 |
| Tile Entity | 坐标与 Tile 配置、独立业务进度、占位或待揭示内容；锁是否放这里见第 3 项 |
| Tile EntityView | 创建和刷新地面、沙土、固定遮挡及揭示表现；资源选择来自配置 |
| Item Entity | 物品身份、种类与 Function 自有数据，归属某个 Tile 或其它容器 |
| Item EntityView | 物品外观、拖拽和物品自身的覆盖表现；不决定业务解锁 |

Tile EntityView 与 Item EntityView 可以由共同的表现容器安排层级，逻辑归属不由 Transform 父子关系决定。沙土、蛛网、物品之间的遮挡顺序须能按配置表达。

固定棋盘中的 Tile 身份可能用“棋盘实例＋坐标”确定；是否还需要额外 EntityId，取决于既有 Entity／View 绑定协议。采用 Entity 不自动要求每格生成新的持久 UUID。

## 一级锁下面是否已有 Item

文字示例同时允许“有物但隐藏”和“尚无物品”，二者需保留为不同候选。

| 候选 | 一级锁的数据 | 揭示时 | 需要判断的代价 |
| --- | --- | --- | --- |
| 已有 Item，显示被遮住 | Tile 占位指向完整 Item | 保留身份，改变可见与操作限制 | 锁内 Function 是否运行、是否计入库存，必须有明确规则 |
| Tile 持待揭示内容描述 | 保存将创建的物品种类及必要初始参数 | 揭示时创建 Item，再建立占位关系 | 不应把待创建内容误计作完整活跃物品；创建时机必须稳定 |

“没有活跃 Item”不等于“可以放入普通物品”：Tile 本身仍可限制占用。不能仅靠 Occupant 为空判断可放置。
