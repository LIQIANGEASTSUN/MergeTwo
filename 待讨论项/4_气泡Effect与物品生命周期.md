# 4. 气泡 Effect 与物品生命周期

状态：**讨论中**。来源：用户 2026-09-29 第 4 点。气泡作为 Effect 是用户思路，统一模型与各变体尚未确认。维护与回写见 [索引](README.md)。

## 变体与旧方案差异

用户提出共用“气泡包裹物品”的表现，支持以下变体：

| 变体 | 解锁方式 | 到期行为 |
| --- | --- | --- |
| 条件解锁气泡 | 点击展示付费／广告等条件，满足后解锁物品 | 用户未规定必须有期限 |
| 带期限的条件解锁气泡 | 同上，另有倒计时 | 到期仍未解锁时销毁该物品 |
| 其它气泡 | 后续按实际需求增加 | 按对应规则定义 |

[_Plan/05](../_Plan/05_生成器与时间.md)讨论到期替换为指定物品，并有选择保护；新样例包含到期销毁。设计需表达相应变体，旧替换行为和选择保护不能自动成为所有气泡的规则。

逻辑可选同一 Effect 的不同配置或不同 Effect 实现；按业务差异规模比较。共用外观可以复用表现，不宜因此把全部规则塞进庞大的条件分支。

## Effect 与内物（候选）

若采用 Effect，可由它记录解锁条件、可选期限和结束原因；实例 ID、来源、层数是否必要，统一在 [第 2 项](2_Function与Effect及State的职责边界.md)讨论。

解锁成功后移除气泡影响，保留或创建可操作物品；到期则按变体销毁、替换或执行其它明确结果。EntityView 展示结果，显示倒计时不决定业务期限。

| 候选 | 表达与优点 | 需要确定 |
| --- | --- | --- |
| 原 EntityElement 已存在，气泡附着在它上面 | 解除后保留同一物品身份与 Function 数据；适合对现有物品施加影响 | 包裹期间哪些能力暂停、哪些字段仍推进 |
| 包装对象持待生成内容 | 解锁时才创建 EntityElement；适合尚未形成完整实例的奖励 | 谁是 Effect 宿主；是否真的应使用 Effect 而非独立容器／物品 |

只保存种类无法承诺恢复生成器完整进度；一物一格模型也不能为气泡暗建两件同时参与查询、计数的活跃物品。

付费／广告窗口发起请求、展示进度；回调时重新检查目标身份、气泡存在性、到期与已处理标记，防止解锁／到期／移除重复结算。通用关闭与绑定保护见 [第 8 项](8_时间推进与表现生命周期.md)，本轮不接真实支付或广告。

## 尚待确定

1. 是否把气泡作为 Effect，以及两个已描述变体如何复用逻辑与表现。
2. 气泡宿主是谁，内部 EntityElement 是否已存在，解除后身份是否保留。
3. 期限、解锁条件与结束行为哪些可配置，哪些应由独立实现承担。
4. 与 Tile 锁等其它影响同时存在时，移除气泡后如何重新计算权限。
5. 解锁回调、到期、物品移除和界面关闭同时出现时，如何保证同一结果只处理一次。
