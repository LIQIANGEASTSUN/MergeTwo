# 2. Function、Effect 与 State 的职责边界

状态：**讨论中**。来源：用户 2026-09-29 第 2、5 点及 2026-09-30 原则；10 个项目的分析报告。最终结构未确认，适用 [索引中的非 ECS 与综合选型原则](README.md#方案选择原则已确认2026-09-30)。

## 要解决的概念问题

用户要求严格区分 Function、Effect 与 State，评估是否需要 Effect、是否可将附加限制类 State 合并进去，以及二者并存是否过重。Travel Town 用 Component 保存 Lock 等事实，是比较这些职责的一种参考。

此前助手把“当前数据”与“State 架构模块”混用，造成歧义。下表为候选定义；生成字段归属的已确认结论见 [第 5 项](5_生成Function的数据归属与扩展边界.md)。

| 概念 | 候选职责与例子 | 边界 |
| --- | --- | --- |
| Function | 一项业务能力及其专用字段，如生成、合成、使用、响应邻格事件 | 可有自有数据记录便于保存，无需由此另立 State 层 |
| Effect | 附着在宿主上的玩法影响，按规则添加、解除或结束；可限制能力或增加触发后果 | 如气泡、限时冻结、外部冷却倍率；具体装配未定 |
| 当前值与局部阶段 | 剩余次数、截止时间、气泡解锁进度；未开启／开启中／可领取 | 留在所属 Function／Effect；enum 是局部选择 |
| 通用 State 框架 | State 基类、StateManager 或状态实例集合 | 属独立选型，目前未确认必须建立 |
| EntityView／表现 Function | 显示业务事实与结果 | 外观相同不决定是否同一种 Effect |

Effect 的语义与其代码基类分别讨论：可用专门处理器，也可复用 Function 装配；需比较生命周期、同类多份和解除规则。引用参考类名 State 时保留原名，说明它是数据还是行为对象。

Buff 类比可用于理解冰冻、沉默、临时减少冷却、增加暴击／穿透等附加影响。例如基础暴击率 10% 是属性值，某来源限时增加 5% 含来源与生命周期，可作为 Effect／Buff 候选；正常生成次数与冷却仍归生成 Function。此类比不要求引入 MOBA／MMORPG 的整套属性、技能和同步框架。

可讨论将附加限制类 State 统一为 Effect、内部字段留在 Function，从而避免同一限制保存两份可写数据；此简化方向尚未定案。

## 非 ECS 的候选结构

| 结构 | 适合之处 | 需要承担的成本 |
| --- | --- | --- |
| Function＋内部字段，锁／气泡也作为专用能力组件 | 复用一套装配方式，类型较少 | 要明确能力与限制的查询、解除、同类多份规则，不能只按 FunctionType 去重后丢掉来源 |
| Function＋Effect，局部数据各自拥有；不建立通用 State 层 | 能力与附加影响的语义清楚，便于统一附加／移除与权限查询 | 需要一个足够小的 Effect 协议；避免再复制一套执行队列、存档和事件系统 |

助手倾向第二种作为起点，第一种仍有效，也可以提出其它非 ECS 方案。用“生成器附加冻结后解除”和“两种气泡变体”比较新增／修改位置、可理解性与复杂度，再选型。

## ECS 参考中可以借鉴的思路

以下为候选借鉴方向，具体接口和管理器按实际需求决定：

| 参考思路 | 在本项目中的候选用法 |
| --- | --- |
| 把身份、位置、能力数据与附加限制的职责分清 | 明确 Entity、Function 自有数据与候选 Effect 的数据归属，避免同一事实重复保存 |
| 通过能力组合表达物品差异 | 按配置装配所需 Function，实际需要时附加 Effect，减少为每种组合建立物品子类 |
| 相同规则由多份实例共用 | Function 保留实例字段，通过普通规则函数或策略复用算法；不要求建立按组件查询实体的 System 执行体系 |
| 能力存在与当前能否执行分别表达 | 锁定或冻结期间保留生成 Function 及其数据，通过统一资格查询控制执行 |
| 规则执行顺序与结果可观察 | 在本项目选定的执行入口明确先后和结果，参考项目的 System 顺序不直接成为本项目约束 |

## 尚待确定

1. 是否需要独立的 Effect 业务概念与装配协议；是否复用 Function 的基础设施。
2. 是否同意不建立通用 State 层，让能力字段、效果字段和局部阶段留在所属对象。
3. 首批需求是否真的需要同类型多个 Effect、独立来源和分别到期；按真实需求确定最小字段。
4. 新增一种 Effect 时，需修改哪些位置，如何保证手动、自动和被动目标入口都使用同一权限规则。
5. Tile 的解锁阶段如何落入最终模型，由第 3 项的具体示例验证。
