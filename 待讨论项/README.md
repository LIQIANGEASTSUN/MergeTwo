## 维护规则

用户已明确要求按主题编号建文档、确认后标记、增加新议题、删除过时文档，并严格确认对 _Plan 的修改。以下据此约定具体维护方式。

1. 每个独立主题使用“编号_名称.md”。本次采用的编号维护约定是：新主题使用当前最大编号加一，保留既有编号，删除后的编号不复用；这项维护约定可调整。
2. 主题使用“待讨论”“讨论中”“已确认”状态。只有用户明确确认结论后才标记“已确认”；“倾向”“可以考虑”“继续讨论”和 Agent 的推荐均不等于确认。
3. 一份文档可记录已经明确的前提，但只要核心选型仍未定，整篇仍为“讨论中”。已确认的文档继续保留，便于追溯。
4. **确认讨论结论与授权回写 _Plan 分别记录。** 回写前列出拟修改的文件、具体结论和替换范围，取得用户明确确认后再改。用户若已同时确认结论与明确的回写范围，就直接执行，不重复询问。
5. 新问题落入既有主题时更新该文档；出现独立的新主题时新增编号文档，并更新本索引。
6. 已过时、被替代或废弃的讨论文档应删除，同时清理索引和引用。仍有价值的已确认内容先移入承接文档；已确认本身不是删除理由。
7. 参考项目的事实、用户明确结论、用户倾向、助手候选建议分别标明。不能把逆向样本的做法直接登记为本项目需求。
8. 讨论顺序以概念与扩展边界为先。具体项目的产出顺序、费用、次数和冷却算法不作为本轮架构定稿的前置问题。
