## 回写管理

**以下是后续 Agent 与程序员接手时持续执行的维护要求。每轮讨论结束或交接前，都应检查并整理，不能仅把已结束的文档标记为“已确认”后长期保留。**

1. 同一问题由一个主题维护，其它文档链接引用；新问题归入已有主题，确属新主题时再新增“编号_名称.md”。
2. 区分参考事实、用户确认、用户倾向和助手候选。只有用户明确确认的范围才能写成定案；Agent 共识不能代替用户确认。
3. 确认后同步 `_Plan` 对应正文、样例与验证，并在 09 登记决策。已有回写授权无需重复询问；确认范围不清楚时，先明确范围。
4. **核对结论与必要依据已进入保留文档、未决问题已解决或迁入对应主题后，删除已收敛的讨论文件。** 用户已授权按此条件继续整理，无需对符合条件的删除逐次询问。仅“讨论过”不代表已确认；部分确定的主题保留未决内容及必要上下文，已确认细节引用 `_Plan`。
5. 过时、被替代的文档先迁移仍有价值的内容，再删除；不另存一套重复的讨论归档。参考原有事实不能因本项目选型而改写。
6. 删除后同步索引、交接说明和正文引用，检查文件路径与章节链接；交接时简要说明删除了哪些主题、结论保留在哪里、还剩哪些未决问题。后续读者应能只通过 `_Plan` 了解全部已确认内容。
