# 8. 时间推进与表现生命周期

状态：**待讨论**。来源：前一轮讨论、_Plan 的 Q06／Q07／Q10。统一调度、时间表示与生命周期协议未确认；维护与回写见 [索引](README.md)。

本篇集中讨论时间输入、到期执行、关闭／取消及回调失效。生成轮次、具体间隔、离线产量等算法仍由项目定义，见 [第 5 项](5_生成Function的数据归属与扩展边界.md)。

## 职责与时间表示（候选）

| 职责 | 候选拥有者 |
| --- | --- |
| 提供当前业务时间与应用前后台输入 | 宿主适配层 |
| 保存某项能力的计时依据 | 对应 Function |
| 保存附加影响的期限 | 对应 Effect（如果选用） |
| 决定到期后的业务结果 | 对应规则，沿第 6 项确认的执行入口提交 |
| 显示倒计时、安排飞行或揭示节奏 | EntityView／表现 Function |

生成冷却归对应 Function；气泡期限是否存在由 [气泡变体](4_气泡Effect与物品生命周期.md)定义。共享时间输入允许各机制选择截止时间、累计进度或暂停剩余时间，无需预建包办所有计时的 State 系统。

## 时序与回调

- 候选约定：动画结束／取消仅处理表现收尾，不重做业务结算。若解锁、扣费或生成依赖动画回调，关闭、取消或缺失 View 就会影响业务；确需等待的业务阶段应表达为逻辑事实。
- 原 CommandRuntime 重入提交会排队。在 Consumer 中提交时间命令后，不能假定它已执行。若采用先推进必要时间再处理玩家请求，执行封装须明确顺序与失败处理。
- 持久 EntityElement ID 无法单独判断旧 View 回调是否有效。候选保护应覆盖棋盘重建代际、每次 View 绑定，以及删除后恢复同一 EntityElement 的情况。执行入口见 [第 6 项](6_Command与Operation执行边界.md)，撤销恢复见 [第 9 项](9_售出删除的专用撤销.md)。

## 尚待确定

1. 时间服务接入哪个宿主入口；怎样处理单位、回拨和一次操作内的统一时间取样。
2. 由谁触发到期检查，如何让未显示或受限制对象按自身规则继续推进。
3. Function／Effect 如何声明到期结果，怎样进入业务执行主线。
4. 隐藏、关闭、重新打开时，选择、未完成窗口和表现资源怎样处理。
5. 取消与迟到回调如何检查身份和绑定，避免作用于复用后的对象。
6. 是否需要共享调度器，还是当前规模可用直接扫描；按实际机制决定实现复杂度。
