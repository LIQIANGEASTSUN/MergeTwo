## 职责与时间表示（候选）

| 职责 | 候选拥有者 |
| --- | --- |
| 提供当前业务时间与应用前后台输入 | 宿主适配层 |
| 保存某项能力的计时依据 | 对应 Function |
| 保存附加影响的期限 | 对应 Effect |
| 决定到期后的业务结果 | 对应规则，沿 02b 已确认的 Command／Operation 入口提交 |
| 显示倒计时、安排飞行或揭示节奏 | EntityView／表现 Function |

生成冷却归对应 Function；气泡的可选期限及弹窗保护见 [_Plan/05](../_Plan/05_生成器与时间.md#气泡-effect-与生命周期)，不是简单选中保护。共享时间输入允许各机制选择截止时间、累计进度或暂停剩余时间，无需预建包办所有计时的 State 系统。

## 时序与回调

- 模块约定：动画结束／取消仅处理表现收尾，不重做业务结算。若解锁、扣费或生成依赖动画回调，关闭、取消或缺失 View 就会影响业务；确需等待的业务阶段应表达为逻辑事实。
- D43 沿用 CommandRuntime 的普通 FIFO，重入提交会排队。在 Consumer 中提交时间命令后，不能假定它已执行。若采用先时间后玩家请求，应由输入适配明确提交次序或在同一业务求解入口组织相关步骤，不能默认给 Runtime 增加前置／插队通道；具体方案在本题确定。
- 持久 EntityElement ID 无法单独判断旧 View 回调是否有效。按 _Plan/10 的宿主会话、View 绑定版本、Effect 运行键与资源请求版本保护，继续确定宿主取消入口及删除后恢复时的接入。执行入口见 [02b 正式执行方案](../_Plan/02b_Command与Operation执行方案.md)，撤销恢复见 [第 9 项](9_售出删除的专用撤销.md)。

## 退场对象的引用与最终释放

业务移除立即退出活跃查询、释放格子；退场动画使用已有的旧外观／效果副本。HomeHub 对仍被 View 引用的 Entity 使用退役 Ticket，View 收尾后最终 Release；二合若能完全解除逻辑引用，也可只保留表现副本与资源。本题按宿主 View 绑定方式确定接线，不能在未解绑时提前释放仍被使用的对象，也不要求占位等待动画。

最终释放的专用 Command 如采用 H 方式，沿普通 FIFO；只回收独立 Graphic 资源则由其拥有者直接完成。关闭时先停接收，Graphic／Logic 各自清理全部资源和活跃／退役对象，不等待已被清队的命令。是否需要自动故障重建须按真实需求单独确定，D43 的基础 Runtime 不默认停掉整个实例。

## 同步气泡窗口失败的宿主接入（D47 移交）

执行核心和关闭／到期 Operation 已在 [02b 第 5 节](../_Plan/02b_Command与Operation执行方案.md#5-二合-operation-的实施契约)明确，本题只落实宿主窗口服务。已确定的约束是同步打开、按原 FIFO 提交后续命令、匹配当前会话／元素／气泡／交互、失败不永久遗留保护；不引入 Runtime 插队或异步开窗阶段。

正常链路为 BeginBubbleInteractionOperation.Apply 建立交互 → Graphic Consumer 同步打开窗口 → 关闭／条件结果提交 Command → 对应 Operation 清理或解泡。窗口同步创建失败时，桥接先清理局部 UI，再提交匹配的 EndBubbleInteractionCommand；重入只入队，不能把这个 Submit 的 true 当作交互已经清理。

实施真实适配前核对并明确：

1. 宿主窗口 API 是否返回成功／实例，可能抛出什么可处理异常；创建一半时谁负责回收，必需窗口 Consumer 怎样确保已注册。
2. 结束请求排队期间，怎样避免无效交互被当作真实有效窗口保护，怎样防止重复 Click 聚焦不存在的窗口；不能让 UI 直接改 Effect 字段，也不能假设没有其它命令已排队。
3. 正常关闭、同步打开失败、整体 Hide／Dispose 各从哪里进入；防止重复 Close 触发二次业务。运行实例已结束则走释放路径，不向已关闭 Runtime 反复提交。
4. 关闭时用哪个业务时间判断到期，广告覆盖／支付回调怎样与窗口有效性接续；旧窗口不能清新泡／新交互。

验收至少包含：创建成功后到期保护、创建失败且已有其它命令排队、重复 Click／Close、故障期间关闭实例、同一元素解除后新泡收到旧回调。实际 API 未核对前，不将“普通 FIFO 提交清理”写成所有失败分支已解决。已确认的气泡玩法不在本题重开。

## 尚待确定

D34／D36／D40 已确认：窗口同步打开，无异步开窗流程；气泡弹窗未关闭时，倒计时到 0 仍保留元素且可解锁；正常主动关闭已到期弹窗，逻辑立即销毁，表现随后播放动画。本文不重开这些规则。继续确定广告覆盖、异步支付进行中关闭、应用退出／重开：建议运行交互键不持久化、广告覆盖保留原交互、条件结果未返回时禁普通关闭；均须结合宿主实际接口确认。强制退出后的外部成功凭据不能直接携旧 RuntimeId 修改新会话，按宿主凭据恢复协议接续。

对象已经到期但受弹窗保护时，调度不得重复注册过去的期限；解除／关闭交互后重新推进一次。窗口／View 的 Release 只清资源，业务关闭通过释放前的显式入口完成。同步受理、打开及到期边界的工程轮廓见 [_Plan/05](../_Plan/05_生成器与时间.md#同步弹窗与执行流程)；这里负责宿主时间、队列和取消接线。不能把 EffectView 通用资源的异步保护套成气泡窗口的加载流程。

1. 时间服务接入哪个宿主入口；怎样处理单位、回拨和一次操作内的统一时间取样。
2. 由谁触发到期检查，如何让未显示或受限制对象按自身规则继续推进。
3. 宿主怎样驱动 Function／Effect 的到期求解，并沿 02b 的执行入口提交一次结果。
4. Tile／Element 各自的 View 怎样按需创建、绑定、解绑和回收；隐藏、关闭、重新打开时，选择、未完成窗口和表现资源怎样处理，避免无用的逐对象 Update。
5. _Plan/10 的取消与绑定校验怎样接入宿主资源服务、窗口、回池与账号切换。
6. 是否需要共享调度器，还是当前规模可用直接扫描；按实际机制决定实现复杂度。
