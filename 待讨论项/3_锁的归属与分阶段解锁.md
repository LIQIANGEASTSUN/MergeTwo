# 3. 锁的归属与分阶段解锁

状态：**讨论中**。来源：用户 2026-09-29 第 1、3 点。一级锁进入二级锁时创建元素已由 D17 确认；锁归属、具体阶段模型与权限仍待讨论。维护与回写见 [索引](README.md)。

## 用户提供的玩法样例

一级／二级锁是讨论用语，阶段数量、枚举名和数字值可调整，旧 R／L 的编号不直接作为新规则。外观配置见 [_Plan/06](../_Plan/06_表现与资源.md#tile-与-element-的表现d10d11-已确认)。

| 阶段 | 可见内容 | 主动操作 | 被动触发与变化 |
| --- | --- | --- | --- |
| 一级锁 | Tile 的沙土等图片；不创建 EntityElement | 没有可操作的物品 | 相邻 Tile 上合成，触发解锁一次，进入二级锁时创建 EntityElement |
| 二级锁 | 已创建的元素部分可见；保留蜘蛛网或其它遮挡 | 用户描述为不能拖拽／点击 | 拖入相同可合成物，完成合成并再次解锁 |
| 完全解锁 | 正常 Tile 与物品表现 | 按物品能力操作 | 按已配置规则响应 |

## 与旧方案的差异

[_Plan/04](../_Plan/04_棋盘交互与合成.md)将浅锁列为“可选中”，用户新样例描述二级锁“不能点击”。需明确选择、信息展示、激活各自是否允许，当前保留用户描述。

此前助手的“地图锁归 Tile、生成浅锁归 Item（现称 EntityElement）”未确认；旧选择题由本篇开放讨论承接。用户已确认格子采用独立 EntityTile／EntityViewTile，物品改称 EntityElement；命名沿用用户现有 Tile 类，锁归属仍由本篇讨论。

## 锁归属候选

| 候选 | 表达方式 | 需要检验的问题 |
| --- | --- | --- |
| 进度与限制都在 Tile | Tile 保存解锁阶段，并限制当前内容或占位 | 物品移走／销毁后 Tile 的进度是否保留；独立生成的锁物如何表达 |
| 限制主要在 EntityElement | EntityElement 持锁；Tile 提供外观或待揭示内容 | 一级锁尚无 EntityElement 时由谁持进度；不能仅为挂锁强造一件正常物品 |
| 按事实分属 Tile 与 EntityElement | Tile 持区域揭示进度，EntityElement 持自身附加限制 | 两者必须是真正不同的事实；不能给同一个锁存两份可写阶段 |

第三种只在确有两份独立事实时使用，不要求每格同时有两种锁。Function／Effect 基础实现已收敛，见 [_Plan/10](../_Plan/10_Function与Effect建模讨论.md)。本篇决定锁归属与具体表达；先验证 EntityElement 后再评估 TileEffect，不重新引入独立 State 层。

## 用解锁过程检验归属

普通 A 合成进二级锁同类 B、产生 C 的完整执行示例由 [第 6 项](6_Command与Operation执行边界.md#用当前需求验证)维护。本篇须明确谁接收请求、谁检查被动目标资格、哪份锁改变、外观如何撤去，以及独立限制是否由 C 继承；不能默认复制全部旧字段。

[_Plan/03 的 D17](../_Plan/03_状态模型与Profile.md#一级锁揭示时的元素创建d17-已确认)已确认一级变二级时首次创建 B；一级锁下没有该元素实例。创建、占位与解锁须形成完整业务结果供表现使用；已有二级锁元素读档时恢复其记录，不能再次按首次揭示创建。

## 尚待确定

1. 两阶段样例对应的事实分别归 Tile 还是 EntityElement。
2. “不能点击”是否同时禁止选择与查看信息；可作为被动合成目标的条件如何表达。
3. 一级锁没有 EntityElement；揭示时的元素配置／初始参数从哪里取得，内容描述与解锁进度由谁保存。现有 Tile 外观配置 ID 的用途不因此自动扩成产物配置。
4. 物品移动、被销毁或替换后，哪些 Tile 事实继续存在。
5. 地块进度与气泡等物品影响同时存在时，权限、解除与表现如何组合。
6. 邻接触发应由哪个 Function／规则入口组织；具体四邻或八邻不在这里预设为所有项目通用规则。
