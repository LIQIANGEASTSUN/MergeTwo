# 表现、配置与资源接入

**D72 已确认：首版二合采用 UGUI 棋盘。** EntityViewTile／EntityViewElement 及 EffectView 使用 UGUI 载体，接宿主输入和 UI 生命周期。旧包美术与布局可按实际资源条件参考，具体复用范围和资源接线仍待工程接入；UGUI 的确认不等于批准直接复用旧 Prefab。规则与存档保持既定职责，换视觉载体不应重写合成与生成器。

所有格子功能相同，配置 ID 目前只区分外观，不据此装配不同逻辑能力。外观差异与解锁程度分开描述，同一阶段可使用不同沙土等资源，不能从外观 ID 推断解锁进度。坐标与配置 ID 进入 Tile 自己的存档，恢复以存档为准。配置 Tile、存档 Tile 和逻辑 EntityTile 的职责分别是只读配置、玩家记录与运行对象，代码引用时用命名空间或别名区分。

两种 View 分别绑定各自 Entity；叠放资源的显示层级可组合，Transform 父子关系不决定数据归属。D25 确定 Element 实际挂载来自 Tile 的锁 Effect；二级锁蛛网按用户倾向由该效果的 EffectView 创建，接线见下节。公共 View 基类和资源池协议尚未定案。

先建立全部格子和元素的逻辑关联，再启用依赖完整棋盘的行为；View 显示已有结果，表现加载或动画回调不补占位。流程见 [03](03_状态模型与Profile.md#保存与恢复)。

D17 已确认：一级锁没有 EntityElement，也不为它创建 EntityViewElement；进入二级锁时创建逻辑元素，再绑定对应 View 显示。创建依据逻辑阶段变化，动画仅负责揭示过程。

## Function／Effect 的表现接入

D23 已将对应关系与实现约定收敛到 [10 第 5–7 节](10_Function与Effect建模讨论.md#5-effectview-的创建与同步)：EntityViewElement 通过 FunctionViewEffects 管理可选 EffectView；独立资源各自管理，共享视觉贡献由 EntityViewElement 汇总写入。同步使用当前只读快照，Bind／Refresh／Unbind 不改变业务数据；旧回调检查宿主、绑定、效果运行键与资源请求版本。D20／D22 要求界面使用方法＋bool 查询，不由动画回调直接设置逻辑权限。

### Logic 到 Graphic 的最小数据交接

业务通过 02b 第 5 节的 Operation 结果交接只读显示数据；表现 Consumer 据结果更新 View／EffectView，独立模块验证可直接提供同样数据。这里不要求新建全局事件总线。

| 数据 | 由谁提供 | Graphic 如何使用 |
| --- | --- | --- |
| Tile 当前显示数据 | Tile 的配置 ID、坐标、解锁 Function 的只读阶段 | EntityViewTile 初始化／刷新地面与一级锁外观 |
| Element 当前显示数据 | 活跃实例身份、配置 ID、坐标，以及显示实际需要的能力数据 | EntityViewElement 显示元素；对应表现 Function 按稳定槽位取得自己的只读数据 |
| Effect 显示列表 | Element 当前 Effects 的类型、RuntimeId、表现键与必要显示字段副本 | FunctionViewEffects.SyncEffects 对齐 EffectView；纯逻辑效果无需生成可视实例 |
| 一次性表现数据 | 成功业务结果中的旧／新位置、外观及需要的动画信息 | 播放移动、合成、揭示；旧数据在修改／释放逻辑前捕获 |

D54 明确 EntityView 持有对应 Entity 引用，通过其查询读取数据；绑定和退场期间都不由 Graphic 修改 Profile 或执行逻辑 Function。`CaptureViewData` 仍可提供一次性动画和 EffectView 所需的稳定字段副本，但不要求所有 View 只持副本。数据查询不外放可写集合／可变 Pos 供 UI 修改；表现配置键是普通标识，Logic 不加载 Prefab。

一次完整逻辑修改后，由调用它的应用／执行入口采集受影响对象的当前数据并交给 Graphic；Function／Effect 不直接调用自己的 View。重建 View 只用当前数据，连续动画用对应次的旧／新结果，不能把当前快照当作过去发生过的事件。生成倒计时等 Function 的显示数据也走同一路径，无需为每个 Function 强造一个 EffectView。

选择事实由逻辑的当前选择记录维护，选择框与果冻曲线由表现维护；点击先查询选择资格，再在成功选择后显示相应反馈。纯点击动画无需写存档；它是否伴随其它持久业务后果由实际交互规则决定。现阶段可用固定数据验证绑定、效果同步与点击显示，真实输入转 Command 的载荷及处理按 02b，宿主输入装配归第 10 项。

### 气泡覆盖与解锁弹窗

D31：`EntityViewElement` 继续显示原元素，`EffectViewBubble` 添加气泡外壳，不创建另一份元素 View。外壳命中应转交所属元素的输入入口，允许选择和拖动；不能把整个 GraphicRaycaster／碰撞入口关闭。气泡和蜘蛛网各自管理资源，视觉顺序按挂点／SortOrder 明确，逻辑 Priority 不直接决定绘制层级。

既有 Graphic 窗口入口消费成功的 `OpenBubbleDialog` 结果；气泡逻辑、EffectViewBubble 均不承担整个支付窗口的所有权。D40 已确认窗口同步打开，直接调用宿主同步窗口 API，不加入异步加载流程或加载等待状态；D62 下窗口打开成功并绑定 EntityElement 后提交 CommandBeginBubbleInteraction，由 Command Consumer 创建 Operation 写入保护。结果提供会话、Element.InstanceId、Effect.RuntimeId、交互键及必要的条件显示数据／可选截止时间。UI 显示倒计时，提交解锁或主动关闭请求，不能直接 RemoveEffect、销毁元素或改期限。重建单个 EffectView 也不自动再次打开窗口或刷新交互保护。

弹窗显示与逻辑生命周期见 [05](05_生成器与时间.md#气泡-effect-与生命周期)：计时为 0、交互仍有效时显示 0 并保留解锁入口；条件可用性按逻辑方法查询。D59 下同步开窗失败视为没有打开，不建立保护、不增加气泡失败补偿。旧的先保护再开窗方案已撤回；窗口发起建立／取消保护，实际修改按 05 的 D62 执行链完成。当前窗口回调校验原会话、元素、效果与交互键；D60 的跨重启支付结果使用持久支付关联，不能要求旧窗口存在，亦不能作用于后来新气泡。D37 下直接订阅 Click，拖拽本身不触发 Click；无需气泡自己的手势防抖层。

D39：二级锁 Effect 先处理交互，仅保留选择框与果冻反馈，不打开气泡窗口；逻辑解锁请求也须拒绝。两份 EffectView 可以同时保留各自覆盖物，优先级不等于删除／隐藏低优先级效果；具体蛛网与气泡的资源排序由表现配置决定。Tile 完全解锁后只移除格锁效果，下次 Click 才按仍存在的气泡处理。

| 业务结果 | 逻辑已经完成什么 | Graphic 接着做什么 |
| --- | --- | --- |
| 解除气泡 | 原 Element 保留，仅移除本次气泡；其它 Effect 继续存在 | 移除对应 EffectViewBubble，可播放破泡动画；不释放原 EntityViewElement，不清理其它特效 |
| 到期后主动关闭弹窗（D36，无 WaitPay 保护） | 立即销毁原 Element、释放占位、使窗口和效果失效 | 旧 View 持有已退役 Entity 及必要的旧显示字段播放消失动画，随后解绑 View 并最终释放 Entity |
| 气泡参与移动／腾位 | 气泡可以在源或目标；相关坐标及 Tile 占位已更新，身份与期限保留 | 空格落入播放单元素移动；有占位播放双方移动，中断时对齐当前坐标，不重新求落点或执行移动 |

D57 下倒计时由 OperationRefreshTimeDisplay 的 Graphic Consumer 按传入 T 刷新；Apply 不写业务，无 View 正常空处理。D58 下广告覆盖／后台保留有效窗口保护，返回先检查时间。支付等待的持久保护见 05；D63 下支付失败只清 WaitPay，窗口未关闭仍提供保护。窗口自身及 ActiveDialogId 不存档。

逻辑已销毁的退场 View 不再接收输入、不计占位；按 D54 保留对退役 Entity 的只读使用及自身退场资源，不修改 Effect 或已移出根的记录。无需动画完成回执才能释放格子；新元素占用旧格时，旧动画只能回收它自己的资源，不能通过坐标移除新 View。不同效果共用材质等资源仍按 10 的贡献汇总处理。

### 二级锁的蜘蛛网、选择框与点击反馈

D26 已确认二级锁元素可点击选中，显示 UI 选择框，并播放 Scale 果冻弹动；不能因禁拖拽而禁掉整个点击命中。蜘蛛网按用户倾向采用以下实现：

- `EffectTileLock → EffectViewTileLock`：由 FunctionViewEffects 创建、刷新、释放，资源挂在 Element 的表现挂点；Tile 完全解锁后逻辑效果移除，相应蜘蛛网退场。只撤回自身资源／贡献，不删除气泡等其它效果。
- 一级锁沙土仍由 EntityViewTile 显示；一级锁下没有 ElementView 或 Element 的 EffectView。
- 选择框由元素选择表现维护，不能把框的存在或点击动画完成当成解锁条件。重复点击可以重播反馈，是否激活另查动作权限。
- 建议果冻动画作用于 Element 的视觉根节点，蛛网挂在该节点下随之缩放；选择框使用独立 UI 层。蛛网命中须透传到所属元素，避免覆盖物截断选择输入。具体资源挂点与气泡遮挡层级在资源接入时确定。
- 同一元素只保留一条当前点击弹动曲线；连续点击停止／替换旧反馈，并回到当前基础缩放。若其它 Effect 也贡献缩放，走 EntityViewElement 的统一视觉贡献入口，不能由多个 Tween 直接争写同一 Transform。
- 重开 View 从当前效果快照重建蛛网，选择恢复策略按交互专题处理；不重播历史揭示或点击动画，不因 View 重建而修改 Tile 进度。

## 表现消费什么

Logic 先完成一次业务变化，Graphic 再消费包含前后状态的结果。动画可以延后显示某些结果，但不得延后真正扣费、创建物品、占格或解锁。

| 业务结果 | 表现工作 | 取消后的稳定画面 |
| --- | --- | --- |
| Move／Swap | 按结果目标格移动 View | 对齐当前逻辑位置 |
| Merge | 两个旧 View 汇聚、退场，新 View 出现 | 只保留新实例及已确定附加物 |
| Generate | 生成器点击、飞出产物、刷新余额与次数 | 已生成物在各自权威格，费用只扣一次 |
| UnlockTiles | 一级锁揭示、元素出现／目标二级锁解除 | 按 Tile 当前进度、元素占位与运行锁效果重建两类 View |
| BubbleExpire／Unlock | 解除仅去掉气泡；到期销毁使用旧外观退场 | 显示已完成结果，不等待动画再删除逻辑元素，不在解锁时重建元素 |
| Remove／读档重建 | 移除外观，或按当前记录重建外观 | 表现反映逻辑结果，不以动画决定业务删除或保存；D71 不提供撤销入口 |

合成先完成再出现气泡／衍生是**表现顺序**。这些附加物可以已在逻辑中占格、暂时隐藏 View，主动画到相应节点后显示。若期间发生新操作，表现必须处理已提交结果之间的冲突，不能让隐藏物被误当成空格。

Operation 结果需要包含旧外观和旧位置，不能在异步回调里重新读取一个已释放的 Entity 来补全动画数据。对于快速连续命令，结果有执行序号与实例身份；不只按“目标格”识别对象。

## Entity、View、GameObject 的寿命

**D54 已确认：View 持有 Entity；业务删除立即移除地图存档与活跃索引，保留旧 Entity 供 View 读取，表现结束后移除 View。** 采用三合的数据持有思路，参考 HomeHub 显式区分逻辑退役和最终 Release；原“只保留表现副本、立即释放 Entity”的主方案撤回。

### 三个时点

| 时点 | Logic／Profile | Graphic |
| --- | --- | --- |
| 正常存在 | Entity 在活跃集合，Profile 记录在 MapData，Tile 保存运行占位 | View 持有 Entity 引用，按查询读取数据 |
| 业务移除，开始退场 | 从 MapData 移除原记录；清占位／选择，移出所有活跃查询；停止时间 Consumer、事件及其它主动能力。保留退役 Entity 和它的数据引用 | 旧 View 禁止新输入，继续通过已持有引用读取退场需要的数据；EntityManager.GetEntity(旧 InstanceId) 返回空 |
| 表现完成／取消后 | 最终 Release 退役 Entity，解除其 Function／Effect／Profile 引用 | 先解绑并释放旧 View／EffectView／资源，再允许最终释放 Entity；两端清理幂等 |

**退出地图存档与 C# 对象仍被引用可以同时成立。** ProfileHub 保存 MapData 当前集合，View 持有旧 Entity／已移出集合的旧记录不会把它重新加入存档。退场期间退出，数据已经表达删除结果；正常退出保存沿用宿主，不等待动画。这里保证删除不依赖动画，实际刷盘仍按 03 的宿主协议，不将内存修改解释为立即写磁盘。

### 运行接法

1. 业务 Operation 通过已有移除方法删除原记录、释放占位和活跃索引，再转入退役管理。可沿 HomeHub 使用 EntityRetirementTicket，凭据仅持运行对象与身份，不存档。
2. Entity 的退役入口立即停止活动：注销时间／事件 Consumer，禁用参与查询与输入；此时不清空 View 还要读取的实体数据。需要 Start 注册的 Function／Effect 对应提供停止注册的内部方法，可与最终 Release 共用幂等注销代码，不增加独立 State 层。
3. Graphic 消费已完成的移除 Operation，找到原 View 播放退出。完成、取消、失败、零时长和没有 View 都进入统一收尾；沿 HomeHub 的专用最终释放 Command／Operation 可以复用，仍走普通 FIFO。
4. 最终释放步骤先解绑 View，再释放退役 Entity；它只回收资源，不能再次 DeleteProfile、清当前格占位、修改余额或推进时间。凭据须匹配原宿主及确切退役对象，重复完成无副作用；不能通过旧坐标查到新元素后释放它。
5. **D58：整体关闭直接由二合总管理器 Release 调用各系统 Release。** 先停止输入与时间驱动、停队并使运行会话回调失效；Graphic 回收窗口、全部活跃／退场 View，Logic 注销 Consumer 并释放全部活跃／退役实体，最后释放共用服务。按依赖先解除 View 对 Entity 的绑定，不等待动画，不发送关窗／到期／最终释放 Command。Release 不删除持久记录、不清 WaitPay。

普通玩家关窗经 CommandEndBubbleInteraction 执行到期规则；整体 Release 引发的 OnHide／OnClose 只清 UI 和订阅，不能再转发该业务命令。可由总管理器的关闭态或解绑回调实现，不增加持久关闭标记。若在当前同步 Batch 内请求整体释放，只置关闭请求并停新输入，到当前调用结束的安全边界统一释放，避免 Apply 使用已释放对象；这不是新的业务 Command。

正常 Remove 与整体 Release 必须区分。若对象以后使用池，退役期间不允许复用该 Entity，必须等 View 解绑后才能归池。移除后的旧 Profile 及业务字段作为退场可读数据保持稳定，不再接受业务写入；新的运行对象若在旧动画期间创建，须使用独立运行绑定，不把旧 View 所读的那份已移除记录重新挂回活动根。

### 引用读取与旧值副本各自的用途

View 可以读取保留 Entity 的配置、被删除前的位置及记录；但“仍有引用”不能让它读取已经 Release 的 Function／Effect，也不能把仍会变化的来源 Tile 当成冻结的旧状态。单独移除某个 Effect、移动前后位置、格锁旧阶段等历史值，仍在 Operation 交接中保存实际需要的小型副本。EffectView 的快照与旧回调约定继续有效，不复制整份存档来替代 Entity 引用。

参考事实：三合 EntityManager.Remove 会立即调用 Entity.Release；EntityBase 仍保留 ProfileData 引用，ViewManager 通过 WaitBehaviourFinish 延迟释放 View。HomeHub 则显式保留退役 Entity，最终解绑后 Release。二合采用上面的分阶段协议，不能将三合的立即 Release 理解为可以提前清空所有供 View 读取的数据。代码导航见 [00](00_参考资料与证据.md#时间窗口与表现释放核对2026-10-02)。

按已确认的 HomeHub 方向落地以下最小链路；名称统一使用 D64 前缀：

```text
删除业务 Operation.Apply
  → 删除存档、占位、活跃索引，停活动，保留退役 Entity／凭据
  → Graphic 播放旧 View 退场
  → 完成／取消／无 View：提交 CommandFinalizeEntityRetirement(原凭据)
  → CommandConsumerFinalizeEntityRetirement 核对凭据并创建 Operation
  → OperationFinalizeEntityRetirement.Apply 不写业务存档
  → Graphic 先解绑并释放旧 View，再最终 Release 原退役 Entity
```

这与参考 HomeHub 的 FinalizeEntityRetirementOperation／EntityRetirementFinalizeOperationConsumer 保持同一顺序：Apply 不做业务变化，Graphic 在 View 释放后通知对应 Entity 管理器完成最终资源清理。这里允许最终释放逻辑对象的资源引用，不允许 Graphic 修改有效物品的业务记录。Operation 仍只能由 Command Consumer 创建；关闭实例时则直接走 D58 的 Release，不再提交收尾 Command。

退役凭据由移除时捕获的确切对象及会话定位，不能靠格子坐标或持久 ID 重新找当前对象。没有 View 时无需等待动画，直接走相同收尾输入；重复完成／取消只释放一次。当前 EffectView 和 EntityView 均解除对旧 Entity 的绑定后，才可最终清除数据引用或归池。View 回收异常也必须执行对应清理出口，沿参考的 try/finally 组织，错误仍按原诊断协议报告；整体 Release 兜底遍历尚未收尾的退役对象。

## 连续输入与取消

D43 沿用本运行实例 FIFO 的同步业务执行；动画不阻塞命令队列。手感策略在 Graphic 局部处理：

- 同一物品受到新结果影响时，停止过时动画，从当前视觉位置过渡或直接对齐最新结果；不会重复发业务请求。
- 退役物品不再可点击。已占位但尚未出现的新物品是否暂时禁点，由明确的局部输入门禁决定。
- 默认不因为一个物品飞行而锁整张棋盘。确需整盘遮挡的入场／关闭由 Host 统一控制。
- 动画完成、取消、资源失败和瞬时播放都能走一次收尾；旧回调检查 SessionGeneration、绑定实例与表现版本。
- 只隐藏面板和真正销毁实例是不同生命周期。广告／后台保留有效交互，返回后先检查时间再开放操作；具体调度见 05，已过期表现按当前结果取消或对齐。

不建议第一版照搬三合 BehaviourPlayer 的完整冲突配置或 Home 的 Flow 优先级。先有简单的“每物品当前表现句柄＋取消／对齐”，出现真实第二类演出需求后再扩展。

## 生命周期归属

| 对象／扩展点 | 创建／注册 | 持有 | 停止／释放 | 错误出口 |
| --- | --- | --- | --- | --- |
| Command 与 Operation Consumer | 按 02b 装配：命令侧 Init 建对象、Start 注册；表现侧由 Player 显式注册 | 对应 Runtime／Player 注册表 | BeginShutdown 后逆序注销 | 沿参考诊断；Apply 故障不自动停掉整个实例 |
| Input 订阅与手势 | 面板绑定完成后 | Graphic 输入模块 | 隐藏取消手势，关闭注销 | 拒绝旧手势并对齐状态 |
| 到期调度 | 全部 Tile／Element 恢复并建立占位后 | Host 时间适配 | 关闭取消全部回调 | 不创建第二套时间状态；出错记录并重建调度 |
| View 与资源句柄 | Graphic 根据稳定状态创建 | Graphic／资源适配 | 取消表现、解绑、回收 | 必需根资源失败阻止开放输入；个别图标缺失用可诊断占位 |
| Profile 接入与记录绑定 | 已注册根可用后，按 03 恢复 | Host 持根；Logic 持原记录 | 按宿主约定请求保存、释放运行绑定；整体 Release 不额外发送关窗 Command，保留根记录和 WaitPay | 初始化失败保留原记录；保存按宿主诊断，不重放业务 |

整体关闭按 D58 直接执行总管理器 Release，再依次调用各系统 Release；不额外提交关窗 Command 或最后一次时间检查。释放流程停止输入／计时、注销注册、取消表现并收尾退役、解绑和回收运行资源；不删除有效存档记录，不清 WaitPay。普通气泡窗口关闭仍走 05 的业务 Command 链。宿主保存沿 03 接入，具体模块释放顺序在第 10 项装配时落实。旧回调必须失效，不能要求系统终止进程时一定有机会保存。

## 旧配置如何进入新模型

旧表保留在 `参考项目/FA/实现/Configs/Json/`。下表仅列本次方案涉及的 8 张表，按阶段接入。只读适配器先把字段转成明确 DTO，再构建规则配置；不能让业务代码到处解释空字符串、数组下标和原始类型编号。

| 核心表 | 当前条数 | 首次需要的阶段 |
| --- | ---: | --- |
| MergeTwoConfigTemplate | 3 | M0 棋盘参数；只取当前验证所需项 |
| MergeTwoMainTemplate | 21 | M0 初始格，按 mapId 分组、全局行 ID 排序后转本地行号 |
| MergeTwoItemTemplate | 371 | M0 物品、nextId、能力与外观键 |
| MergeTwoItemGenerateTemplate | 85 | M1 手动生成；M2 按项目选择轮次／固定段等算法 |
| MergeTwoboxTemplate | 27 | M3 宝箱 |
| MergeTwoWarehouseTemplate | 90 | M3 仓库扩容 |
| MergeTwoShopTemplate | 12 | M4 商店 |
| MergeTwoEnergyShopTemplate | 1 | M4 体力购买 |

三张旧棋盘均为 7×9，mapId 为 28001、28002、32001；含任务区域和外围条件。M1 推荐明确制作一张小型验证配置，再用 7×9 检查布局和完整链，不直接宣称任意旧棋盘已支持离线启动。

导入时统一处理以下规则：

1. ID 转稳定的不透明键，嵌套数组里的数值 ID 与外层字符串一致；nextId 外键、链环、生成器／宝箱子表引用必须校验。
2. 按字段解释 `""`、0、空数组和 -1，保留“无下一等级”“不允许删除”“耗尽移除”的不同含义；缺售出价格不默认为可删除。
3. `num`／`cd` 长度与次数合法，固定段与随机池组合有明确定义，权重和概率单位统一；0 概率必不发生，最大概率必发生。
4. `column_N` 的物品、初始状态、遮罩、区域任务、区域类型分别解析；`maxCol` 取分组首行，不能把其它行的 0 当成空棋盘。
5. 业务必需引用错误阻止该配置进入可玩集合，输出表名／键／字段。可选外观缺失可以占位，但需要清单，不能用图标是否存在决定物品是否存在。
6. 旧包根下 `Configs/Related/` 的四张宿主表只作为查证来源。原 ItemTemplate 货币和二合 ItemTemplate 物品不是同一命名空间，不全量复制原游戏经济与条件系统。

现有表实际使用类型 1、2、3、4、6；被动生成和工具需要专门样例才能验证。不能因为函数在旧包里就认为有可用配置与测试覆盖。
