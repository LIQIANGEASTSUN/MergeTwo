# 表现、配置与资源接入

建议首个验证版本用 UGUI 棋盘，复用旧包的美术与布局信息，重新连接宿主项目的输入和 UI 生命周期。UGUI 是根据现有资源提出的建议，尚未由用户确认。规则与存档不依赖该选择，以后换视觉载体不应重写合成与生成器。

EntityView、表现 Function、三段对象寿命及异步结束协议的原理见 [02a 第 3–4、8 节](02a_逻辑表现分离架构详解.md)。本页仅展开二合表现、输入、配置和资源的接入选择。

## Tile 与 Element 的表现（D10／D11 已确认）

| 逻辑对象 | 对应表现对象 | 职责 |
| --- | --- | --- |
| EntityTile | EntityViewTile | 地面、沙土等格子外观与格子表现 |
| EntityElement | EntityViewElement | 元素显示、拖拽表现和物品动画 |

编辑器为每个 Tile 指定配置 ID。D16 已提供生成类 [Config/Two/Scripts/Tile.cs](/Users/betta/Company/Projects/meatloaf_client/client/Assets/Game/MergeTwo/Config/Two/Scripts/Tile.cs)，2026-09-30 已静态读取，实际类型为 **MergeTwo.Two.Config.Tile**：

| 实际成员 | 类型 | 用途 |
| --- | --- | --- |
| ID | int，私有 setter | 配置行的主键，TileConfigKeys.GetKey 返回此值 |
| iconPath | string，私有 setter | 格子图标资源路径 |

当前配置行只有 ID 与 iconPath；前文讨论的一条记录包含多项表现设置是扩展方向，Prefab 等未生成字段不作为现有接口使用。

对接关系为：**BettaSDK.Profile.Tile.CfgId → MergeTwo.Two.Config.Tile.ID → iconPath → EntityViewTile 的图标表现**。坐标取存档 Pos，资源选择取配置；具体取表 API 和资源加载服务在实施时接入，不虚构尚未核对的方法。

所有格子功能相同，配置 ID 目前只区分外观，不据此装配不同逻辑能力。外观差异与解锁程度分开描述，同一阶段可使用不同沙土等资源，不能从外观 ID 推断解锁进度。坐标与配置 ID 进入 Tile 自己的存档，恢复以存档为准。配置 Tile、存档 Tile 和逻辑 EntityTile 的职责分别是只读配置、玩家记录与运行对象，代码引用时用命名空间或别名区分。

两种 View 分别绑定各自 Entity；叠放资源的显示层级可组合，Transform 父子关系不决定数据归属。蛛网等覆盖物归格子还是元素，随锁的后续设计确定。公共 View 基类、表现 Function 的拆分与资源池协议尚未定案。

先建立全部格子和元素的逻辑关联，再启用依赖完整棋盘的行为；View 显示已有结果，表现加载或动画回调不补占位。流程见 [03](03_状态模型与Profile.md#保存与恢复)。

D17 已确认：一级锁没有 EntityElement，也不为它创建 EntityViewElement；进入二级锁时创建逻辑元素，再绑定对应 View 显示。创建依据逻辑阶段变化，动画仅负责揭示过程。

## Function／Effect 的表现接入

D23 已将对应关系与实现约定收敛到 [10 第 5–7 节](10_Function与Effect建模讨论.md#5-effectview-的创建与同步)：EntityViewElement 通过 FunctionViewEffects 管理可选 EffectView；独立资源各自管理，共享视觉贡献由 EntityViewElement 汇总写入。同步使用当前只读快照，Bind／Refresh／Unbind 不改变业务数据；旧回调检查宿主、绑定、效果运行键与资源请求版本。D20／D22 要求界面使用方法＋bool 查询，不由动画回调直接设置逻辑权限。

## 表现消费什么

Logic 先完成一次业务变化，Graphic 再消费包含前后状态的结果。动画可以延后显示某些结果，但不得延后真正扣费、创建物品、占格或解锁。

| 业务结果 | 表现工作 | 取消后的稳定画面 |
| --- | --- | --- |
| Move／Swap | 按结果目标格移动 View | 对齐当前逻辑位置 |
| Merge | 两个旧 View 汇聚、退场，新 View 出现 | 只保留新实例及已确定附加物 |
| Generate | 生成器点击、飞出产物、刷新余额与次数 | 已生成物在各自权威格，费用只扣一次 |
| UnlockTiles | 深锁转浅锁、目标浅锁解除 | 按当前锁状态重建格子 |
| BubbleExpire／Unlock | 气泡消失、替换或解锁 | 显示已完成的物品状态 |
| Remove／Restore | 移除或恢复外观，更新撤销入口 | 按逻辑撤销凭据显示按钮，不以动画判断可撤销 |

合成先完成再出现气泡／衍生是**表现顺序**。这些附加物可以已在逻辑中占格、暂时隐藏 View，主动画到相应节点后显示。若期间发生新操作，表现必须处理已提交结果之间的冲突，不能让隐藏物被误当成空格。

Operation 结果需要包含旧外观和旧位置，不能在异步回调里重新读取一个已释放的 Entity 来补全动画数据。对于快速连续命令，结果有执行序号与实例身份；不只按“目标格”识别对象。

## Entity、View、GameObject 的寿命

参考 H 的三段模型及 [02a 的退役流程](02a_逻辑表现分离架构详解.md#8-异步表现退役与整体关闭)：二合业务物品退出活跃集合时，旧外观仍可能在退场。退役 Entity／记录和活跃物品分开；显示层释放后，专用生命周期路径才能最终清理退役数据。

新结果的占位不等旧 View 销毁。查询库存、生成器保护时不统计退役集合。Graphic 可以通知专用退役收尾，不能通过这条通道继续发奖励或完成合成。

首版若采用不可变结果副本，使 Entity 无需等动画保留，也可以简化退役结构；但必须先证明全部表现信息已独立捕获，不能半套使用 H 的票据、半套依赖旧 Entity。候选采用方式在实现 M1 生命周期时确定。

## 连续输入与取消

建议保留全局 FIFO 的同步业务执行；动画不阻塞命令队列。手感策略在 Graphic 局部处理：

- 同一物品受到新结果影响时，停止过时动画，从当前视觉位置过渡或直接对齐最新结果；不会重复发业务请求。
- 退役物品不再可点击。已占位但尚未出现的新物品是否暂时禁点，由明确的局部输入门禁决定。
- 默认不因为一个物品飞行而锁整张棋盘。确需整盘遮挡的入场／关闭由 Host 统一控制。
- 动画完成、取消、资源失败和瞬时播放都能走一次收尾；旧回调检查 SessionGeneration、绑定实例与表现版本。
- 只隐藏面板和真正销毁实例是不同生命周期。隐藏期间是否推进主动调度、恢复时如何跳过过期表现，见 05 和待决 Q06。

不建议第一版照搬三合 BehaviourPlayer 的完整冲突配置或 Home 的 Flow 优先级。先有简单的“每物品当前表现句柄＋取消／对齐”，出现真实第二类演出需求后再扩展。

## 生命周期归属

| 对象／扩展点 | 创建／注册 | 持有 | 停止／释放 | 错误出口 |
| --- | --- | --- | --- | --- |
| Command 与 Operation Consumer | 子模块 Init 建对象，Start 注册 | 本次 Runtime | BeginShutdown 后逆序注销 | 运行时结构化诊断；Apply 故障关闭实例 |
| Input 订阅与手势 | 面板绑定完成后 | Graphic 输入模块 | 隐藏取消手势，关闭注销 | 拒绝旧手势并对齐状态 |
| 到期调度 | 全部 Tile／Element 恢复并建立占位后 | Host 时间适配 | 关闭取消全部回调 | 不创建第二套时间状态；出错记录并重建调度 |
| View 与资源句柄 | Graphic 根据稳定状态创建 | Graphic／资源适配 | 取消表现、解绑、回收 | 必需根资源失败阻止开放输入；个别图标缺失用可诊断占位 |
| ProfileAdapter | Profile 可用后装配 | Host | 关闭前发布最终必要结果，随后脱离实例 | 发布失败关闭写入口；不冒充保存成功 |

关闭顺序建议：在可提交阶段处理取消选择等业务离开语义 → 发布最后完整结果 → BeginShutdown → 停止输入／计时 → 取消表现并收尾退役 → 逆序释放模块和资源。强制销毁仍需保证旧回调无效，但不能要求进程终止时一定有机会执行保存。

## 旧配置如何进入新模型

旧表保留在 `参考项目/FA/实现/Configs/Json/`。下表仅列本次方案涉及的 8 张表，按阶段接入。只读适配器先把字段转成明确 DTO，再构建规则配置；不能让业务代码到处解释空字符串、数组下标和原始类型编号。

| 核心表 | 当前条数 | 首次需要的阶段 |
| --- | ---: | --- |
| MergeTwoConfigTemplate | 3 | M0 棋盘参数；只取当前验证所需项 |
| MergeTwoMainTemplate | 21 | M0 初始格，按 mapId 分组、全局行 ID 排序后转本地行号 |
| MergeTwoItemTemplate | 371 | M0 物品、nextId、能力与外观键 |
| MergeTwoItemGenerateTemplate | 85 | M1 手动生成；M2 按项目选择轮次／固定段等算法 |
| MergeTwoboxTemplate | 27 | M3 宝箱 |
| MergeTwoWarehouseTemplate | 90 | M3 仓库扩容 |
| MergeTwoShopTemplate | 12 | M4 商店 |
| MergeTwoEnergyShopTemplate | 1 | M4 体力购买 |

三张旧棋盘均为 7×9，mapId 为 28001、28002、32001；含任务区域和外围条件。M1 推荐明确制作一张小型验证配置，再用 7×9 检查布局和完整链，不直接宣称任意旧棋盘已支持离线启动。

导入时统一处理以下规则：

1. ID 转稳定的不透明键，嵌套数组里的数值 ID 与外层字符串一致；nextId 外键、链环、生成器／宝箱子表引用必须校验。
2. 按字段解释 `""`、0、空数组和 -1，保留“无下一等级”“不允许删除”“耗尽移除”的不同含义；缺售出价格不默认为可删除。
3. `num`／`cd` 长度与次数合法，固定段与随机池组合有明确定义，权重和概率单位统一；0 概率必不发生，最大概率必发生。
4. `column_N` 的物品、初始状态、遮罩、区域任务、区域类型分别解析；`maxCol` 取分组首行，不能把其它行的 0 当成空棋盘。
5. 业务必需引用错误阻止该配置进入可玩集合，输出表名／键／字段。可选外观缺失可以占位，但需要清单，不能用图标是否存在决定物品是否存在。
6. 旧包根下 `Configs/Related/` 的四张宿主表只作为查证来源。原 ItemTemplate 货币和二合 ItemTemplate 物品不是同一命名空间，不全量复制原游戏经济与条件系统。

现有表实际使用类型 1、2、3、4、6；被动生成和工具需要专门样例才能验证。不能因为函数在旧包里就认为有可用配置与测试覆盖。
