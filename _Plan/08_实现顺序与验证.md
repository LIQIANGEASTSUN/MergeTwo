# 实现顺序与验证

本页是后续实现的候选路线，本轮只产出文档。M1 验证最小架构，M2 才逐步覆盖完整核心需求；M3／M4 依赖用户后续讨论结果，不自动开始。

## 成功标准和范围

M1 的成功标准：一个独立入口打开棋盘；首次点击选中、再次点击生成；物品可以移动、换位、两两合成；满盘／费用不足正常拒绝；关闭重开从当前项目 Profile 恢复。无 Graphic、零时长或中断动画时，成功业务产生相同稳定状态。关闭后旧回调不能改新棋盘。

M2 的成功标准：按已经确认的规则覆盖深浅锁、完整生成器、时间、气泡／衍生、使用与耗尽变更、售出／删除撤销；每项都有状态和存档边界用例。被动生成单列验收，不因基础生成可用就视为完成。

本轮不新增运行代码，不修改旧 Lua、公共 Profile、原配置或历史资源；通用 Undo／Redo 与回放不进入首期；活动和正式商业经济后置。

## 真实变化轴

| 变化轴 | 当前候选选择 | 后续变化及影响 |
| --- | --- | --- |
| 棋盘与物品规则 | 一张验证棋盘、单颗手动生成器起步 | 多轮／固定段／锁／气泡，需要稳定物品状态与完整结果表达 |
| 表现载体 | UGUI、新绑定、可取消动画 | 换场景／特效时保持 Command 和存档模型不变 |
| 产品与经济 | 独立入口、二合测试余额、当前 Profile | 活动期次与宿主钱包需要明确实例键和结算边界 |

后两列是边界预留的原因，不代表现在要写多棋盘管理框架、通用经济平台或第二套 UI。

## 实现顺序建议

以下 `Assets/Game/MergeTwo/` 是待确认代码位置，尚不存在本轮实现；Profile 文件名也为候选。每步只改相关局部，依赖完成并验证后才进入下一步。

### Step 1：冻结最小样例和基础契约（M0）

- **位置／动作**：本目录 01–05、09；选定样例棋盘、物品链、手动生成器、时间单位、费用、配置版本，决定核心复用／提交点、状态快照方式。
- **状态与权限**：配置规则由导入器构建；所有业务状态写入归 Logic 的 Operation；本步只定规格。
- **依赖／复杂度**：无；中等。Q01／Q02／Q08／Q10／Q11 中影响 M1 的部分先解决；Q11 决定锁等数据采用效果组合还是原有候选表达。固定段等可以使用明确不涉及该机制的 M1 样例。
- **风险／兼容**：不能用“仅作样例”掩盖模型冲突；保留旧数据，不修改原表以迎合新模型。
- **验证／回退**：一份明确初始状态和至少一条生成→合成→恢复的期望状态记录；有冲突先改讨论稿，没有运行代码回退成本。

### Step 2：建立配置与状态（M0→M1）

- **位置／动作**：候选 `Core/Config`、`Core/Logic/State`、`Runtime/Config`、`Tests`；实现稳定身份、占位、合法状态组合、最小只读配置适配与引用校验。
- **状态与权限**：Config 运行期只读；BoardState 为唯一活动权威；数量／空格索引为可重建缓存。
- **依赖／复杂度**：Step 1；中等。
- **风险／兼容**：混合 ID、空值、旧锁编号、全局行号；新配置有版本，不重导旧 Excel／Lua。
- **验证／回退**：加载合法样例并列出可交互物品；缺 nextId、非法尺寸等返回精确字段错误。可单独回退适配层，不影响现有三合。

### Step 3：建立最小运行骨架和提交出口（M1）

- **位置／动作**：候选 `Core/Command`、`Core/Operation`、`Runtime/Host`；按 A／H 装配 Init→Start、FIFO、Consumer、Batch、Graphic Player，加入明确的逻辑成功观察点与故障通道。
- **状态与权限**：Runtime 管队列，Operation 写业务；宿主只控制生命周期；Graphic 无业务写入口。
- **依赖／复杂度**：Step 2；较复杂。
- **风险／兼容**：最容易误改 bool、重入和失败语义；复制适配在本项目隔离完成，不修改 A／H 原实现。
- **验证／回退**：对关键契约做小型可执行测试，特别是同类型多消费者、重入、Apply／Graphic 异常。接入扩展若不成立，停在骨架层修订，不向业务复制错误模式。

### Step 4：实现选择、移动、换位和合成（M1）

- **位置／动作**：候选 `Core/Logic/Command`、`Operation`、`Rules`；实现一个 Drop 求解入口和完整结果，支持同 ID＋nextId 的普通合成。
- **状态与权限**：选择为 Logic 运行状态；占位、物品实例和 ID 分配为持久状态；只在 Apply 提交。
- **依赖／复杂度**：Step 3；中等。
- **风险／兼容**：重复手势、源物品已变化、链尾、换位双向不一致。
- **验证／回退**：无 Graphic 情况验证前后棋盘与不变量；失败无费用／随机／占位副作用。按命令回退，不接旧 Lua 逻辑兜底。

### Step 5：接入 Profile 往返（M1）

- **位置／动作**：候选 `Runtime/Profile` 和宿主 Profile 定义／生成注册位置；定位真实生成源与热更注册链后再新增二合类型，不直接手改生成的 ProfileMerge。
- **状态与权限**：ProfileAdapter 独占快照发布；发布后嵌套数据不可变，Logic 继续持有独立活动对象。
- **依赖／复杂度**：Step 4；较复杂。
- **风险／兼容**：后台保存观察半写状态、对象引用泄漏、漏标脏、缺配置；旧账号没有新存档可初始化，已有二合版本必须有显式加载规则。
- **验证／回退**：保存→销毁实例→加载比对稳定数据；表现失败仍保留已提交状态；Apply／发布故障停止下一条写请求。用独立存档键隔离，回退入口不会修改三合旧存档。

### Step 6：单颗生成、基础冷却与最小界面（M1）

- **位置／动作**：候选 `Core/Logic/Rules/Generator`、`Runtime/Time`、`Runtime/Graphic`、`Res`；加测试余额、单颗产出、轮次基础状态、时间归一化与最小 UGUI。
- **状态与权限**：逻辑扣费／次数／落点／截止时间同次提交；Graphic 只显示、命中测试与跟手；Host 采样时间。
- **依赖／复杂度**：Step 5；较复杂。
- **风险／兼容**：满盘扣费、新建跳轮、动画回调晚到、旧 Prefab 缺组件；只接已校验样例与必要资源。
- **验证／回退**：完成本页 M1 成功标准，关闭时机包含拖拽和动画中途。图形有问题可回到无 Graphic 的规则验证，不更改规则来掩盖表现问题。

### Step 7：完成完整核心规则（M2）

- **位置／动作**：按 04–06 逐项扩展：锁与空间→固定段／多轮／多颗→气泡／衍生→使用／耗尽→售出删除撤销→被动生成。
- **状态与权限**：各机制专用状态归对应 Logic 模块；共同占位不变量仍由完整 Operation 维护。新增 Profile 字段须有默认值／版本说明。
- **依赖／复杂度**：M1 验收；较复杂，拆成独立功能批次。各批次先关闭其待决问题，不能一次接受全部暂定建议。
- **风险／兼容**：空间竞争、状态继承、倒计时／离线、撤销经济；Q03–Q07 等必须在对应批次开始前裁定。
- **验证／回退**：每项完成下表相关用例再加入下一项；保留已验收样例。通过单独配置集和入口回退功能，不回退已发布的存档版本语义。

### Step 8：库存、道具和外围（M3→M4）

- **位置／动作**：按 07 扩展容器、宝箱／图鉴，最后宿主活动与商业接入。
- **状态与权限**：库存、道具独占各自领域数据写入；正式宿主余额归宿主，二合不建立第二权威。
- **依赖／复杂度**：M2 验收和新的范围讨论；较复杂，需另开模块细化文档。
- **风险／兼容**：跨 Profile 奖励、期次结束、购买重入；先明确实际协议和产品行为，再决定所需技术方案。
- **验证／回退**：阶段成果分别为仓库往返、宝箱领取与图鉴记录、活动完整生命周期；外围入口可撤回，不能破坏已完成核心棋盘的存档。

## 有意义的验证清单

这里记录验证目标，不声称已经编写或运行测试。实现时按阶段选择用例，不为每个 getter／委托写镜像测试。

| 类别 | 代表用例 | 核心断言 |
| --- | --- | --- |
| 执行契约 | 收集时重入、同类型多个消费者、Consumer 先登记后失败 | 顺序与 A 一致，已登记内容不会被误清空 |
| 故障边界 | 第二个 Apply 异常、Graphic 返回 false／抛异常 | Apply 不自动回滚；故障时下一条业务被关闭；Graphic 失败不重复扣费 |
| 提交出口 | 整批成功、空 Batch、只选择无持久变化、持久变化的取消选择 | 仅正确的完整稳定结果发布；不依赖 Submit 的 bool |
| 基础棋盘 | 移动、换位、合成链尾、失效源 ID、两次相同手势 | 占位／Location 一致，身份稳定，拒绝不伤状态 |
| 锁 | 浅锁作为目标、深锁禁止、目标四邻边缘、带锁生成物 | 格子锁与物品状态不会互相绕过；邻接为四向 |
| Effect，若采用 Q11 推荐 | 同时存在两个限制、移除其中一个、物品移动／换位、合成后效果去向 | 剩余限制仍有效；地格效果不随物品移动；没有枚举与效果两份可写权威 |
| 生成器 | 新建首轮、非末轮时间先到／次数先尽、末轮最后一次 | 正确的计时起点和轮次，无跳首轮／无限补轮 |
| 固定／随机 | 固定段跨保存、0／满概率、多个权重、不产出项 | 游标和抽样范围正确；拒绝不推进随机状态 |
| 落点 | 中心／边角螺旋、多颗仅余一格、气泡衍生被动争格 | 无重叠；费用和空间策略与已确认规则一致 |
| 气泡 | 选中后到期、改选、关闭恢复、到期和支付同帧 | 只发生一个最终结果，截止时间不被动画重置 |
| 售出撤销 | 正价／零价／禁止、保护唯一最高、原格先占后空、扣回不足 | 完整状态恢复一次，失效不可复活，不覆盖新物品 |
| 持久化 | 新账号、版本不兼容、时间状态往返、未知物品、发布后继续操作 | 无数据静默丢失，旧快照不随活动对象继续变化 |
| 生命周期 | 动画零时长／取消、资源延迟返回、关闭后再开、切账号 | 老实例回调无效，退役与订阅没有残留 |
| 外围阶段 | 仓库暂停／恢复、满盘领取、宝箱重复领取、图鉴保存重载 | 容器状态一致，奖励不重复发放，发现记录正确恢复 |

## 验证方法

Core 使用可控时间、固定随机序列与内存快照替身，直接比较可观察结果和关键不变量。Unity 层测试真实拖拽、Raycast、资源绑定、关闭重开和取消，不能用纯逻辑通过代替场景通过。

开始新增 C# 时按实际所属程序集选择受控编译：

```bash
dotnet build <本次改动所属项目>.csproj --no-restore --disable-build-servers /nr:false /m:1 /p:UseSharedCompilation=false -v:m
```

候选程序集尚未建立，不能现在写一个假定存在的 csproj 当通用门禁。资源验证则需 Unity 实际导入和界面检查；旧包静态审计只证明文件／数据引用状况。
