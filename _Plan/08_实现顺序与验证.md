# 实现顺序与验证

本页是后续实现的候选路线，此次只修订文档。M1 验证最小架构，M2 才逐步覆盖完整核心需求；M3／M4 依赖用户后续讨论结果，不自动开始。

## 成功标准和范围

M1 的成功标准：一个独立入口打开棋盘；首次点击选中、再次点击生成；物品可以移动、换位、两两合成；满盘／费用不足正常拒绝；关闭重开从宿主项目 Profile 恢复。无 Graphic、零时长或中断动画时，成功业务产生相同稳定状态。关闭后旧回调不能改新棋盘。

M2 的成功标准：按已经确认的规则覆盖深浅锁、完整生成器、时间、气泡／衍生、使用与耗尽变更、售出／删除撤销；每项都有状态和存档边界用例。被动生成单列验收，不因基础生成可用就视为完成。

本轮不新增运行代码，不修改旧 Lua、公共 Profile、原配置或历史资源；通用 Undo／Redo 与回放不进入首期；活动和正式商业经济后置。

## 真实变化轴

| 变化轴 | 当前候选选择 | 后续变化及影响 |
| --- | --- | --- |
| 棋盘与物品规则 | 一张验证棋盘、单颗手动生成器起步 | 多轮／固定段／锁／气泡，需要稳定物品状态与完整结果表达 |
| 表现载体 | UGUI、新绑定、可取消动画 | 换场景／特效时保持 Command 和存档模型不变 |
| 产品与经济 | 独立入口、二合测试余额、宿主 Profile | 活动期次与宿主钱包需要明确实例键和结算边界 |

后两列是边界预留的原因，不代表现在要写多棋盘管理框架、通用经济平台或第二套 UI。

## 唯一实施路线

阶段用于控制范围，技术步骤用于安排依赖；其他章节通过本页引用，不再各自维护一套 Step 1–N。正式代码候选位于**外部宿主 S** 的 `Assets/Game/MergeTwo/`，并非本仓库已有目录。实际编码前读取宿主的工程规则，保持旧参考包可追溯。

| 阶段 | 可验收成果 | 范围与进入条件 |
| --- | --- | --- |
| M0 准备 | 明确配置与状态样例 | 确定棋盘、链、生成器、时间单位、余额、提交及 Profile 接入；锁／固定段等在对应样例启用前定规格 |
| M1 最小闭环 | 生成→移动／换位→合成→关闭重开 | 一张棋盘、单颗手动生成器、选中、费用与满盘拒绝、基础冷却、测试余额、真实 Profile、最小界面 |
| M2 核心规则 | 需求边界可验证 | 锁、完整轮次／固定段／多颗、气泡／衍生、使用／变更、售出删除撤销、离线时间；被动生成单独验收 |
| M3 库存道具 | 存取与领取可靠 | 仓库、待领取、图鉴、宝箱；类型、计时、身份先定，再接 UI |
| M4 产品接入 | 可以作为活动交付 | 活动生命周期、正式经济、商店、倍率、广告／付费、BP、任务、引导、埋点，分别讨论范围 |

M1 不代表核心需求全部完成；M3／M4 不因存在旧文件就自动进入实施。尚未确认的 Q 按下表实际依赖逐项解决，无需一次回答全部。

| 顺序 | 工作与位置（相对候选模块，宿主接入除外） | 完成条件与主要风险 |
| --- | --- | --- |
| 1 范围与样例 | 在 01、03、09 固定初始状态、生成器样例和一条预期链路 | 解决 Q01／Q02／Q08／Q10 中 M1 必需部分。Q11 可先做纯数据比较样例；未选择前，不并建枚举和 Effect 两套运行体系 |
| 2 配置与状态 | `Core/Config`、`Core/Logic/State`、`Runtime/Config` | 稳定身份、占位和引用校验；错误定位到表／键／字段。最小样例不含未实现区域门槛，不重导原 Excel／Lua |
| 3 运行与提交 | `Core/Command`、`Core/Operation`、`Runtime/Host` | Init→Start、FIFO、一次登记完整业务操作、成功观察点、结构化故障出口。验证收集不完整和 Apply 故障两种不同风险 |
| 4 基础交互 | `Core/Logic/Command`、`Operation`、`Rules` | 单一 Drop 求解入口，选择／移动／换位／合成可无 Graphic 完成，失败不写状态／随机／ID |
| 5 Profile 往返 | `Runtime/Profile` 与宿主实际生成／注册位置 | 先定位生成源与热更注册；完整快照独立于活动对象，关闭重开及磁盘重载通过。不手改生成的 ProfileMerge |
| 6 生成与最小界面 | `Core/Logic/Rules/Generator`、`Runtime/Time`、`Runtime/Graphic`、`Res` | 单颗产出、基础轮次、时间先后、测试余额和最小界面满足 M1；表现取消不改已提交结果 |
| 7 逐项补核心 | 04–06 的对应模块 | 锁与空间→固定段／多轮／多颗→气泡／衍生→使用／耗尽→售出删除撤销→被动。每项先关闭相关 Q，再验收，不一次启用所有候选规则 |
| 8 库存及外围 | 07 的对应模块与宿主适配 | 仓库／领取→宝箱／图鉴→活动／正式经济；跨 Profile 奖励与购买恢复单独设计，保留核心独立入口 |

**回退原则**：通过独立入口、配置集和存档键隔离新功能；骨架契约不成立时先停在骨架层修订。不能用旧 Lua 兜底掩盖新模型错误，也不能回退代码后误读新版本存档。

## 有意义的验证清单

这里记录验证目标，不声称已经编写或运行测试。实现时按阶段选择用例，不为每个 getter／委托写镜像测试。

| 类别 | 代表用例 | 核心断言 |
| --- | --- | --- |
| 执行契约 | 参考核心中 Consumer 先登记后失败；二合求解中途失败；重复注册业务归属 | 参考语义不变；二合失败求解不登记半套操作，不发布残缺结果；每命令仅一个可写业务 Consumer |
| 基础时序，见 02a | 前后创建 Operation 依赖、Consume 中重入提交、同实体一批内多次变化 | 全部收集后 Apply，全部 Apply 后表现；重入先入队；中间演出使用显式结果，不误读最终 Entity 状态 |
| 故障边界 | Apply 中途异常、快照构建／发布异常、Graphic 返回 false／抛异常 | 状态／发布故障在下一条业务前关闭；Graphic 失败不重试扣费；不声称自动回滚 |
| 提交出口 | 整批成功、空 Batch、只选择无持久变化、持久变化的取消选择 | 仅正确的完整稳定结果发布；不依赖 Submit 的 bool |
| 基础棋盘 | 移动、换位、合成链尾、失效源 ID、两次相同手势 | 占位／Location 一致，身份稳定，拒绝不伤状态 |
| 锁 | 浅锁作为目标、深锁禁止、目标四邻边缘、带锁生成物 | 格子锁与物品状态不会互相绕过；邻接为四向 |
| Effect，若采用 Q11 推荐 | 同时存在两个限制、移除其中一个、物品移动／换位、合成后效果去向 | 剩余限制仍有效；地格效果不随物品移动；没有枚举与效果两份可写权威 |
| 生成器 | 新建首轮、非末轮时间先到／次数先尽、末轮最后一次 | 正确的计时起点和轮次，无跳首轮／无限补轮 |
| 固定／随机 | 固定段跨保存、0／满概率、多个权重、不产出项 | 游标和抽样范围正确；拒绝不推进随机状态 |
| 落点 | 中心／边角螺旋、多颗仅余一格、气泡衍生被动争格 | 无重叠；费用和空间策略与已确认规则一致 |
| 气泡 | 选中后到期、改选、关闭恢复、到期和支付同帧 | 只发生一个最终结果，截止时间不被动画重置 |
| 售出撤销 | 正价／零价／禁止、保护唯一最高、原格先占后空、扣回不足、删除后恢复遇到旧回调 | 完整状态恢复一次，失效不可复活，不覆盖新物品；恢复绑定版本隔离旧回调 |
| 持久化 | 新账号、版本不兼容、时间状态往返、未知物品、发布后继续操作 | 无数据静默丢失，旧快照不随活动对象继续变化 |
| 落盘 | 关闭持久化、清除内存后重载、磁盘保存失败 | 区分内存发布与保存成功；失败可诊断，不重放奖励／扣费 |
| 时间顺序 | 冷却到期同帧点击、重入命令、选中气泡过期 | 先用同一 now 归一化再执行动作；不会把时间推进排到动作后，不重复调度过去的截止时间 |
| 生命周期 | 动画零时长／取消、资源延迟返回、关闭后再开、切账号 | 老实例回调无效，退役与订阅没有残留 |
| 对象绑定，见 02a | View 已初始化但尚无 GameObject、反复绑定／回收、退役凭据重复／跨会话到达 | 组件在 GraphicBound 后绑定；回池不删除业务；退役立即退出活跃查询，晚到凭据不释放新对象 |
| Function，按采用范围 | 多功能 Failed／Success／SuccessAndAbort、数值顺序、必需功能缺注册 | 停止仅作用于局部功能链，不 Abort 整批；必需能力缺失可诊断；两层不直接越权调用 |
| 外围阶段 | 仓库暂停／恢复、满盘领取、宝箱重复领取、图鉴保存重载 | 容器状态一致，奖励不重复发放，发现记录正确恢复 |

## 验证方法

Core 使用可控时间、固定随机序列与内存快照替身，直接比较可观察结果和关键不变量。Unity 层测试真实拖拽、Raycast、资源绑定、关闭重开和取消，不能用纯逻辑通过代替场景通过。

开始新增 C# 时按实际所属程序集选择受控编译：

```bash
dotnet build <本次改动所属项目>.csproj --no-restore --disable-build-servers /nr:false /m:1 /p:UseSharedCompilation=false -v:m
```

本仓库没有 Unity 工程或已生成 csproj；上面的命令仅供未来在宿主对应项目中使用，不能在此执行。资源验证则需 Unity 实际导入和界面检查；旧包静态审计只证明文件／数据引用状况。
