# 棋盘交互与合成

一次放手只提交一次业务意图。Logic 决定移动、合成、特殊工具使用或换位的唯一结果；Graphic 负责跟手、预览和结果动画。失败回原位是显示对齐，不是把逻辑从拖拽中的屏幕坐标恢复回来。

**对象与数据按 D10–D14：** TileSystem 管理 EntityTile，ElementSystem 管理 EntityElement，表现对应 EntityViewTile／EntityViewElement；Tile.ElementId 仅为运行占位，元素自己的存档保存 Coord 与 ConfigId。基础 Command／Operation 执行协议已按 D43／02b 确认；五类业务操作与邻接同批已按 D45／D46 确认，具体输入和 Apply 顺序见 02b 第 5 节。

## 输入与查询

| 输入 | Graphic 工作 | Logic 请求 |
| --- | --- | --- |
| 首次点击物品 | 点击反馈；按成功结果展示交互 UI | 选择当前物品；Effect 接管点击时走其对应动作，气泡首次点击即请求解锁弹窗 |
| 再点已选物品 | 点击反馈 | 先确定 Effect 是否接管本次点击；未接管才按普通规则校验生成、使用、开箱，不将可选择视为可激活 |
| 开始拖动 | 建立本次手势、记录绑定、暂隐藏选择框 | 需要时提交选择命令；校验可拖拽 |
| 拖动过程 | 跟手、算目标格、显示预览 | 只读 EvaluateDrop，不改占位、不抽真实随机 |
| 松手 | 结束手势与预览 | CommandDropElement(ElementId, TargetTile) |
| UI／棋盘外松手 | 显示回到当前权威格 | 非法目标拒绝，无业务变化 |
| 空格／其它 UI 点击 | 对应局部反馈 | 按 R 不自动取消选择；但其实际业务操作仍可使对象失效 |

命令同时携带物品身份和预期源格；出队时重新核对。若系统操作已移动／移除该物品，拒绝旧手势，不能改用“原格现在的另一个物品”。异步回调再加 SessionGeneration／绑定版本校验。

UI 预览与提交共用同一份只读能力规则。预览只是提示，真实执行以出队时状态为准。屏幕坐标、RectTransform、RaycastResult 不进入 Logic 命令。

D37：输入层提供 Click 与 Drag，拖拽本身不会产生 Click。气泡只响应已有 Click，不新增按下检测、延时辨别或手势过滤层。Effect 的交互响应接线见 [10](10_Function与Effect建模讨论.md#effect-响应点击与拖放实现轮廓)，它补充权限检查，不取代权限检查；二级锁优先于气泡，锁定时只选择，不开气泡窗口。

## 放手判定顺序

使用一个可直接阅读的 DropRules 求解入口。**D41 已确认：普通元素仍可合法合成进二级锁目标并解锁；目标 Tile 完全解锁是普通移动／腾位的要求，不能作为所有 Drop 的全局前置条件。** 各业务分支分别检查动作权限，不让互不相关的订阅者竞争修改棋盘。

1. 校验源实例、源位置、目标坐标、棋盘实例、区域门槛和源操作能力。
2. 同一格：保持状态，结束手势。可直接作局部反馈；若需要成功的统一命令结果，登记明确无变化操作，不能改变空 Batch 的基础语义。
3. 同时识别源与目标 Effect 的拖放响应；任一方有气泡即选中“移动／有占位则腾位”分支，先检查目标 Tile 完全解锁，再完整校验双方与落点。双方气泡合并为一个分支；失败即拒绝，不回退成合成、工具使用或普通换位。
4. 没有专用响应时，对已接入的特殊工具按明确业务顺序尝试；工具失败是否允许换位按具体规则决定，不能吞掉明确错误。
5. 满足普通合成时，生成 Merge 结果；二级锁可作为目标，仍检查双方 Function、所有 Effect 及合法产物，成功后目标 Tile 完全解锁。任一方有气泡时已由第 3 步接管，不到此分支。
6. 未发生合成时，只有完全解锁的目标空格才可普通移入；两个均允许换位的普通物品才可换位。二级锁目标合成失败不能回退换位。
7. 其余拒绝，Graphic 对齐当前逻辑位置。

M1 尚未接入气泡／特殊工具时省略相应分支。以上为已确认规则的接线轮廓，执行载体按 02b 第 5 节实现；不把旧 FunctionType 数值当业务优先级搬过来，执行顺序应在规则与用例中可见。

## Tile 解锁与运行时锁 Effect

**D24／D25 已确认：Tile 保存唯一解锁进度，具有解锁 Function；Element 根据所处 Tile 挂载运行时锁 Effect。** D28 已确认下文二级锁操作表；D29 确定当前 Tile 不添加 Effect。数据与地编来源见 [03](03_状态模型与Profile.md#锁数据归属与表示d24d25-已确认)。以下类名与集中同步方式为实现约定；邻接采用 D46 的同批执行，完整协议见 02b。

| 对象 | 职责与边界 |
| --- | --- |
| EntityTile.FunctionTileUnlock | 管理当前阶段；校验某种解锁原因是否适用，求解阶段变化；执行阶段中修改唯一进度 |
| TileSystem | 查位置、邻格和占位；不存第二份全盘锁进度，不自行决定解锁算法 |
| ElementSystem 与占位入口 | 创建／恢复／移除元素并维护双方关系；在关系稳定后同步来自 Tile 的效果 |
| EntityElement.EffectTileLock | 真正加入 Owner 的 Effects；只影响该元素，绑定来源 Tile，读取其只读阶段；不持久化、不自行推进 Tile |
| EntityViewElement 的 EffectViewTileLock | 按用户倾向负责二级锁蜘蛛网，走既有 FunctionViewEffects 管理；具体层级见 06 |

**运行 Effect 与持久锁进度不是两套可分别演进的数据。** Effect 使用来源引用和规则，不复制可写 Phase／Locked 字段；它的存在由集中同步维护。EntityTile 如暴露 Phase，应转发 FunctionTileUnlock 的值。其它独立 Effect 可保存自己的数据，不能一并丢弃。

### 集中同步入口

采用一个内部方法 `SyncTileLockEffect(element)`，由完成占位／阶段变化的逻辑执行入口调用，不由 View、查询方法或逐帧轮询调用。可直接实现于已有 ElementSystem／关联模块，不新增全局 EffectSystem。内部可传入已解析的 `occupiedTile`，为空仅表示元素已通过合法流程退出格子；不能把“活跃元素查不到 Tile”的错误当成已离开。

```text
找到该元素上“来自 Tile 的锁 Effect”这一专用实例
若元素已合法退出格子：移除该专用效果并结束
否则校验当前 Tile 存在、坐标相符、Tile.ElementId 等于 element.InstanceId
若当前 Tile 一级锁却已有元素：报告结构错误，不先增删效果
若当前 Tile 完全解锁：移除该专用效果并结束
当前 Tile 为二级锁：
  已有同来源效果：保留实例与 RuntimeId
  无效果或来源已改变：按实例键移除旧效果，添加 EffectTileLock(currentTile)
```

每个已占格 Element 至多有一份当前 Tile 来源的锁 Effect；独立气泡、冻结或其它物品锁不在这个同步入口的删除范围内。可用内部专用引用定位效果，仍统一加入普通 Effects 集合供查询与表现读取。来源换格时释放旧引用并生成新的 Effect 运行身份；释放宿主时清理来源引用。

| 入口 | 必须完成的同步 |
| --- | --- |
| 首次揭示／新局创建 | 创建元素并关联 Tile 后，按其当前进度装配效果；全部完成后开放查询 |
| 读档恢复 | 先恢复 Tile 和 Element／占位，再重建锁 Effect，随后开放输入与自动行为 |
| Tile 解锁 | 修改唯一进度，同一业务执行中同步当前占位元素的效果；随后发布稳定结果与表现 |
| 元素移动、换位或合法系统替换 | 改坐标与占位，按新的 Tile 重新同步；不改变任何 Tile 进度 |
| 元素消耗／销毁 | 退出活动集合并释放自身效果，清占位；不把清空占位当成解锁 |
| 撤销恢复 | 恢复元素自身数据，再按当前目标 Tile 同步；不从旧撤销记录恢复格锁 |

Tile 进度变化与效果同步在同一逻辑调用内完成，期间不派发外部业务通知／表现，不等待动画。D49 下进度直接写 Tile 原记录并由 setter 标脏，没有延后的存档发布步骤；这也不代表后台保存已具备完整业务隔离，具体边界见 03。若内部失败，不把半同步结果当成功；核心异常语义见 02b，不假定 Batch 会回滚或停机。可在业务稳定边界验证“二级锁占位元素恰有对应效果、完全解锁元素没有该来源效果”。

准备解锁／合成时先捕获旧元素的锁效果显示快照，再改变 Tile 进度。旧蜘蛛网退出动画使用这个副本；不能稍后通过旧 Effect 的来源引用回读已经完全解锁的 Tile，否则会丢失解锁前的显示信息。新元素和重建 View 只使用当前稳定结果。

通用移除 Effect 的业务不能单独“驱散”此效果以解锁；真正解锁必须请求 FunctionTileUnlock 推进 Tile 后再同步。否则重建时会再次出现，且违反唯一进度来源。这里的底层 Remove 只供内部同步和生命周期清理使用。

### 方法输入与输出

| 方法轮廓 | 只读阶段需要哪些输入／输出 | 写入与发布 |
| --- | --- | --- |
| TryPrepareAdjacentMergeUnlock | 只读合成上下文、Owner 当前阶段、当前地图与坐标；返回 bool 及必要的下一阶段／默认元素创建描述 | 不改进度、不创建、不发正式合成事件 |
| TryPrepareTargetMergeUnlock | 已通过源／目标资格和完整合成校验的上下文、Owner 当前阶段；返回 bool 及阶段变化 | D28 已确认二级锁可作目标；进度变化与成功合成共同执行，准备阶段不修改进度 |
| ApplyPreparedUnlock | 预期旧阶段和已准备的下一阶段；先核对预期事实 | 写唯一 Phase；与元素创建／替换、占位同步由同一次业务组织完成 |
| SyncTileLockEffect | 元素及其当前合法占位；无业务奖励输出 | 内部维护实例集合；调用者完成全部变化后再发布当前效果快照 |

这些是具体业务输入，不建立 RuleCheck／BlockReason 或通用 object 参数袋。准备数据只用于紧接着的当前执行；经过异步等待或其它写入后必须重验，不能长期持有一份可过期的解锁许可。小型阶段记录与创建描述可用普通结构，不要求专门的事务／反应引擎。

### 解锁原因与完整变化

分别提供可读的规则方法，例如 `TryPrepareAdjacentMergeUnlock`、`TryPrepareTargetMergeUnlock`，而非无条件 `Phase--`。准备方法只读当前事实、返回 bool 与必要的局部变化数据；执行方法验证预期阶段后应用，不能由外部直接赋值 Phase。具体方法签名随最终执行协议落地。

- 邻接合成：一级锁首次揭示为二级锁；先校验地编内容可创建，再将进度、创建、占位及效果装配作为同一完整变化。
- 目标合成（D28）：普通 A 合成进二级锁 B，成功得到 C，同时目标 Tile 完全解锁；C 根据目标 Tile 最终阶段装配效果，不继承 B 的格锁。合成拒绝不推进 Tile。
- 普通移动／销毁／替换仅改变 Tile 的占位运行 ID。上述“目标合成解锁”是明确执行的解锁规则，不是任意替换都自动改变阶段。

之前“同一次邻接触发不跨两级”的含义：在位置 X 合成，只使邻格 Y 从一级变二级并创建 B；B 没有参与 X 的那次合成，不能因此也算成“B 已完成目标合成”。**这是两种触发条件，不是同一帧只能解锁一次的限制。** 随后确有另一件物品与 B 成功合成，可以立即完成下一阶段；重复派发同一来源不能重复创建 B。邻接分发、去重与写入协议见 [02b 的邻接同批实施](02b_Command与Operation执行方案.md#54-邻接解锁同批执行)。

## 锁与能力矩阵

这里的“操作权限”只是逐项说明**一个动作能否执行**，不增加权限管理系统。**D20／D22：下表均为方法＋bool 的查询语义，不是可写 CanClick／CanDrag 字段；D28 已确认二级锁这一列。** Effect.Blocks 的组合见 [10 第 3–4 节](10_Function与Effect建模讨论.md#3-权限查询普通方法与-bool)。元素限制由实际挂载的 EffectTileLock 参与；Tile 的占位／未揭示检查直接读取 Tile 事实，D29 当前不添加 TileEffect。

| 动作 | 一级锁 | 二级锁 | 完全解锁 |
| --- | --- | --- | --- |
| 点击选中 Element | 无元素可选 | **允许**；显示 UI 选择框，播放 Scale 果冻弹动（D26） | 按元素能力及其它 Effect |
| 拖拽 Element | 无元素 | **禁止**（D26） | 按元素能力及其它 Effect |
| 作为普通合成源 | 无元素 | **禁止**，逻辑入口也须检查 | 按完整合成条件 |
| 作为普通合成目标 | 无元素 | **条件允许**：源有资格、双方可合成、有合法结果，且其它 Effect 未阻止 | 按完整合成条件 |
| 点击激活生成／使用／开箱 | 无元素 | **禁止**，选择和果冻反馈不会激活能力 | 按能力及其它 Effect |
| 普通移动放入／换位 | 不能创建普通占位元素 | **禁止**；成功目标合成走独立合成分支 | 按占位及其它规则 |
| 玩家出售／删除 | 无元素 | **禁止** | 按价格、保护及其它规则 |
| 读档恢复原有占位 | 一级锁不应有元素记录 | **允许结构正确的恢复**，随后重建运行锁 Effect；恢复本身不解锁 | 恢复原有记录 |

对二级锁，选择动作不被本锁 Effect 阻止；其它独立 Effect 若阻止选择仍应生效。重复点击的果冻反馈不自动调用生成／使用 Function。UI 输入不能因“不可拖拽”就关闭整个元素的命中，否则会同时丢失已确认的点击反馈。

二级锁的 EffectTileLock 对 Select／MergeAsTarget 返回不阻止，对 Drag／MergeAsSource／Generate／Use／OpenChest／Swap／Sell／Delete 等上述禁止动作返回阻止；动作名按实际 API 对应。MergeAsTarget 不阻止不代表整个合成已获准，业务入口仍须核对双方条件。其它未来动作按具体需求补规则，不从“可选中”推导为可执行。

目标合成失败不得回退为换位移走二级锁元素；同类但没有合法合成结果，也不推进解锁。普通放置还须检查目的 Tile：锁格即使因合法系统移除变为空格，仍不能仅凭 ElementId 为空就允许移入。系统创建／恢复使用已定义的结构维护入口，不复用玩家拖放许可或偷偷清除 Tile 进度。

旧 R／L 的参考基线：浅锁可选中、不可拖、可被同 ID 普通元素合成；深锁不可操作；浅／深锁不允许激活、售出和删除。R 的锁格拒绝普通移动与浅锁允许目标合成是不同动作；L 的气泡支持拖动／换位，新方案按下节已确认的就近腾位执行。旧编号、四邻定义和限制不能自动成为新方案确认值。

## 气泡操作与就近腾位

### 操作边界（D31／D32／D38／D39）

以下是气泡这一 Effect 的作用；整体动作仍需满足 Function、Tile 及其它 Effect。气泡“不阻止”绝不覆盖格锁、冻结等其它拒绝。D38 补齐源带气泡和双气泡拖放，取消上一轮“气泡源撞普通元素拒绝”的建议。

| 动作 | 气泡规则 |
| --- | --- |
| Click／Select | 允许选择；所在 Tile 完全解锁时 Click 请求气泡窗口。二级锁优先处理，仅保留选择／果冻反馈 |
| Drag／移动到完全解锁空格 | 允许；保持元素身份、气泡 RuntimeId、期限及其它数据 |
| 普通源拖入气泡目标 | 目标 Tile 完全解锁才可腾位：源进入目标格，目标气泡找最近合法空格 |
| 气泡源拖入普通或气泡占位目标 | 目标 Tile 完全解锁才可腾位：源进入目标格，原占位元素找最近合法空格；不合成、不激活其它功能 |
| 气泡参与的拖放落在一级／二级锁 Tile | 拒绝，源回到权威原位，目标元素及 Tile 进度不变；空锁格也拒绝 |
| MergeAsSource／MergeAsTarget | 都禁止；相同配置也不能合成 |
| Generate／AutoGenerate | 都禁止；所有触发入口均查询限制，不能只关 UI 按钮 |
| Collect／Use／OpenChest／Sell／玩家 Delete 等其它功能 | 按用户“其它任何功能禁用”处理；解锁气泡自身走独立业务动作 |
| OpenBubbleDialog／UnlockBubble | Tile 必须完全解锁，且当前效果、交互与具体条件有效；不能靠直接调用请求绕过格锁 |
| BubbleExpire／系统清理 | 专门的生命周期入口，不属于玩家 Delete；禁止玩家删除不会阻止到期销毁 |

这里“源替换到目标 Tile”指**位置与占位变更**：不销毁／重建源，也不把被腾位元素替换成另一个实例。双方都是气泡时执行同一次移动／腾位，不生成两份重复计划。

D41 已明确保留 D28 的普通目标合成解锁：普通 A 与二级锁 B 满足全部合成条件时，可以产生 C 并解锁目标 Tile。**普通移动／换位／气泡腾位不能进入锁格，合法目标合成可以。** 若任一合成方有气泡，其 MergeAsSource／MergeAsTarget 检查仍拒绝，不能以普通合成例外绕过气泡。

### 二级锁优先于气泡

D39 已确认同一元素的二级锁 Effect 优先于气泡 Effect；只有 Tile 完全解锁后才可解除气泡。实现时：

- 二级锁 Click 响应为仅选择；不继续打开气泡窗口。选择框／果冻反馈保持。
- EffectTileLock 明确阻止 OpenBubbleDialog、UnlockBubble、Drag、Displace 及普通移入／换位；实际解除入口也校验当前 Tile，不能只隐藏按钮。
- 优先级不等于把低优先级 Effect 停用。气泡的禁合成、禁生成与自身期限仍有效；不自动冻结时间或删除气泡。
- Tile 真正完全解锁后，按既有 SyncTileLockEffect 移除来源锁；气泡本身、期限与 Function 数据保持，之后 Click 才能处理气泡。
- D42：项目若安排二级锁与气泡同时存在，须另有可先解除格锁的方式；若未设计这种方式，则由配置避免出现该组合。气泡禁合成、先格锁后气泡的规则都保持，不用 Priority 放行本来禁止的动作。

### 独立解锁方式与配置约束（D42）

这是项目扩展约定，气泡专题不再要求先选一种具体新玩法，也不预建空的解锁类／枚举或通用条件框架。

- 新的 Tile 解锁方式确定后，在 FunctionTileUnlock 增加对应的具体检查／准备方法，与目标合成、邻接揭示入口并列；由明确业务入口传入条件事实，校验当前阶段，准备阶段变化，再沿已有执行入口写入唯一进度。
- 独立解除格锁同样执行 `更新 Tile 进度 → SyncTileLockEffect → 发布稳定结果`。若原元素仍存在，保留其身份、Function 与气泡数据，只移除来源格锁；下次 Click 才能按仍存在的气泡处理，不自动连带解泡或刷新期限。
- 未实现独立解锁方式的项目，在地图／初始效果配置中避免“二级锁＋气泡”；动态附加效果的入口同样检查是否会制造该组合。不能只防地编，却允许运行时附加出同样的无解局面。
- 实现配置校验时，检查此组合是否匹配本项目已实现、对当前 Tile 适用且不依赖先解气泡的解锁规则。无需通用可达性推演系统；规则设计者负责新玩法条件确实可达，代码验证必要配置与入口存在。
- 校验依据是地编阶段、元素实际效果和项目接入的解锁规则；现有 Tile 外观配置 ID 的用途不变，不声称已经生成的 Tile／Profile 类包含这些扩展字段。具体配置载体随项目新规则接入，当前不修改生成类。
- 新局初始化／附加准备不满足约束时，明确报告或拒绝，不先建立半成品。恢复既有存档时，按同一组合约束核对；发现配置变更导致规则缺失，应保留原记录并交由存档错误／迁移协议处理，不静默删除气泡或自动解锁 Tile。

因此，不含该组合的项目可以直接实现当前普通目标合成规则；采用该组合的项目在接入具体新解锁玩法时补对应方法和配置，基础 Effect／存档／表现模型不需要改变。

### 腾位的完整求解

统一使用源 A、源格 S、目标格 T、T 的可空占位元素 X。A 或 X 带气泡时采用本节路径，避免只检查目标 Effect。

1. 核对 A 的身份／预期源格、目标坐标、A 可拖动，且 T 完全解锁；同格放手直接结束。检查 X 时使用它当前身份，不能沿用过期预览。
2. T 为空：准备 A：S→T 的普通移动结果，无须找第二个落点。
3. T 有 X：检查 X 的 CanBeDisplaced，以及它自身所有 Effect。气泡允许被腾位，格锁或其它不可移动限制仍能阻止；不使用“X 必须已选中”或“X 主动发起拖拽”的条件。
4. 在**局部占位草稿**中模拟 A 离开 S、X 离开 T、A 占据 T。S 纳入候选空格，T 已预留给 A。查询／预览不修改真实对象。
5. 以 X 原位置 T 为中心寻找最近可放置的空格 U。检查地图范围、Tile 完全解锁、X 的放置限制，以及草稿中的空位／预留；不能因真实 S 尚有 A 就漏掉已模拟腾出的 S。
6. 没有合法 U 或 X 不可移动时，整次拒绝，双方和 Tile 全部不变；不销毁 X、不覆盖、不塞入队列。这是维护单格单元素不变量的执行边界。若 U=S，最终两格互换位置；其它情况更新三格。
7. 完整准备 A：S→T、X：T→U 后，在执行入口重验，再统一更新元素原记录的坐标和 Tile.ElementId；先完成全部占位，再同步 Tile 来源效果，最后交付表现数据。记录修改已由生成机制标脏，不另做存档导出。

腾位只改变位置，保留双方 Function 数据与独立 Effect，气泡期限不刷新。不递归模拟“X 又拖放一次”，不触发合成／工具使用／生成；以后如果项目确有移动后的其它规则，须通过明确业务入口组织，不能在动画回调中隐式附加。

距离算法与同距顺序由项目空间规则明确，可复用生成器空位查询，不在本文固化某项目的扫描顺序。接口至少输入搜索中心、待放元素、局部占位视图与放置检查，输出 bool 和坐标；真实执行和预览使用同一求解方法。

### 最小方法与执行数据

D45 已确认移动／换位／气泡腾位使用一条 Operation 同时维护相关位置与占位；具体数据和执行步骤见 02b 第 5 节，不新增气泡棋盘管理器。

| 方法／数据 | 职责 |
| --- | --- |
| DropRules.TryPrepareDrop | 校验身份与目标，选择本次唯一动作；分别查询源和可空目标的 Effect |
| EffectBubble.TryGetDropAction | Owner 位于源或目标时提出 MoveWithDisplacement；不修改占位，不自行执行腾位 |
| CanBeDisplaced(X, context) | 检查 X 当前关联及所有 Effect 的 Displace 限制；返回 bool |
| TryPrepareMoveWithDisplacement | 只读求解空目标单移动或有目标的双移动；失败没有副作用 |
| TileSystem 的最近合法空位查询 | 根据传入局部占位视图找 U，不修改真实 Tile；具体距离／同距策略由项目提供 |
| 本次移动数据 | A 的身份与 S／T；可选 X 的身份与 T／U；检查使用的气泡身份；表现所需旧／新坐标副本 |
| ElementSystem＋TileSystem 执行入口 | 重验预期对象与占位，更新全部关联，同步来源效果后统一发布 |

准备数据不能跨异步等待复用；真正执行时重新查询。失败回位只让 Graphic 对齐当前权威位置，因为跟手从未修改真实坐标。完整准备结果不等于框架自动提供异常回滚，基础失败协议按 02b 沿用参考机制。

## 合成的完整变化

**D45／D46 已确认：** 主合成由 OperationMergeElements 维护共同关系，逐格首次揭示由 OperationRevealTile 负责；Consumer 完整准备后，依序登记同一个 Batch。详见 [02b 的操作契约与同批实现](02b_Command与Operation执行方案.md#5-二合-operation-的实施契约)。这组业务采用连续登记，不限制同一 Command 的其它 Consumer；不能先删源、在动画回调里再建目标。

```text
读取源和目标的配置／状态，校验同 ID、nextId 和特殊限制
→ 在局部求解数据中释放源／目标占位并确定新物品
→ 按已选规则计算目标格解锁与指定邻格的一级锁揭示
→ 按所选项目的附加物顺序分配气泡、衍生物落点（具体规则另定）
→ 准备创建参数和必要的局部随机结果（运行时身份只在实际创建时取得）
→ 一起登记主合成与邻格揭示操作

同一 Batch 的全部 Apply（期间不播放表现；一般消息须标明局部语义，不冒充整批完成）
→ 消耗源与目标、从活跃集合退役
→ 更新相关 Tile 进度、目标格放入新实例、首次揭示格创建元素
→ 完成所有受影响占位与运行锁 Effect 的同步
→ 放入已确定附加物并更新发现记录等已接入状态
→ 选中新结果，提交本次实际使用的随机状态
```

L 先 CheckClone／CheckDerivant 再 OnTriggerUnlockGrid；新方案建议先求解主合成与锁变化，再分配附加落点。按当前揭示样例，一级锁进入二级锁并创建地编元素，不会增加普通产物空位。邻格使用四向还是八向尚未确定；旧 L 的四邻行为仅是参考。未来特殊放置／解锁为空地的规则须另行明确。

主合成必须成功，附加物空位不足如何处理见 05：建议不挤走原物、不自动塞待领取队列；附加物是否丢弃与其抽样时机要明确。主产物位置始终是目标格。

Graphic 所需结果至少有：消耗实例和旧外观／旧格、新实例和目标格、锁变化列表、附加产物及来源、选中变化。不能等动画播放时再读已被释放对象，也不能只查最终状态猜旧图标。

## 移动与换位

移动应一起清空源 EntityTile.ElementId、填入目标 ElementId、更新 EntityElement.Coord；换位同样维护两个元素的位置与两格占位。按 D45 由 OperationMoveElements 调用 ElementSystem／TileSystem 的内部入口，先解除全部旧占位，再写坐标和新占位、同步派生效果，详细输入和顺序见 02b 第 5 节。元素 ID 不进入 Tile 存档；元素位置写入自己的存档。普通移动保留 Function 数据、气泡期限及其它独立 Effect；与所在 Tile 相关的效果按新位置同步。

如果拖拽过程中系统到期事件改变目标，提交时重新求解；若原预览不成立则回位或执行当前合法分支，具体手感可讨论。默认不在每帧拖拽时发送占位变更命令。

## 售出 删除与恢复

三个入口可复用同一 RemovalRules：

| 请求 | 校验 | 成功结果 |
| --- | --- | --- |
| SellItem | 普通可移除、价格>0、满足生成器保护 | 退役物品、释放格子、增加余额、建立一条撤销记录 |
| DeleteItem | 普通可移除、价格=0、满足同一生成器保护 | 同上但不改余额 |
| RestoreRemovedItem | 记录有效、原格仍空、可扣回出售收入 | 恢复完整实例、扣回收入、凭据失效；不能回放原删除再重建 |

售出与删除都校验当前选中实例，并使用同一移除保护规则。价格=-1 禁止移除；缺失价格不能无条件解释为零价。旧表空值较多，导入规则需要显式决定。

生成器保护用当前持有状态，而非仅图鉴历史。达到门槛前整条链禁移除；达到门槛后最高等级唯一一件禁移除，其余按价格。持有统计是否包含仓库，以及哪些生成器种类享有保护，需要 M2 前确认。

选中另一个物品／原格被占用时永久使本条凭据失效；之后原格重新空出来也不重新开启旧撤销。原格占用检查不能只在点击撤销按钮时做，否则会错误延长入口生命周期。

## 性能与可测性

参考配置为 7×9 共 63 格。TileSystem 可按坐标组织格子集合，ElementSystem 按运行 ID 管理元素；整盘规则检查 O(格数)，单次普通合成局部更新 O(1)，附加物找位最坏 O(格数)。先做清楚的代码和测量，再决定空格索引／池化，不复制三合大地图的空间分块系统。
