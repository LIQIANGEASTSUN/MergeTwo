# 棋盘交互与合成

一次放手只提交一次业务意图。Logic 决定移动、合成、特殊工具使用或换位的唯一结果；Graphic 负责跟手、预览和结果动画。失败回原位是显示对齐，不是把逻辑从拖拽中的屏幕坐标恢复回来。

**对象与数据按 D10–D14：** TileSystem 管理 EntityTile，ElementSystem 管理 EntityElement，表现对应 EntityViewTile／EntityViewElement；Tile.ElementId 仅为运行占位，元素自己的存档保存 Coord 与 ConfigId。具体 Command／Operation 类名与执行协议仍是候选。

## 输入与查询

| 输入 | Graphic 工作 | Logic 请求 |
| --- | --- | --- |
| 首次点击物品 | 点击反馈 | 选择当前物品，必要时处理旧选择的规则后果 |
| 再点已选物品 | 点击反馈 | 单独校验激活权限后才请求生成、使用、开箱；可选中不等于可激活 |
| 开始拖动 | 建立本次手势、记录绑定、暂隐藏选择框 | 需要时提交选择命令；校验可拖拽 |
| 拖动过程 | 跟手、算目标格、显示预览 | 只读 EvaluateDrop，不改占位、不抽真实随机 |
| 松手 | 结束手势与预览 | DropItemCommand(ElementId, SourceTile, TargetTile) |
| UI／棋盘外松手 | 显示回到当前权威格 | 非法目标拒绝，无业务变化 |
| 空格／其它 UI 点击 | 对应局部反馈 | 按 R 不自动取消选择；但其实际业务操作仍可使对象失效 |

命令同时携带物品身份和预期源格；出队时重新核对。若系统操作已移动／移除该物品，拒绝旧手势，不能改用“原格现在的另一个物品”。异步回调再加 SessionGeneration／绑定版本校验。

UI 预览与提交共用同一份只读能力规则。预览只是提示，真实执行以出队时状态为准。屏幕坐标、RectTransform、RaycastResult 不进入 Logic 命令。

## 放手判定顺序

建议使用一个可直接阅读的 DropRules 求解入口，而不是让互不相关的事件订阅者竞争改变棋盘。

1. 校验源实例、源位置、目标坐标、棋盘实例、区域门槛和源操作能力。
2. 同一格：保持状态，结束手势。可直接作局部反馈；若需要成功的统一命令结果，登记明确无变化操作，不能改变空 Batch 的基础语义。
3. 对已接入的特殊工具按明确业务顺序尝试；一个成功即确定结果。工具失败是否允许换位按配置和产品规则决定，不能吞掉明确错误。
4. 满足普通合成时，生成 Merge 结果；浅锁目标只走这一合法路径。
5. 目标为普通空格则移动；两个均允许换位的普通物品则换位。
6. 其余拒绝，Graphic 对齐当前逻辑位置。

M1 无特殊工具，第 3 步不存在。以后不能只把旧 FunctionType 数值当业务优先级搬过来；执行顺序应在规则与用例中可见。

## Tile 解锁与运行时锁 Effect

**D24／D25 已确认：Tile 保存唯一解锁进度，具有解锁 Function；Element 根据所处 Tile 挂载运行时锁 Effect。** D28 已确认下文二级锁操作表；D29 确定当前 Tile 不添加 Effect。数据与地编来源见 [03](03_状态模型与Profile.md#锁数据归属与表示d24d25-已确认)。以下类名与集中同步方式为实现约定；邻接分发与完整执行协议继续由第 6 项确定。

| 对象 | 职责与边界 |
| --- | --- |
| EntityTile.FunctionTileUnlock | 管理当前阶段；校验某种解锁原因是否适用，求解阶段变化；执行阶段中修改唯一进度 |
| TileSystem | 查位置、邻格和占位；不存第二份全盘锁进度，不自行决定解锁算法 |
| ElementSystem 与占位入口 | 创建／恢复／移除元素并维护双方关系；在关系稳定后同步来自 Tile 的效果 |
| EntityElement.EffectTileLock | 真正加入 Owner 的 Effects；只影响该元素，绑定来源 Tile，读取其只读阶段；不持久化、不自行推进 Tile |
| EntityViewElement 的 EffectViewTileLock | 按用户倾向负责二级锁蜘蛛网，走既有 FunctionViewEffects 管理；具体层级见 06 |

**运行 Effect 与持久锁进度不是两套可分别演进的数据。** Effect 使用来源引用和规则，不复制可写 Phase／Locked 字段；它的存在由集中同步维护。EntityTile 如暴露 Phase，应转发 FunctionTileUnlock 的值。其它独立 Effect 可保存自己的数据，不能一并丢弃。

### 集中同步入口

采用一个内部方法 `SyncTileLockEffect(element)`，由完成占位／阶段变化的逻辑执行入口调用，不由 View、查询方法或逐帧轮询调用。可直接实现于已有 ElementSystem／关联模块，不新增全局 EffectSystem。内部可传入已解析的 `occupiedTile`，为空仅表示元素已通过合法流程退出格子；不能把“活跃元素查不到 Tile”的错误当成已离开。

```text
找到该元素上“来自 Tile 的锁 Effect”这一专用实例
若元素已合法退出格子：移除该专用效果并结束
否则校验当前 Tile 存在、坐标相符、Tile.ElementId 等于 element.InstanceId
若当前 Tile 一级锁却已有元素：报告结构错误，不先增删效果
若当前 Tile 完全解锁：移除该专用效果并结束
当前 Tile 为二级锁：
  已有同来源效果：保留实例与 RuntimeId
  无效果或来源已改变：按实例键移除旧效果，添加 EffectTileLock(currentTile)
```

每个已占格 Element 至多有一份当前 Tile 来源的锁 Effect；独立气泡、冻结或其它物品锁不在这个同步入口的删除范围内。可用内部专用引用定位效果，仍统一加入普通 Effects 集合供查询与表现读取。来源换格时释放旧引用并生成新的 Effect 运行身份；释放宿主时清理来源引用。

| 入口 | 必须完成的同步 |
| --- | --- |
| 首次揭示／新局创建 | 创建元素并关联 Tile 后，按其当前进度装配效果；全部完成后开放查询 |
| 读档恢复 | 先恢复 Tile 和 Element／占位，再重建锁 Effect，随后开放输入与自动行为 |
| Tile 解锁 | 修改唯一进度，同一业务执行中同步当前占位元素的效果；随后发布稳定结果与表现 |
| 元素移动、换位或合法系统替换 | 改坐标与占位，按新的 Tile 重新同步；不改变任何 Tile 进度 |
| 元素消耗／销毁 | 退出活动集合并释放自身效果，清占位；不把清空占位当成解锁 |
| 撤销恢复 | 恢复元素自身数据，再按当前目标 Tile 同步；不从旧撤销记录恢复格锁 |

Tile 进度变化与效果同步之间不开放外部查询、不发布存档／表现、不等待动画。若内部失败，不把半同步结果当成功；完整故障出口由第 6 项确定。可在业务稳定边界验证“二级锁占位元素恰有对应效果、完全解锁元素没有该来源效果”。

准备解锁／合成时先捕获旧元素的锁效果显示快照，再改变 Tile 进度。旧蜘蛛网退出动画使用这个副本；不能稍后通过旧 Effect 的来源引用回读已经完全解锁的 Tile，否则会丢失解锁前的显示信息。新元素和重建 View 只使用当前稳定结果。

通用移除 Effect 的业务不能单独“驱散”此效果以解锁；真正解锁必须请求 FunctionTileUnlock 推进 Tile 后再同步。否则重建时会再次出现，且违反唯一进度来源。这里的底层 Remove 只供内部同步和生命周期清理使用。

### 方法输入与输出

| 方法轮廓 | 只读阶段需要哪些输入／输出 | 写入与发布 |
| --- | --- | --- |
| TryPrepareAdjacentMergeUnlock | 只读合成上下文、Owner 当前阶段、当前地图与坐标；返回 bool 及必要的下一阶段／默认元素创建描述 | 不改进度、不创建、不发正式合成事件 |
| TryPrepareTargetMergeUnlock | 已通过源／目标资格和完整合成校验的上下文、Owner 当前阶段；返回 bool 及阶段变化 | D28 已确认二级锁可作目标；进度变化与成功合成共同执行，准备阶段不修改进度 |
| ApplyPreparedUnlock | 预期旧阶段和已准备的下一阶段；先核对预期事实 | 写唯一 Phase；与元素创建／替换、占位同步由同一次业务组织完成 |
| SyncTileLockEffect | 元素及其当前合法占位；无业务奖励输出 | 内部维护实例集合；调用者完成全部变化后再发布当前效果快照 |

这些是具体业务输入，不建立 RuleCheck／BlockReason 或通用 object 参数袋。准备数据只用于紧接着的当前执行；经过异步等待或其它写入后必须重验，不能长期持有一份可过期的解锁许可。小型阶段记录与创建描述可用普通结构，不要求专门的事务／反应引擎。

### 解锁原因与完整变化

分别提供可读的规则方法，例如 `TryPrepareAdjacentMergeUnlock`、`TryPrepareTargetMergeUnlock`，而非无条件 `Phase--`。准备方法只读当前事实、返回 bool 与必要的局部变化数据；执行方法验证预期阶段后应用，不能由外部直接赋值 Phase。具体方法签名随最终执行协议落地。

- 邻接合成：一级锁首次揭示为二级锁；先校验地编内容可创建，再将进度、创建、占位及效果装配作为同一完整变化。
- 目标合成（D28）：普通 A 合成进二级锁 B，成功得到 C，同时目标 Tile 完全解锁；C 根据目标 Tile 最终阶段装配效果，不继承 B 的格锁。合成拒绝不推进 Tile。
- 普通移动／销毁／替换仅改变 Tile 的占位运行 ID。上述“目标合成解锁”是明确执行的解锁规则，不是任意替换都自动改变阶段。

之前“同一次邻接触发不跨两级”的含义：在位置 X 合成，只使邻格 Y 从一级变二级并创建 B；B 没有参与 X 的那次合成，不能因此也算成“B 已完成目标合成”。**这是两种触发条件，不是同一帧只能解锁一次的限制。** 随后确有另一件物品与 B 成功合成，可以立即完成下一阶段；重复派发同一来源不能重复创建 B。邻接分发、去重与写入协议见 [待讨论项 6](../待讨论项/6_Command与Operation执行边界.md#邻接解锁的响应阶段候选)。

## 锁与能力矩阵

这里的“操作权限”只是逐项说明**一个动作能否执行**，不增加权限管理系统。**D20／D22：下表均为方法＋bool 的查询语义，不是可写 CanClick／CanDrag 字段；D28 已确认二级锁这一列。** Effect.Blocks 的组合见 [10 第 3–4 节](10_Function与Effect建模讨论.md#3-权限查询普通方法与-bool)。元素限制由实际挂载的 EffectTileLock 参与；Tile 的占位／未揭示检查直接读取 Tile 事实，D29 当前不添加 TileEffect。

| 动作 | 一级锁 | 二级锁 | 完全解锁 |
| --- | --- | --- | --- |
| 点击选中 Element | 无元素可选 | **允许**；显示 UI 选择框，播放 Scale 果冻弹动（D26） | 按元素能力及其它 Effect |
| 拖拽 Element | 无元素 | **禁止**（D26） | 按元素能力及其它 Effect |
| 作为普通合成源 | 无元素 | **禁止**，逻辑入口也须检查 | 按完整合成条件 |
| 作为普通合成目标 | 无元素 | **条件允许**：源有资格、双方可合成、有合法结果，且其它 Effect 未阻止 | 按完整合成条件 |
| 点击激活生成／使用／开箱 | 无元素 | **禁止**，选择和果冻反馈不会激活能力 | 按能力及其它 Effect |
| 普通移动放入／换位 | 不能创建普通占位元素 | **禁止**；成功目标合成走独立合成分支 | 按占位及其它规则 |
| 玩家出售／删除 | 无元素 | **禁止** | 按价格、保护及其它规则 |
| 读档恢复原有占位 | 一级锁不应有元素记录 | **允许结构正确的恢复**，随后重建运行锁 Effect；恢复本身不解锁 | 恢复原有记录 |

对二级锁，选择动作不被本锁 Effect 阻止；其它独立 Effect 若阻止选择仍应生效。重复点击的果冻反馈不自动调用生成／使用 Function。UI 输入不能因“不可拖拽”就关闭整个元素的命中，否则会同时丢失已确认的点击反馈。

二级锁的 EffectTileLock 对 Select／MergeAsTarget 返回不阻止，对 Drag／MergeAsSource／Generate／Use／OpenChest／Swap／Sell／Delete 等上述禁止动作返回阻止；动作名按实际 API 对应。MergeAsTarget 不阻止不代表整个合成已获准，业务入口仍须核对双方条件。其它未来动作按具体需求补规则，不从“可选中”推导为可执行。

目标合成失败不得回退为换位移走二级锁元素；同类但没有合法合成结果，也不推进解锁。普通放置还须检查目的 Tile：锁格即使因合法系统移除变为空格，仍不能仅凭 ElementId 为空就允许移入。系统创建／恢复使用已定义的结构维护入口，不复用玩家拖放许可或偷偷清除 Tile 进度。

旧 R／L 的参考基线：浅锁可选中、不可拖、可被同 ID 普通元素合成；深锁不可操作；浅／深锁不允许激活、售出和删除。R 的锁格拒绝普通移动与浅锁允许目标合成是不同动作；L 的气泡支持拖动／换位，气泡整体权限仍由第 4 项确定。旧编号、四邻定义和限制不能自动成为新方案确认值。

## 合成的完整变化

建议由一个完整构造、一次登记的 MergeItemsOperation 维护共同不变量，附加变化可以保留为该操作的有序结果数据；不是先删源、回调里再建目标。

```text
读取源和目标的配置／状态，校验同 ID、nextId 和特殊限制
→ 在局部求解数据中释放源／目标占位并确定新物品
→ 按已选规则计算目标格解锁与指定邻格的一级锁揭示
→ 按所选项目的附加物顺序分配气泡、衍生物落点（具体规则另定）
→ 准备新身份和必要随机结果
→ 登记完整 MergeItemsOperation

Apply
→ 消耗源与目标、从活跃集合退役
→ 更新相关 Tile 进度、目标格放入新实例、首次揭示格创建元素
→ 完成所有受影响占位与运行锁 Effect 的同步
→ 放入已确定附加物并更新发现记录等已接入状态
→ 选中新结果，提交本次 ID／随机状态
```

L 先 CheckClone／CheckDerivant 再 OnTriggerUnlockGrid；新方案建议先求解主合成与锁变化，再分配附加落点。按当前揭示样例，一级锁进入二级锁并创建地编元素，不会增加普通产物空位。邻格使用四向还是八向尚未确定；旧 L 的四邻行为仅是参考。未来特殊放置／解锁为空地的规则须另行明确。

主合成必须成功，附加物空位不足如何处理见 05：建议不挤走原物、不自动塞待领取队列；附加物是否丢弃与其抽样时机要明确。主产物位置始终是目标格。

Graphic 所需结果至少有：消耗实例和旧外观／旧格、新实例和目标格、锁变化列表、附加产物及来源、选中变化。不能等动画播放时再读已被释放对象，也不能只查最终状态猜旧图标。

## 移动与换位

移动应一起清空源 EntityTile.ElementId、填入目标 ElementId、更新 EntityElement.Coord；换位同样维护两个元素的位置与两格占位。ElementSystem 通过 TileSystem 的格子入口协调关联，具体 API 与 Operation 组织待定。元素 ID 不进入 Tile 存档；元素位置写入自己的存档。生成 Function 数据或附加影响在移动时怎样变化，由对应规则决定。

如果拖拽过程中系统到期事件改变目标，提交时重新求解；若原预览不成立则回位或执行当前合法分支，具体手感可讨论。默认不在每帧拖拽时发送占位变更命令。

## 售出 删除与恢复

三个入口可复用同一 RemovalRules：

| 请求 | 校验 | 成功结果 |
| --- | --- | --- |
| SellItem | 普通可移除、价格>0、满足生成器保护 | 退役物品、释放格子、增加余额、建立一条撤销记录 |
| DeleteItem | 普通可移除、价格=0、满足同一生成器保护 | 同上但不改余额 |
| RestoreRemovedItem | 记录有效、原格仍空、可扣回出售收入 | 恢复完整实例、扣回收入、凭据失效；不能回放原删除再重建 |

售出与删除都校验当前选中实例，并使用同一移除保护规则。价格=-1 禁止移除；缺失价格不能无条件解释为零价。旧表空值较多，导入规则需要显式决定。

生成器保护用当前持有状态，而非仅图鉴历史。达到门槛前整条链禁移除；达到门槛后最高等级唯一一件禁移除，其余按价格。持有统计是否包含仓库，以及哪些生成器种类享有保护，需要 M2 前确认。

选中另一个物品／原格被占用时永久使本条凭据失效；之后原格重新空出来也不重新开启旧撤销。原格占用检查不能只在点击撤销按钮时做，否则会错误延长入口生命周期。

## 性能与可测性

参考配置为 7×9 共 63 格。TileSystem 可按坐标组织格子集合，ElementSystem 按运行 ID 管理元素；整盘规则检查 O(格数)，单次普通合成局部更新 O(1)，附加物找位最坏 O(格数)。先做清楚的代码和测量，再决定空格索引／池化，不复制三合大地图的空间分块系统。

实施与验收统一见 [08](08_实现顺序与验证.md)。
