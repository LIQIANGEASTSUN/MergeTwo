# 棋盘交互与合成

一次放手只提交一次业务意图。Logic 决定移动、合成、特殊工具使用或换位的唯一结果；Graphic 负责跟手、预览和结果动画。失败回原位是显示对齐，不是把逻辑从拖拽中的屏幕坐标恢复回来。

## 输入与查询

| 输入 | Graphic 工作 | Logic 请求 |
| --- | --- | --- |
| 首次点击物品 | 点击反馈 | 选择当前物品，必要时处理旧选择的规则后果 |
| 再点已选物品 | 点击反馈 | ActivateItemCommand：生成、使用、打开箱子等分支 |
| 开始拖动 | 建立本次手势、记录绑定、暂隐藏选择框 | 需要时提交选择命令；校验可拖拽 |
| 拖动过程 | 跟手、算目标格、显示预览 | 只读 EvaluateDrop，不改占位、不抽真实随机 |
| 松手 | 结束手势与预览 | DropItemCommand(ItemInstanceId, SourceCell, TargetCell) |
| UI／棋盘外松手 | 显示回到当前权威格 | 非法目标拒绝，无业务变化 |
| 空格／其它 UI 点击 | 对应局部反馈 | 按 R 不自动取消选择；但其实际业务操作仍可使对象失效 |

命令同时携带物品身份和预期源格；出队时重新核对。若系统操作已移动／移除该物品，拒绝旧手势，不能改用“原格现在的另一个物品”。异步回调再加 SessionGeneration／绑定版本校验。

UI 预览与提交共用同一份只读能力规则。预览只是提示，真实执行以出队时状态为准。屏幕坐标、RectTransform、RaycastResult 不进入 Logic 命令。

## 放手判定顺序

建议使用一个可直接阅读的 DropRules 求解入口，而不是让互不相关的事件订阅者竞争改变棋盘。

1. 校验源实例、源位置、目标坐标、棋盘实例、区域门槛和源操作能力。
2. 同一格：保持状态，结束手势。可直接作局部反馈；若需要成功的统一命令结果，登记明确无变化操作，不能改变空 Batch 的基础语义。
3. 对已接入的特殊工具按明确业务顺序尝试；一个成功即确定结果。工具失败是否允许换位按配置和产品规则决定，不能吞掉明确错误。
4. 满足普通合成时，生成 Merge 结果；浅锁目标只走这一合法路径。
5. 目标为普通空格则移动；两个均允许换位的普通物品则换位。
6. 其余拒绝，Graphic 对齐当前逻辑位置。

M1 无特殊工具，第 3 步不存在。以后不能只把旧 FunctionType 数值当业务优先级搬过来；执行顺序应在规则与用例中可见。

## 锁与能力矩阵建议

锁可以按 [10](10_Function与Effect建模讨论.md) 改为 Cell／Item 的附加效果。下表描述的是有效业务限制，不强制使用互斥枚举；源／目标能力应分别查询，浅锁可被合成的规则保持不变。具体数据表示待 Q11。

区域未开放时先拒绝业务操作，展示区域说明属于 UI。下表是棋盘层与物品状态共同满足后的有效能力，不代表所有组合都合法。

| 有效状态 | 可选中 | 可主动拖动 | 可作为普通合成目标 | 可激活／出售／删除 |
| --- | --- | --- | --- | --- |
| 普通 | 是 | 是 | 同 ID 且双方有合法合成关系 | 按物品能力／价格／保护规则 |
| 浅锁 | 是 | 否 | 是，源必须普通且同 ID | 否 |
| 深锁 | 否 | 否 | 否 | 否 |
| 气泡 | 是 | L 支持拖动／换位；R 未完整规定，待确认 | 否 | 只能走专用气泡解锁／到期规则 |

R 的“拖到锁定地格移动失败”与“浅锁物品可被合成”应解释为：**禁止普通移动／换位，不禁止满足条件的浅锁目标合成**。

## 合成的完整变化

建议由一个 MergeItemsOperation 维护共同不变量，附加变化可以保留为该操作的有序结果数据；不是先删源、回调里再建目标。

```text
读取源和目标的配置／状态，校验同 ID、nextId 和特殊限制
→ 在局部求解数据中释放源／目标占位并确定新物品
→ 计算目标格解锁与四邻深锁转浅锁
→ 按已确认优先级分配气泡、衍生物落点
→ 准备新身份和必要随机结果
→ 登记完整 MergeItemsOperation

Apply
→ 消耗源与目标、从活跃集合退役
→ 目标格放入新实例，相关格子锁一起更新
→ 放入已确定附加物并更新发现记录等已接入状态
→ 选中新结果，提交本次 ID／随机状态
```

“目标解锁／四邻解锁”和附加物找位的先后会影响可用格集合。L 先 CheckClone／CheckDerivant 再 OnTriggerUnlockGrid；建议先按 R 的合成结果完成解锁，再求附加落点，但这是待裁定的边界，需用邻格“深锁且为空”的例子确认。对通常含物品的深锁格，这个差异可能不可见。

主合成必须成功，附加物空位不足如何处理见 05：建议不挤走原物、不自动塞待领取队列；附加物是否丢弃与其抽样时机要明确。主产物位置始终是目标格。

Graphic 所需结果至少有：消耗实例和旧外观／旧格、新实例和目标格、锁变化列表、附加产物及来源、选中变化。不能等动画播放时再读已被释放对象，也不能只查最终状态猜旧图标。

## 移动与换位

MoveItemOperation 同时改物品 Location 与两格占位。SwapItemsOperation 同时改两个实例的位置和两格占位。两者不改变生成器轮次、气泡截止时间和持久身份。

如果拖拽过程中系统到期事件改变目标，提交时重新求解；若原预览不成立则回位或执行当前合法分支，具体手感可讨论。默认不在每帧拖拽时发送占位变更命令。

## 售出 删除与恢复

三个入口可复用同一 RemovalRules：

| 请求 | 校验 | 成功结果 |
| --- | --- | --- |
| SellItem | 普通可移除、价格>0、满足生成器保护 | 退役物品、释放格子、增加余额、建立一条撤销记录 |
| DeleteItem | 普通可移除、价格=0 | 同上但不改余额 |
| RestoreRemovedItem | 记录有效、原格仍空、可扣回出售收入 | 恢复完整实例、扣回收入、凭据失效；不能回放原删除再重建 |

价格=-1 禁止移除；缺失价格不能无条件解释为零价。旧表空值较多，导入规则需要显式决定。

生成器保护用当前持有状态，而非仅图鉴历史。达到门槛前整条链禁移除；达到门槛后最高等级唯一一件禁移除，其余按价格。持有统计是否包含仓库，以及哪些生成器种类享有保护，需要 M2 前确认。

选中另一个物品／原格被占用时永久使本条凭据失效；之后原格重新空出来也不重新开启旧撤销。原格占用检查不能只在点击撤销按钮时做，否则会错误延长入口生命周期。

## 性能与可测性

参考配置为 7×9 共 63 格。格子数组＋物品字典即可；整盘规则检查 O(格数)，单次普通合成局部更新 O(1)，附加物找位最坏 O(格数)。先做清楚的代码和测量，再决定空格索引／池化，不复制三合大地图的空间分块系统。

## 实现顺序建议

1. **Step 1：写纯数据能力和落点查询。** 先定义普通／浅锁／深锁的矩阵以及“同格／空格／不同物／同物”的预期。
2. **Step 2：实现 Move／Swap／Merge 命令。** 一次放手只有一个成功分支，运行时身份不随位置改变；无 Graphic 也能完整求解。
3. **Step 3：加入选择和 UI 输入。** 跟手不改占位；无表现／零时长／取消时，规则结果相同。
4. **Step 4：补锁和附加产物。** 一个完整业务操作覆盖主结果、解锁与空间竞争，冻结先后顺序。
5. **Step 5：加入售出／删除撤销。** 和 Profile、时间规则联测；重复撤销、原格先占后空、余额不足均有固定结果。
