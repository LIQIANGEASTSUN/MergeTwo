## 4. 总管理器与宿主接线

建议增加一个 MergeTwoManager，负责持有和编排本次棋盘运行实例；名称待确认。已有 TileSystem、ElementSystem 的职责不变，不再添加 Board。管理器协调初始化、运行入口和释放，业务算法继续归属对应 Function／规则及 Consumer／Operation。

| 位置 | 负责 | 不应承担 |
| --- | --- | --- |
| Host／MergeTwoEntry | 获取已经注册的 Profile、加载配置与 UGUI 根、连接宿主时间／窗口／经济等实际服务，创建管理器 | 合成判断、锁进度或气泡期限规则 |
| MergeTwoManager | 持有 CommandRuntime、TileSystem、ElementSystem、Graphic 入口；协调启动、输入可用时点、后台恢复和 Release | 把生成／合成／效果规则汇总成中央大分支 |
| Core/Logic | 基于配置和原记录求解、维护对象关系，经已确认 Operation 修改数据 | 资源加载、文件保存、直接取真实时间或访问 View |
| Runtime/Graphic 与 Input | UGUI 显示与命中，View／效果装配，输入转 Command；时间敏感输入由统一宿主边界携带时间戳 | 根据画面位置回写业务坐标，动画结束再结算 |
| Host/Proxy | 调用确实位于其它业务模块的权威入口，把外部结果转为 Command | 维护第二份正式余额或从支付回调直接改活跃 Entity |

- 薄 Entity／EntityView、Function／Effect 基类按正式正文实现，借鉴参考项目的数据持有与绑定方式；不移植三合的 State、HungUp、区域等业务。
- 只有真实外部依赖需要隔离时才建立窄契约；内部一个实现优先显式调用，不建立服务定位器、通用依赖注入框架或每类一个接口。
- 已有底层资源能力可按宿主规则复用，例如已核对三合 ResourceProxy 转发 ResourceHub；不为了资源加载再依赖 MergeManager.ResourceProxy。资源加载、Owner 与释放仍由 Graphic／Host 边界管理。
- 逻辑源码不直接调用 Unity 场景／UI API，且可以在不创建 View 的条件下验证。Profile setter 仍连接宿主 Hub；本轮不承诺独立无 Unity 的命令行运行包，也不据此新建存档 DTO。
- 配置是只读输入，生成 Profile 是持久权威，ElementId／运行锁 Effect 是派生数据；每项写入职责继续按 03／04／10，不因目录调整改变。

### 启动和释放怎样落到管理器

以下串起已经确认的时序，只新增候选装配位置：

1. Host 准备配置、已注册 Profile 和实际服务；管理器构造各模块。模块先统一 Init，再统一 Start，装配执行注册表；此时玩家输入和周期时间驱动尚未启用。
2. 按 MapData.Initialize 填充首次数据或使用已有记录。全部创建 Tile，再创建 Element，完成占位和派生锁，再启动需要完整局面的实体能力。
3. 注册实体相关 Consumer、公共时间 Consumer 及表现 Consumer，绑定 UGUI View／窗口服务。模块的 Start 与实体完成关联后的 Start 是两个时点，不在创建第一个元素时运行全盘规则。
4. 按 05 提交首次当前时间的 CommandTimePulse；WaitPay／支付关联已恢复。检查在安全宿主边界执行完成后，再开放玩家输入和周期驱动；不能把重入 Submit 的入队成功当成检查完成。
5. 整体 Release 按 D58：停输入／时间输入、BeginShutdown 与旧回调失效 → Graphic 解绑并释放窗口及全部 View → 逻辑停止能力并释放活跃／退役 Entity → 执行核心与本实例服务收尾。若由同步 Batch 内发起，等该调用结束后清理。不发送最后一次 Tick／关窗 Command，不删除 Profile、不清 WaitPay。

总管理器按依赖明确调用释放，不能依赖宿主 SystemComponent 的默认释放顺序，也不修改公共 SystemComponent 来迁就二合。普通业务删除仍按 D54 先移除存档和索引，再等待 View 退场；整体退出直接释放资源，两条路径不可合并。
