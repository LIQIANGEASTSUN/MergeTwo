## 具体实现类命名（D64）

具体实现类统一以前缀表示职责；效果采用本项目既有拼写 `Effect`（用户示例 Efect 对应此概念）。

| 职责 | 命名规则 | 二合示例 |
| --- | --- | --- |
| 输入命令 | CommandXXX | CommandTimePulse、CommandDropElement |
| 命令消费者 | CommandConsumerXXX | CommandConsumerTimePulse、CommandConsumerDropElement |
| 执行操作 | OperationXXX | OperationRefreshTimeDisplay、OperationMergeElements |
| 操作消费者 | OperationConsumerXXX | OperationConsumerRefreshTimeDisplay |
| 逻辑功能／表现功能 | FunctionXXX／FunctionViewXXX | FunctionTileUnlock、FunctionViewEffects |
| 逻辑效果／效果表现 | EffectXXX／EffectViewXXX | EffectBubble、EffectViewBubble |
| 逻辑实体／实体表现 | EntityXXX／EntityViewXXX | EntityElement／EntityViewElement、EntityTile／EntityViewTile |

一个 Command 仍可有多个 Consumer，例如 CommandConsumerBubbleTime、CommandConsumerGeneratorTime 同时消费 CommandTimePulse；名称不要求所有消费者共享同一后缀。Function／Effect 自身实现 Command Consumer 接口时，仍按其主要职责命名，不强制再套一个空适配类。

接口保留 `ICommand`、`ICommandConsumer`、`IAtomicOperation` 等已确认执行契约，不因具体类命名调整修改核心语义。TileSystem／ElementSystem、Profile 生成类和参考项目的原类名／文件路径保持各自约定；本次不扩展为全项目类型重命名。历史决策与源码证据可能使用旧示例名，二合实施以本节及当前正文为准。

## 已确认的执行主线

接口、算法、失败与持久化边界、源码对应和实施顺序统一见 [02b Command 与 Operation 执行方案](02b_Command与Operation执行方案.md)。本页只保留总览。

```text
Command 输入
→ 按注册顺序分发给多个匹配的 Command Consumer
→ 各 Consumer 构造并登记 Operation 到同一个 OperationBatch
→ Batch.End 按顺序执行全部 Apply
→ 全部成功后，按顺序分发给各 Operation Consumer
→ View／表现 Function 展示结果；动画独立完成
```

D43 沿用参考核心，不改变收集失败保留已登记项、Apply 失败不回滚、表现 false 汇总／异常传播以及 Submit 的同步／重入含义。Function／Effect 的权限仍在业务准备入口检查，不靠另一个 Consumer 返回 false 否决已有操作。

D44 明确：Command 是输入，需要时可以记录稳定命令数据，用于回放／Redo／Undo 扩展；Operation 是 Consumer 产生的运行执行单元，Operation 与 OperationBatch 不存档。D71 明确本项目不实现重播、Undo、Redo；上述能力仅为架构考虑，不增加历史框架或 Undo 接口。D70 的售卖不可撤销、逆序 Undo 遇不可撤销项停止保留为未来扩展原则，见 02b。

D45／D46 已确定五类操作与主合成→邻格揭示同批，输入、Apply 顺序和结果见 [02b 第 5 节](02b_Command与Operation执行方案.md#5-二合-operation-的实施契约)。第 6 项已收敛删除；窗口失败与保护按 05 的 D59／D62 实施；Profile、时间和生命周期见 03／05／06，模块装配见第 10 项。

| 对象 | 职责 |
| --- | --- |
| TileSystem | 管理全部 EntityTile，提供坐标／邻格查询与占位操作，替代原 Board 对象 |
| ElementSystem | 管理 EntityElement；通过 TileSystem 的格子入口建立、解除关联 |

D24／D25 已确定 EntityTile 具有解锁 Function，Element 实际挂载来自 Tile 的锁 Effect；具体实现和同步入口见 [04](04_棋盘交互与合成.md#tile-解锁与运行时锁-effect)。所有 Tile 的能力组成仍一致，阶段差异来自各自数据。**D29：当前 Tile 不添加 Effect，解锁规则归 FunctionTileUnlock；** 不为监听邻接变化预建 TileEffect。以后存在独立附加需求时再扩展。

### System 的最小调用职责

下面是按 D12–D14／D25 补齐的代码设计轮廓，方法名可以按宿主规范调整；不新增 Board 或占位管理系统。对外只读查询与执行阶段内部写入分开，UI 不能直接调用后者。

| 所属对象／入口 | 输入与输出 | 调用约束 |
| --- | --- | --- |
| TileSystem.TryGetTile | 坐标 → bool 与 EntityTile | 只读；查不到是查询结果，不自动创建格子 |
| TileSystem.GetNeighbors | 原点与项目邻接规则 → 去重 Tile 集合 | 只查几何关系；一级锁等资格由业务规则检查 |
| ElementSystem.TryGetElement | 运行 InstanceId → bool 与活跃 EntityElement | 不返回已消费元素；配置 ID 不是实例查询键 |
| ElementSystem.CreateNew | 元素配置、已验证的目标 Tile、该项目的初始数据 → 新元素 | 仅新局／首次揭示／生成等明确创建入口；新建存档时按 03 分配持久 UniqueId，再分配运行身份并初始化能力 |
| ElementSystem.Restore | 元素保存记录、目标 Tile → 恢复元素 | 直接绑定已有记录，不创建替代 elementData、不分配 UniqueId、不做新建赠送；两种入口都须完成占位和派生效果同步 |
| ElementSystem.Move／Swap | 已确认的元素、预期源格、目标格 | 先检查所有关联与目的占位，再同时修改双方位置／占位，最后同步受影响元素的锁 Effect |
| ElementSystem.Remove | 预期活跃元素 | 上层先捕获退场显示数据；内部解除占位、退出活跃查询、清理能力／效果；不隐式解锁 Tile |
| TileSystem 的内部占位写入口 | Tile、预期旧 ElementId、新 ElementId | 只维护格子占位，不计算合成或解锁；由上述 ElementSystem 流程协调元素位置 |

这些写入口只维护对象不变量，不代替玩家的 CanMove／CanMerge 等资格判断。恢复锁格原有占位可合法调用 Restore，而玩家普通放置仍须通过业务规则；不为复用一个方法增加到处可传的 skipLockCheck 标记。预期占位在执行时不符属于过期请求或内部执行错误，须在对应阶段处理，不能先改一半再返回普通 false。

一个正常业务入口先只读校验／准备，再调用上述内部方法，待位置、占位、锁效果全部一致后才发布结果。正式执行由 Operation.Apply 调用；基础模块验证可由受控测试入口调用，不因此另建一套正式命令框架。没有任何普通 UI 或 View 回调能直接设置 Coord／ElementId。

格子建模的参考依据保留于各项目分析报告：[Merge Studio](/Users/betta/Company/Projects/MergeTwo/参考项目/MergeStudio_4.5.0_APKPure/_分析实现方案/01_架构与数据模型.md)提供 CellEntity／CellController 与锁区内容的例子；[Merge Cooking](/Users/betta/Company/Projects/MergeTwo/参考项目/Merge_Cooking_1.59.0_APKPure/_分析实现方案/01_架构与数据模型.md)提供位置规则与物品关系的例子；[Travel Town](/Users/betta/Company/Projects/MergeTwo/参考项目/TravelTown_2.12.1751_APKPure_arm64/_分析实现方案/01_架构与数据模型.md)已分析的新路径未见逐格完整 Entity。这些是比较依据，D10 已选定本项目独立 EntityTile／EntityViewTile；此前仅保留轻量格子记录的建议已被替代。
