# 生成器与时间

生成器是这次最容易在重写中丢失规则的模块。不能把它简化成“点击后进入统一 CD”，也不能沿用旧代码的轮内计数同时表示固定产出进度。R／L 的具体冲突见 [01](01_需求与历史差异.md)。

## 建议的数据

| 配置 | 含义 |
| --- | --- |
| FixedOutputs | 每实例固定段的输出序列，确切语义待 C04 决定 |
| WeightedOutputs | 正常产出的有序权重池 |
| UsesPerRound[]／CooldownSeconds[] | 一一对应的每轮次数与冷却，不接受长度不匹配 |
| OutputCountPerUse | 每次激活产出的颗数，与本轮次数分开 |
| CostPerUse | 每次成功激活的货币与费用 |
| LockedOutputProbability | 浅锁产物概率，单位归一化 |
| ExhaustionMode／ReplacementId | 正常循环、耗尽消失、耗尽变更 |

| 运行／持久状态 | 含义 |
| --- | --- |
| FixedOutputCursor | 已产出的固定段进度，不与 roundUsed 混用 |
| RoundIndex | 当前循环轮次，初始明确为第 0 轮 |
| RoundUsed | 当前轮已使用次数 |
| HasRoundStarted | 区分未开始与“截止时间恰为 0”，也可用等价显式状态 |
| RoundEndsAt | 已开始冷却的截止时间，统一 UTC 秒或毫秒；建议整个模块采用一种整数单位 |
| PausedRemaining／TimerMode | 后续入仓暂停剩余时长，不与运行截止时间同时生效 |

是否保存“完成总轮次数”取决于规则和统计需求。不要照抄名为 historyCount、实际表达轮次的字段，再让新代码猜语义。

## 单次生成链路

```text
ActivateItemCommand
→ 校验物品身份／普通状态／区域／选择条件
→ 使用命令采样的当前时间计算本次有效生成器状态
→ 查费用、空位和锁定产出限制
→ 在局部求解上下文抽样并确定全部产物与落点
→ 登记 GenerateItemsOperation
→ Apply 同步扣费、推进次数／固定游标、更新计时、创建产物
→ 耗尽时同次处理移除或变更
→ 发布稳定快照，再播放点击与飞出动画
```

“当前时间”由 Host／时间适配提供，Logic 不读取 Time.time／DateTime.Now。正常冷却到期是独立可提交的时间变化；不能把它和“产出成功”混为一谈。若余额或空位不足，生成请求不消费费用、次数和随机；到期归一化可由独立的 AdvanceTime 命令完成并保存。

抽样要在必要前置校验后进行，或使用本次局部随机副本成功后提交。表现用的随机抖动不能影响逻辑结果。首期没有通用 Replay，但可控时间／随机有直接的规则测试价值。

## 冷却示例

假设 `num=[10,10,10]`、`cd=[150,150,300]`，以下是按 R 整理的**建议解释**，需确认启动下一轮的细节。

| 情况 | 建议状态转换 |
| --- | --- |
| 第 1／2 轮第一次正常产出 | 记录 roundEndsAt = now + 当前轮 CD；仍可继续点击直到次数耗尽 |
| 第 1／2 轮次数提前耗尽 | 停止产出，等待既有 roundEndsAt，不重新从最后点击计时 |
| 第 1／2 轮时间先到、次数未耗尽 | 未用次数不累加，结束这一轮，下一轮次数恢复 |
| 进入新非末轮 | 建议等待下一次实际产出启动该轮计时；L 会在轮次切换时设置新 end，属于待确认差异 |
| 第 3 轮尚未耗尽 | 不以第一次产出时间自动重置次数 |
| 第 3 轮最后一次产出 | 开始 300 秒 CD |
| 第 3 轮 CD 到期 | 返回第 1 轮，轮内次数清零 |
| 付费完成当前冷却 | 只结束当前轮，按统一转换进入下一轮，不把全循环历史清空 |

例如非末轮 CD 为 8 小时，12:00 首次产出、16:00 用尽，则还剩 4 小时；20:00 尚未用尽也应切换下一轮。末轮从用尽时起计时。新建 `end=0` 不得被当成“已经完成首轮”。

## 固定段必须单独决定

推荐按 R 前段：每实例先依次产出固定列表，固定段结束后进入普通随机／循环，不重复赠送固定序列。待确认的问题包括：固定段是否扣费、是否消耗 num 次数、产出最后一颗固定物时是否开始普通计时、无随机池时如何继续。

旧 L 的 `GenerateItem(itemId, curCount+1)` 是轮内索引，且无随机池时重复最后一个固定物；它不能证明推荐语义已经存在。合成新生成器是否重置固定段与 C12 一起决定，避免通过合成／撤销反复领取不应重复的奖励。

## 多颗 空位和空间优先级

M1 可使用 OutputCountPerUse=1 的确定配置。多颗正式接入建议在“全量可放才成功”和“允许部分生成并定义费用／次数”中选择；推荐先全量可放才成功，避免半扣费，但尚未确认。

统一 PlacementRules 按“上→右上→右→右下→下→左下→左→左上→向外继续”的顺时针螺旋查找，跳过越界、不可操作和已占格。同一求解的已分配落点也要视为占用。图示来自 R 的产出位置图，不能只写“找最近空格”。

合成的可选产物按 R：气泡→衍生→被动生成。普通生成器的费用产物不能被低优先级自动生成抢走。建议先完整求解当前玩家命令及其派生结果，提交后再调度被动机会。

满盘时可选气泡／衍生是否直接不产生、是否仍消耗一次抽样应冻结；建议保持“无落点不产生，不进待领取队列”，同时明确抽样顺序。等待奖励队列属于不同业务，不当成所有产出失败的万能兜底。

## 时间推进与离线

自然时间用于冷却和气泡期限；动画 deltaTime 只用于显示。一个 Host 采样时间后发 `AdvanceTimeCommand`，按稳定顺序处理确实到期的对象，不必每帧给每个倒计时写 Profile。

建议统一在以下时机归一化：恢复／显示前、有效截止时间到达、与对象相关的命令执行前。使用一个边界服务或现有 TimerHub 调度到期检查；停止／销毁归调用方所有。不使用 UniTask.Delay／WaitUntil 轮询规则。

离线恢复建议只推进能由已保存截止时间证明成立的冷却／到期变化；下一轮若需实际产出才计时，不按离线时长无限补轮。被动生成是否离线补产未在 R 明确，建议首期不补产，重新进入后按当前空间处理。该建议需要确认，不能把“自然时间冷却”直接推出“离线无限生产”。

系统时间倒退时不让已用次数或余额回退。使用项目可信时间来源还是本机 UTC、允许的修正策略，在首期实现前明确；本地验证不宣称防作弊。

## 被动生成

触发入口为进入棋盘、移动后、相关空格出现、冷却恢复。Logic 统一收集有资格的候选，按配置 ID 大者优先；同 ID 的冲突使用逻辑随机裁定。

R 的 0.1 秒可能表达业务产出间隔，也可能主要是演出节奏，需确认。若为业务间隔，使用明确的下一次可生产时间，每次时间命令产一颗并重新校验；若只是表现间隔，可先一次确定全部允许产物，再在 Graphic 中错峰。两种结果不能未经讨论混用，且都不允许 Tween 完成驱动规则。

八邻找不到空位时等待新的状态变化，不递归空转。不搬用每个 AutoGeneratorFunction 各自递归 0.1 秒回调的方式。

## 气泡时间

气泡生成时逻辑立即确定截止时间，出现动画晚一点不重置寿命。到期且未选中就执行替换；选中则只保留到期事实，取消选择时再处理。

付费解锁使用执行时的身份、到期策略和余额重新校验；支付展示窗口不能直接保留一个 Article 引用在未来回调里扣费／改状态。旧对象已移除时拒绝，不作用到同格新物品。

## 实现顺序建议

1. **Step 1：冻结时间单位和初始状态。** 选定时钟来源，写出新建、非末轮、末轮的状态表。
2. **Step 2：实现单颗生成。** 校验先于扣费／次数／随机提交，覆盖满盘和余额不足；与 M1 Profile 往返贯通。
3. **Step 3：裁定固定段和多颗规则。** 新增独立游标及完整空间分配，一次输出全部业务结果。
4. **Step 4：加入到期和恢复。** 假时钟跨轮、跨天、倒退及重新进入；不等待真实 8 小时。
5. **Step 5：加入气泡和被动生成。** 确认选择保护、空间优先级和 0.1 秒语义后验证竞争，不由动画驱动产出。
