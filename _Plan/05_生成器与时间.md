# 生成器与时间

**D15 已确认**：生成次数与冷却属于生成 Function 的内部字段，不为它们另建 State 组件／系统，也不改作 Effect。首次、第二次和后续产出都是生成算法的一部分，每个项目可自定义；具体序列、轮次、计次／扣费、空间不足策略与继承规则已退出本轮架构前置讨论。

本页前半部分保留 R／L 的生成器证据与原候选作为**可选项目样例**，用于检验扩展接口，不要求先裁定这些算法才能讨论架构。R／L 差异见 [01](01_需求与历史差异.md)；已确认的时间输入见下文[命令时间戳契约](#命令时间戳契约d56-已确认)，宿主调度见下文[调度与恢复](#调度与恢复的接续边界)，整体关闭见 [06 生命周期](06_表现与资源.md#生命周期归属)。文末 [气泡 Effect 与生命周期](#气泡-effect-与生命周期)单独区分 D31–D42 的确认规则与本轮实现建议。

此前“固定段扣标准费用但不占普通次数”“合成后统一重置固定段与轮次”等助手建议均未确认为通用规则，也未批准其相反规则；不以裁定前三次产出作为架构前提。生成 Function 的装配、方法＋bool 查询与参数修正由 [10 实现方案](10_Function与Effect建模讨论.md)维护，本文使用 FunctionGenerate 作为实现用名；具体产出算法由项目自定，数据保存协议见 [03](03_状态模型与Profile.md)。

## 生成 Function 的数据归属与可选字段示例

| 配置 | 含义 |
| --- | --- |
| FixedOutputs | 可选固定段输出序列；C04 保留来源差异，算法由项目定义 |
| WeightedOutputs | 正常产出的有序权重池 |
| UsesPerRound[]／CooldownSeconds[] | 一一对应的每轮次数与冷却，不接受长度不匹配 |
| OutputCountPerUse | 每次激活产出的颗数，与本轮次数分开 |
| CostPerUse | 每次成功激活的货币与费用 |
| LockedOutputProbability | 浅锁产物概率，单位归一化 |
| ExhaustionMode／ReplacementId | 正常循环、耗尽消失、耗尽变更 |

| 生成 Function 内部字段／自有数据记录 | 示例含义 |
| --- | --- |
| FixedOutputCursor | 已产出的固定段进度，不与 roundUsed 混用 |
| RoundIndex | 当前循环轮次，初始明确为第 0 轮 |
| RoundUsed | 当前轮已使用次数 |
| RoundTimer | 只选一个计时表示：NotStarted，或 Running(EndsAt)；入仓阶段再加 Paused(Remaining) |

时间统一一种整数单位；零值不隐含“已到期”。不同时保存 HasRoundStarted、TimerMode 和多份可写期限，避免组合矛盾。是否保存“完成总轮次数”取决于规则和统计需求。不要照抄名为 historyCount、实际表达轮次的字段，再让新代码猜语义。

## 单次生成链路（业务接线候选）

```text
CommandActivateElement
→ 校验物品身份／普通状态／区域／选择条件
→ 使用本次命令携带的时间戳；检查必要的到期条件
→ 查费用、空位和锁定产出限制
→ 在局部求解上下文抽样并确定全部产物与落点
→ 完整结果构造完毕后一次登记 OperationGenerateItems
→ Apply 同步扣费、推进次数／固定游标、更新计时、创建产物
→ 耗尽时同次处理移除或变更
→ 全部 Apply 成功后分发点击与飞出表现（Profile 原记录在 Apply 中已修改，宿主负责保存）
```

D56 已确认命令携带本次时间戳，正常运行在宿主输入边界取得，业务逻辑只使用传入值，重播使用原命令记录值；具体契约见下文。普通冷却可直接按保存的时间查询，不一定存在需要写入的“到期完成”变化。若具体算法要求到期切轮次／恢复次数，该变化与“产出成功”分开组织；余额或空位不足不消费费用、次数和随机。需要写入的时间变化经 Operation 完成，定时链路按下文 D57。

抽样要在必要前置校验后进行，或使用本次局部随机副本成功后提交。表现用的随机抖动不能影响逻辑结果。首期没有通用 Replay，但可控时间／随机有直接的规则测试价值。

## 冷却示例（来自旧需求，非通用规则）

假设 `num=[10,10,10]`、`cd=[150,150,300]`，以下保留按 R 整理的**项目样例解释**，启动下一轮的细节由采用该算法的项目定义。

| 情况 | 建议状态转换 |
| --- | --- |
| 第 1／2 轮第一次正常产出 | 记录 roundEndsAt = now + 当前轮 CD；仍可继续点击直到次数耗尽 |
| 第 1／2 轮次数提前耗尽 | 停止产出，等待既有 roundEndsAt，不重新从最后点击计时 |
| 第 1／2 轮时间先到、次数未耗尽 | 未用次数不累加，结束这一轮，下一轮次数恢复 |
| 进入新非末轮 | 建议等待下一次实际产出启动该轮计时；L 会在轮次切换时设置新 end，属于待确认差异 |
| 第 3 轮尚未耗尽 | 不以第一次产出时间自动重置次数 |
| 第 3 轮最后一次产出 | 开始 300 秒 CD |
| 第 3 轮 CD 到期 | 返回第 1 轮，轮内次数清零 |
| 付费完成当前冷却 | 只结束当前轮，按统一转换进入下一轮，不把全循环历史清空 |

例如非末轮 CD 为 8 小时，12:00 首次产出、16:00 用尽，则还剩 4 小时；20:00 尚未用尽也应切换下一轮。末轮从用尽时起计时。新建 `end=0` 不得被当成“已经完成首轮”。

## 固定前缀与普通产出示例

原推荐按 R 组织的固定产出样例是：每实例先依次产出固定列表，完成后进入普通产出，不重复赠送固定前缀。文末“按序循环”的说明位于普通产出配置，可能是另一种顺序池模式；它与固定前缀可以并存，不先认定两段要求互斥。项目选择此算法时自行定义固定段是否扣费、是否消耗 num 次数、最后一颗固定物是否开始普通计时、无随机池时如何继续；这些不再作为本轮必答题。

旧 L 的 `GenerateItem(itemId, curCount+1)` 是轮内索引，且无随机池时重复最后一个固定物；它不能证明推荐语义已经存在。C12 保留合成新生成器重置／继承的来源差异；具体项目自行选择，并检验与自身固定产物及撤销规则的一致性。

## 多颗、空位和空间优先级示例

M1 可使用 OutputCountPerUse=1 的确定配置。多颗正式接入建议在“全量可放才成功”和“允许部分生成并定义费用／次数”中选择；推荐先全量可放才成功，避免半扣费，但尚未确认。

旧候选 PlacementRules 按“上→右上→右→右下→下→左下→左→左上→向外继续”的顺时针螺旋查找，跳过越界、未开放、仍受地格锁限制和已占格；不能用普通移动权限判断浅锁产物能否被创建。同一求解的已分配落点也要视为占用。

R 图的首圈编号 1–8 明确，外圈未标全；图中 9 在 (-2, 0)，以棋盘内部格为起点时，L 在首圈后先检查 (-2, -1)（行向下、列向右），不能宣称两者完全一致。外圈及边角的证据差异保留在 C18。原候选普通放置从上方开始、不检查原点，被动只搜索八邻；L 的 FindOneRoundGrid 实际按行扫描。采用哪个空间策略由项目定义，Q04／Q07 不再要求本轮裁定具体算法。

## 时间推进与离线

### 命令时间戳契约（D56 已确认）

用户于 2026-10-03 确认：**命令携带时间戳，具体逻辑不自行获取；重播通过命令中记录的时间戳驱动同一套逻辑。** D55 的边界继续有效：Command 不修改游戏真实时间源，不新增 CurrentTick 存档或推进全局时钟的 Operation。

| 环节 | 实施约定 |
| --- | --- |
| 正常输入 | 宿主输入边界取得本次时间戳并写入命令；具体服务和采样入口由 Host 接入落实 |
| 命令载荷 | 所有涉及时间判断或写入的命令携带时间戳，包括周期检查、生成、气泡点击／关闭及需要时间校验的外部结果；不涉及时间的命令无需强加字段 |
| Consumer 与规则 | 同一命令的 Consumer、Function／Effect 共用该值，通过参数传递；不在方法内部重新读取 TimerProxy／UtilsTime、DateTime.Now 或 Unity 当前时间 |
| Operation.Apply | 使用本次求解保留的时间值及结果写入业务记录，不因稍后 Apply 而重新取现在；新截止时间由本次命令时间戳和规则时长计算 |
| 命令记录与重播 | 保存原命令的时间戳；重建命令时原样恢复，播放速度与重播当天时间不改变该命令的时间条件 |
| 表现与存档 | 倒计时展示不修改逻辑时间源；Profile 只保存所属机制必要的开始／截止时间等数据，命令历史按需另存，Operation／Batch 不存档 |

示意命令用名 `CommandTimePulse(NowSeconds)`，表示“用这个时间戳检查一次”；具体类型／字段名按工程风格落实。核心链路：

```text
正常运行：宿主取时间戳 T → Command(T)
重播：   从记录恢复 T    → Command(T)
                              ↓
             Consumer → Function／Effect 判断(T)
                              ↓
                    Operation.Apply → Graphic
```

普通冷却按 `now >= ReadyAt` 查询；生成成功可设置 `ReadyAt = commandTime + cooldown`。气泡按 `now >= ExpiresAt` 再结合交互保护判断，剩余值先比较再相减，避免无符号下溢。只选择一种权威计时表示，也可保存上次生成时间并加配置 CD；示意字段不代表生成 Profile 已提供这些成员。

每秒触发检查与真实时间戳流逝分开。漏过几次定时回调不会延长期限，下一次命令携带重新观察到的时间戳即可；相同时间戳的检查通过当前对象与期限判断幂等处理。普通冷却不逐秒保存剩余秒数，没有业务变化不写 Profile。

本契约明确时间维度的可重演性；完整 Replay／Redo／Undo 仍需初始数据、随机、目标身份和规则顺序等配合，见 [02b](02b_Command与Operation执行方案.md#7-保存command-历史与-replayredoundo)。定时检查与无到期时的表现刷新按 D57 见下文；具体时间服务和采样入口由宿主接入落实。Tile／Element 的共享持久身份见 [03](03_状态模型与Profile.md#tileelement-持久身份与分配d65d68d69)，跨重启支付接线见下文[支付保护](#支付等待与到期保护d60)。

### 定时检查与倒计时刷新（D57 已确认）

采用 `OperationRefreshTimeDisplay(T)`：Apply 不修改业务数据，Graphic 刷新倒计时；没有 View 时不产生业务影响。Operation 可以只有表现职责，不必为每次执行制造存档变化。保持 HomeHub 原有多 Consumer → 同一 Batch → 全部 Apply → Graphic 的执行方式。

```text
统一驱动器取得 T → CommandTimePulse(T)
  ├─ 公共时间 Consumer → OperationRefreshTimeDisplay(T)（每次一条）
  ├─ Function Consumer → 有实际到期业务才登记相应 Operation
  └─ Effect Consumer   → 如气泡可到期销毁，登记 OperationExpireBubble
                  ↓ 全部收集完成
            OperationBatch：依序 Apply
                  ↓ 所有 Apply 成功
            Graphic：退场、倒计时显示等
```

实施约定：

1. 运行实例拥有一个驱动器，正常运行约每秒提交一次命令；漏帧后用新时间戳检查，不靠补发 N 次命令计算经过时间。重播停实时驱动，使用记录的同类命令。
2. 公共时间 Consumer 由模块装配一次，每次构造并登记一条刷新 Operation。D61 限定 Operation 只能由 Command Consumer 产生；驱动器只发送 Command，Graphic 只消费结果；Function／Effect 在其 Command Consumer 身份下才产生执行操作。需要主动到期的 Function／Effect 在关联完成后注册，退役即注销，最终 Release 可幂等清理。普通冷却仅需 `GetRemaining(T)`／`CanGenerate(T)` 查询时，不增加专属定时 Consumer。
3. 收集期只读、只登记。正常检查未到期或受保护时，不登记业务 Operation，Consumer 表示已处理而非业务错误；公共刷新保证 Batch 非空，保留原 Runtime 的空 Batch 语义。注册表不在收集遍历途中增删。
4. 业务 Operation 在首次写入前核对当前实例、期限与保护事实，使用同一 T，不重新读取时钟。多个 Consumer 的空间／同对象冲突沿 02b 的业务准备与依赖规则组织；不假定其它 Consumer 已经 Apply。
5. 刷新 Operation 只携带 T。它的 Graphic Consumer 读取当前仍有效的 View／窗口绑定，以 T 查询剩余时间；剩余时间安全计算为 `T >= end ? 0 : end - T`。本批已移除的实体／气泡不再参与正常倒计时刷新，旧 View 只完成退场。
6. 因为全部 Apply 先于任何 Graphic，刷新 Operation 在 Batch 中的位置不影响其读取最终逻辑数据，不需要新增 Consumer 优先级或强行放到列表末尾。显示需要动画时可使用表现时间，但不由动画／显示秒数决定业务到期。
7. 无 View 时保留业务到期检查，公共 Graphic 刷新正常空处理；无业务变化不写 Profile。整体 Release 停驱动与注册，不发送“最后一次 Tick”来结算。

具体类名与时间服务在宿主实现时确定。以上流程复用已确认执行契约；实现顺序及验证统一见 08。

### 时间数据与启动接线

以下为 D56–D63 的工程实施约定，不新增玩法规则：

- 本文代码示例统一使用 `ulong NowSeconds`／`ExpiresAtSeconds`／`ReadyAtSeconds`。宿主三合 TimerProxy 已有 ulong 秒和毫秒接口；二合由 Host 在命令输入边界采样并统一成秒，Function／Effect 不持有 TimerProxy 或 UtilsTime。时长配置也在进入规则前转换为同一单位；表示无期限使用可空字段或生成工具支持的明确存在标记，不能拿数值 0 同时表示无期限和已到期。
- 驱动频率与业务时钟分开：Host 的 Update／计时服务约每秒触发一次采样，命令携带该次实际时间戳；不把累计 deltaTime 当存档时间，不为漏掉的每秒补发一条命令。命令和 Operation 中的时间值在创建后不改变。
- 冷启动／重新进入：按 03 初始化或恢复 Profile → 先 Tile 后 Element，绑定 Function／Effect 及 WaitPay／支付关联 → 建立占位和派生锁 → 注册业务 Consumer、公共时间 Consumer 与 Graphic Consumer → 完成需要的 View／窗口服务绑定 → 提交一次当前时间的 CommandTimePulse → 该次执行完成后开放玩家输入并启用周期驱动。启动检查不等待外部支付结果；尚在等待的记录靠 WaitPay 保留。
- 临时后台恢复：保留原实例和有效交互，暂不开放玩家输入；在宿主恢复入口采样并完成一次同类时间检查，再恢复输入／周期驱动。不恢复已经 Release 的旧实例、不制造离线期间的逐秒命令，也不把返回前台当作气泡关窗。
- 首次／恢复检查在无正在执行的 Command 的宿主边界提交；若恢复通知在当前调用链中到达，延后到该调用结束再做检查。不能在 Consumer 内重入提交后立即开放输入；Submit 的排队成功并不表示检查已完成。沿用原 FIFO，不扩展 CommandRuntime 的返回类型。

核心验证用可控的时间输入；真实服务的类名、注册入口和时间校准沿宿主实现接入。完整回放另按 02b：这里只保证同一组命令时间产生相同的时间判断，不能据此声称随机、身份和全部历史功能已实现。

### 调度与恢复的接续边界

时间检查与玩家输入沿 FIFO；时间敏感的玩家命令也携带本次时间戳，不能只记录定时检查而让其它命令在重播时重新读取现在。恢复使用当前时间戳检查原期限，具体离线产出由项目规则决定。

不能在 Consumer 中重入 Submit(TimePulse) 后假定到期业务已处理，因为 FIFO 会把它排到当前命令之后。动作自己使用本次时间戳校验；若需先处理到期再继续动作，须完整准备相关结果，不能假定原 Runtime 会自动停队。实际写入仍经 Operation.Apply，不增加插队口。

三合 TimerProxy／UtilsTime 的源码事实见 [00](00_参考资料与证据.md#时间窗口与表现释放核对2026-10-02)。二合具体时间源与采样入口由宿主实现落实，多 Consumer 接线按上文 D57；业务读取输入值，不自行沿实时服务读取现在。停止检查不等于暂停真实时间；不使用 UniTask.Delay／WaitUntil 轮询规则。

离线恢复建议只处理由已保存期限证明成立的冷却／到期变化；下一轮若需实际产出才开始，不按离线时长无限补轮。被动生成是否补产由项目确定，旧候选为首期不补产，重新进入按当前空间处理；该建议尚未确认，也不作为核心架构的必答题。

外部时间戳的校准与回拨沿选定宿主时间源处理，安全计算剩余时间，不撤销已完成业务。历史回退恢复对象数据，并在重演中使用记录的时间参数，不修改全局时钟。线上专用撤销仍使用当前时间戳，冷却恢复细则归第 9 项。

## 被动生成示例

触发入口为进入棋盘、移动后、相关空格出现、冷却恢复。Logic 统一收集有资格的候选，按 R 指定的配置 ID 大者优先；比较旧数值 ID 的数值大小，不按字符串字典序。导入时可映射为明确优先级；同 ID 的冲突使用逻辑随机裁定。

R 的 0.1 秒可能表达业务产出间隔，也可能主要是演出节奏；具体项目需定义其含义，本轮只讨论两者的接口边界。若为业务间隔，使用明确的下一次可生产时间，每次时间命令产一颗并重新校验；若只是表现间隔，可先一次确定全部允许产物，再在 Graphic 中错峰。两种结果不能未经讨论混用，且都不允许 Tween 完成驱动规则。

八邻找不到空位时等待新的状态变化，不递归空转。不搬用每个 AutoGeneratorFunction 各自递归 0.1 秒回调的方式。

## 气泡 Effect 与生命周期

### 已确认的对象与规则（D31–D42）

- 气泡是已存在 `EntityElement` 上的 `EffectBubble`，没有第二个包装 Entity 或隐藏内容物。解除只移除本次气泡，保留元素身份、配置、位置、Function 及其数据；其它 Effect 继续生效，不直接设置任何 CanXXX 标记。
- 元素原外观始终可见，气泡覆盖由 `EffectViewBubble` 显示；解除同步移除该效果表现。表现接入见 [06](06_表现与资源.md#气泡覆盖与解锁弹窗)。
- 允许点击选中、拖动；气泡位于源或目标均可触发移动／占位腾位，双方气泡同样处理，目标 Tile 必须完全解锁。合成、生成、自动生成、收集等其它功能禁用。完整动作与方法轮廓见 [04](04_棋盘交互与合成.md#气泡操作与就近腾位)。
- 期限可配置；解锁条件与到期结束行为由具体逻辑实现，支持广告、支付、等级等条件。带期限且到期销毁是用户给出的变体；不要求所有变体到期都销毁，也不沿用旧 R 的默认替换。
- 同一时刻最多一层气泡，重复附加拒绝，不能叠加或刷新。一次解锁不再自动揭出另一层气泡。用户进一步确认：解除后允许由后续业务再次添加；因此不增加“此元素曾经有过气泡”的永久标记。不同气泡实现也属于同一互斥类别，不能各加一层。再次添加是一轮新的附着，有新的 RuntimeId 和本次期限。
- 到期前点击并打开解锁弹窗，弹窗显示剩余时间；弹窗未关闭时，到 0 不能因气泡到期而销毁该元素，仍可通过条件解锁。这里暂缓的是到期处理，**期限和倒计时不暂停、不延长**。保护仅针对本次气泡到期，不授予元素抵抗其它合法系统移除的能力。
- D36：当前到期销毁的气泡，计时到 0 后主动关闭解锁弹窗且无其它到期保护，**逻辑层立即销毁元素、释放占位，表现层播放消失动画**；不等动画完成后才删除。无期限的气泡不触发到期销毁；未来不同结束行为仍由具体变体实现。
- D37／D39／D40：直接响应输入层的 Click，拖拽不触发 Click；二级锁 Effect 先于气泡，Tile 完全解锁后才可打开并解除气泡；窗口同步打开，不增加异步开窗流程。
- D41／D42：普通目标合成仍可解二级锁，但气泡不参与合成。若配置二级锁与气泡并存，项目须提供其它先解格锁的方式；未提供时配置避免该组合。接入与组合校验见 [04](04_棋盘交互与合成.md#独立解锁方式与配置约束d42)，不作为气泡框架继续待讨论的前提。

### 数据与变体复用（实现建议）

共用 `EffectBubble` 实现操作限制、点击／腾位响应和本次生命周期。具体变体只覆写解锁条件校验、解锁准备与到期结果准备；少量普通方法即可，不新增条件表达式框架、Effect 内部 FunctionController 或全局 BubbleSystem。条件相同、只有时长或美术不同的气泡共用逻辑类与不同配置；条件／结算真正不同的变体再使用具体子类，共用 EffectViewBubble。

| 内容 | 所属位置 | 保存与变化 |
| --- | --- | --- |
| 气泡种类／定义键、期限时长、表现键 | 只读定义 | 定义键用于恢复具体实现；时长不等于已经开始的截止时间 |
| 可选 `ExpiresAt`、该变体确实需要的解锁进度 | EffectBubble 自有数据 | 随 Element 保存；无期限明确为空，新建计算一次，恢复不重算 |
| `WaitPay` | 建议放在 EffectBubble 所属持久子记录，由该 Effect 管理 | D60：开始支付置 true；支付成功／失败置 false；恢复原值；此字段为本轮新增设计要求，尚未生成代码 |
| `RuntimeId` | 本次 Effect 附着 | 运行期唯一；移动保留，移除后再加使用新键 |
| 可选 `ActiveDialogId` | EffectBubble 的运行数据（工程轮廓） | 只表示本次真正成功打开且已登记有效的弹窗交互，不保存；不以 SelectedElementId、GameObject.active 或窗口引用代替，不表达加载进度 |
| 生成次数、冷却等原有能力数据 | 原 Function | 保留原归属，气泡不能把它们搬进自己或重建 Function |

显示剩余时间为 `max(0, ExpiresAt - now)`；业务以统一输入的 now 判断。`ActiveDialogId` 是具体交互事实，不是可随意赋值的综合权限字段，也不需要独立 State 层。只在业务入口内部变更。

气泡期间自动生成入口同样查询 Effect，不能只禁 UI 按钮。已经排队、尚未执行的生成也须重验；被阻止时不扣费用、不消耗次数、不产生物品。时间是否推进某个 Function 的内部冷却仍遵守该 Function 自己的算法；本轮不额外定义冻结剩余冷却或解除后补发漏掉产物。不会因“禁止产出”自动清零次数、改写期限或建立补产队列。

### 同步弹窗与执行流程

**D37／D40：输入系统直接提供 Click，拖拽不产生 Click；窗口同步打开。** 不为气泡另写手势识别、异步开窗任务、Loading 阶段或开窗完成回执。以下为已确认规则的工程轮廓，Command／Operation 载体按 02b 第 5 节实现，实际窗口服务按下文 D62 的保护写入边界接入；广告／支付结果可能异步返回，不能与窗口自身的同步打开混同。

1. **Click 与资格检查**：按 [10 的交互响应](10_Function与Effect建模讨论.md#effect-响应点击与拖放实现轮廓)处理已产生的 Click。校验 Host 会话、Element.InstanceId、Effect.RuntimeId、当前 Tile 与所有相关限制；D39 要求 Tile 已完全解锁。二级锁时只保留选择／果冻反馈，不打开气泡解锁窗口。首次打开带期限气泡，通常须在命令时间尚未到期；WaitPay=true 且重启无旧窗口时的查询／恢复支付入口由支付接入落实，不直接套用无保护到期删除分支。
2. **同步打开并登记保护（D62）**：同步打开成功、窗口绑定 EntityElement 后，由窗口提交 CommandBeginBubbleInteraction，携带当前会话、元素／气泡运行身份、窗口交互键与时间戳。Command Consumer 校验后创建 OperationBeginBubbleInteraction，在 Apply 写 ActiveDialogId。窗口负责发起保护的建立与结束，实际逻辑修改仍经过 Command→Consumer→Operation。失败视为未打开，不提交成功命令、不提供保护、不增加失败补偿。重复 Click 聚焦匹配的有效窗口，不刷新期限；窗口仍为同步 API。
3. **到期检查**：已到期、没有有效交互且 WaitPay=false，才准备具体变体的到期结果；有效交互或 WaitPay 任一保护存在则保持气泡与元素。到期后不反复注册同一个已经过去的期限；交互结束时重新检查即可。仅选中、拖动或播放动画均不能自动获得这项保护。
4. **条件解锁**：请求带会话、元素、效果和交互键，以及必要条件结果。完成广告／支付后重新核对当前事实与完全解锁条件；有效窗口仍在时，即使计时为 0，也允许继续按条件解锁，不能统一用 `now < ExpiresAt` 拒绝。条件通过后，只移除匹配 RuntimeId 的气泡并结束本次交互；功能权限由剩余 Effect 重新查询。
5. **主动关闭**：清除匹配的交互键；若已到期且没有 WaitPay 等仍有效保护，按 D36 同一业务入口立即销毁元素并释放占位，随后播放消失表现；未到期继续原期限。销毁前取得必要显示副本，旧 View 可以退场，但不再参与查询、碰撞命中和占位。晚到的旧窗口关闭不能结束新窗口／新气泡；晚到动画也不能删除同格新物品。
6. **其它原因移除元素**：使本次交互失效，关闭对应窗口，清理 Effect；没有“气泡解除后再造一个元素”的补偿。Release／EffectView.Unbind 只做清理，不再次扣费、销毁或发奖励。

若 Click 进入逻辑处理时已经到期且没有有效交互、WaitPay=false，先按到期规则处理，不建立新的保护；不增加 UI 时间戳回溯和超时宽限。ActiveDialogId 仍用于区分已打开窗口及其条件回调，不是异步开窗票据，也不进入存档。

### 窗口保护的写入边界（D62）

```text
Click Command → Click Consumer 创建开窗 Operation
              → Apply 完成本次逻辑准备
              → Graphic 同步打开窗口，绑定 EntityElement
              → 窗口提交 CommandBeginBubbleInteraction
              → Command Consumer 创建 OperationBeginBubbleInteraction
              → Apply 记录有效窗口保护

玩家关闭窗口 → 窗口提交 CommandEndBubbleInteraction
             → Command Consumer 创建 OperationEndBubbleInteraction
             → Apply 取消匹配保护并检查到期
```

窗口持有 EntityElement 用于显示和提取目标身份，不能凭某个坐标查另一件元素后写保护；命令携带匹配身份，不把 UI 对象作为业务条件。运行保护由 EffectBubble 的内部方法维护，不导出可任意赋值的综合 CanExpire 字段。成功开窗输入可被记录；重播输入该事实，不重新打开真实支付窗口或读取 Unity 可见性。

D43 的重入 Submit 仍只表示排队：窗口的“打开成功”不代表 Begin Operation 已 Apply。通常当前调用链排空后即完成保护；排队期间不受理解锁／支付等依赖保护的操作，也不把 UI 的可见性作为另一份保护源。若已有排队命令先移除目标，Begin Consumer 拒绝旧目标并让这份失效显示收尾，不复活元素、不影响新泡；沿既有运行绑定失效清理，不增加开窗重试或优先队列。重复成功／关闭请求只匹配本次交互，不清其它窗口。具体控件接入不改变这条调用顺序。

D58 的整体 Release 是资源清理，窗口销毁时解除引用／订阅，不再提交普通关窗业务；重启不恢复 ActiveDialogId。

### 窗口与支付命令的实现清单

Command 名为职责用名；每一行由对应 Command Consumer 创建 Operation，准备阶段只读，业务写入在 Apply。实现沿用 02b 的注册及失败协议，不把此表包装成新的通用消息框架。

| 输入 | 必须携带的业务数据 | Consumer／Operation 完成什么 |
| --- | --- | --- |
| CommandTimePulse | 本次 NowSeconds | 公共 Consumer 总是创建一条 OperationRefreshTimeDisplay；能力 Consumer 仅为实际到期准备业务操作 |
| Click 的开窗结果 | 会话、元素 InstanceId、Effect.RuntimeId、本次时间；显示所需数据 | 先按 Click 时间校验，Graphic 同步开窗；失败无成功输入、无保护 |
| CommandBeginBubbleInteraction | 同一会话和元素／Effect 身份、成功窗口的交互键、该输入时间 | 核对仍属于当前目标；OperationBeginBubbleInteraction 写运行保护。同一键重复输入不重复建立；其它键不能直接覆盖仍有效交互 |
| CommandEndBubbleInteraction | 相同目标、交互键、本次时间 | OperationEndBubbleInteraction 只清匹配交互；根据清除后的保护事实与原期限，在同一业务步骤完成必要的到期删除 |
| CommandStartBubblePay | 当前目标／交互、Element.UniqueId、本次支付请求标识、方案所需条件和时间 | 校验完全解锁及条件，且没有正在等待的支付；OperationStartBubblePay 同时写当前请求标识和 WaitPay=true，完成后才交给宿主发起该次支付 |
| CommandBubblePayResult | Element.UniqueId、本次支付请求标识、宿主确认的成功／失败结果、命令时间 | 持久定位当前元素及气泡；匹配当前等待请求。成功 Operation 同次清等待并解泡；失败 Operation 清等待、保留仍有效窗口，并检查无保护到期。不要求旧窗口或旧运行身份存在 |

窗口是否可见不参与逻辑权限查询。窗口按钮只在匹配的 Begin 已生效后允许提交解锁／支付；可以查询已登记交互键，不需要给所有命令新增异步完成协议。普通 Close 即使紧接同步打开，也按 Begin→End 的提交顺序排队；整体 Release 清理则直接解绑，按 06 处理。

Begin 消费的是成功开窗这一输入事实，不能再次打开窗口，也不从 UI 引用反向判断规则。执行时目标已失效则拒绝；旧显示由运行绑定清理。End 的交互键不匹配时不能清新窗口。支付结果先匹配持久关联，再由当前实例的 Consumer 准备结果；Operation 写入前仍核对相同请求未被消费。WaitPay=false、当前请求不匹配或效果已解除的重复结果不再改写气泡；宿主的外部凭据确认与补单仍走已有入口。

### 支付等待与到期保护（D60）

用户确认新增持久 `WaitPay`：开始支付为 true；为 true 时到期不销毁，重启仍保留；成功回调清 false 并移除本次气泡，失败回调清 false。广告／支付页面已阻止普通关闭，不额外设计核心关闭拦截。广告观看不自动等同支付，不据此给所有广告设置持久 WaitPay。

建议该字段由 EffectBubble 持有，放在 Element 的气泡子记录中。它表示“等待本次支付结果”这一事实，可以是 bool；它不是可被多个模块任意覆盖的综合 CanExpire。到期资格仍由方法计算：

```csharp
bool CanExpire(ulong now)
{
    if (!HasDeadline || now < ExpiresAt) return false;
    if (WaitPay) return false;
    if (HasActiveDialog) return false;
    return true;
}
```

**D63 已确认两种保护独立组合：** WaitPay=false 只解除支付保护；只要窗口未关闭，其原有保护继续有效。支付失败不能清 ActiveDialogId，也不能只因失败时已到期就销毁窗口中的元素。 到期资格只针对气泡到期机制，不扩成禁止一切系统删除的通用无敌标志。

| 输入 | Operation 的职责 | 后续 |
| --- | --- | --- |
| 开始支付 | 校验本次气泡／条件与尚未等待支付，写 WaitPay=true | 写入后才调用宿主支付入口；UI 不直接写 Profile。命令重入时须等真实 Apply，不能把 Submit=true 当作已经写入 |
| 支付成功 | 匹配本次支付，清 WaitPay=false 并在同一业务操作中解除该气泡 | 保留 Element／其它 Effect，清匹配运行交互；不能先清保护后等待另一条解泡命令，被中途到期删除 |
| 支付失败／宿主明确取消 | 匹配本次支付，清 WaitPay=false，保留气泡和原期限 | 重新判断其余保护；已到期且无保护时可在同一失败结果业务入口准备销毁，无需等动画。仍有有效窗口时按 D63 保留元素；之后普通关窗再按期限判断。 |
| 重复／迟到结果 | 校验当前气泡及本次支付归属，已处理的结果不重复消费 | 不影响同元素后来新增的气泡，也不影响另一次支付 |
| 整体 Release／重建 | 仅解除运行引用；不清 WaitPay、不改期限 | 恢复子记录原值，无窗口也能因 WaitPay=true 保留元素 |

建议沿用 `CommandStartBubblePay → OperationStartBubblePay`、`CommandBubblePayResult → 对应结果 Operation` 的最小链路；名称可按宿主调整。外部回调是 Command 输入，所需时间由命令携带。成功判定由宿主提供真实结果，不能由展示窗口关闭推断；重播使用记录结果，不重新调用支付。

**跨重启必须能认出是哪一次支付。** WaitPay 只说明正在等待，不能定位外部结果；窗口交互键、运行 InstanceId 以及位置也不能单独承担跨重启关联。当前三合已有持久 KeyProfileInstanceID 与支付 userData 关联的参考，但本轮没有据此认定其完整补单／失败恢复协议都适用于二合。D65／D68 已确认所有 Element 的持久 UniqueId，新建记录通过 checked(++profile.LastElementUniqueId) 分配，恢复保留；字段已生成，契约见 [03](03_状态模型与Profile.md#tileelement-持久身份与分配d65d68d69)。用户基本同意支付同时关联元素身份与当前支付请求，D67 按此落实；宿主具体请求字段与补单入口在接入时核对。只有 WaitPay 而没有恢复支付结果的入口，会留下无法自动解除的等待。

支付载荷中的 UniqueId 必须大于 0；缺失、0 或负数均不作为有效目标 ID。正数 ID 仍需通过 TryGet 等查询确认目标存在，不能仅凭数值有效就认定物品仍在。

**支付目标与本次请求（D67）：** 支付 userData 携带 Element.UniqueId；气泡持久数据保存当前等待的支付请求标识，与 WaitPay 同次写入。优先复用宿主能在发起／恢复时关联的请求键，具体字段类型按实际接口确定，不假设商店交易号在发起前已经存在。回调先通过 UniqueId 找到物品，再匹配当前请求，才允许 Consumer 创建 Operation 修改本次气泡。

例如元素 42 的 P1 已解泡，后来同一元素重新加泡并发起 P2；P1 的迟到成功不能解除新泡，P1 的失败不能清 P2 的 WaitPay。元素 ID 不随支付变化，运行 Effect.RuntimeId 不承担跨重启匹配。没有目标／请求不匹配走宿主已有结果处理，不按坐标寻找替代物，不重新创建被删除元素。

具体接入步骤：写本次关联与 WaitPay → 按宿主保存规则处理关键记录 → 发起外部支付 → 接收包含相同关联的结果 → CommandConsumer 产生成功／失败 Operation。宿主对同一结果的去重与补单能力复用原实现；当前请求的消费与本地业务结果同步维护，不能只因窗口销毁就丢掉已支付结果。长整型载荷需验证宿主往返不丢精度，SDK 若只可靠支持字符串则使用十进制字符串表达同一 ID，不改变分配规则。

恢复时先绑定带 WaitPay 的原气泡记录，再启用时间 Consumer；Pending 支付未得到最终结果时保留 true，不因无窗口、无即时回调或期限已过而擅自清零。结果属于持久业务输入，运行实例已释放时由宿主保留并在可处理的实例中交付，不能只绑定旧 UI 委托后丢弃。目标映射与重复结果处理是支付接入范围，不新增一套通用事务框架。

Element.UniqueId 与根计数器已核对生成；WaitPay、气泡记录和当前支付请求字段仍属于待扩展的生成定义。写入 setter 仅标脏，真实落盘沿 03 的宿主链；支付发起前的保存请求与完成条件须对照宿主支付实现落实，不能仅因内存已设 true 就声称任意强退都已耐久保存，也不另造二合保存机制。

### 最小业务方法轮廓

以下方法可分布在 EffectBubble 与既有业务入口，无需新增窗口逻辑管理器。Can／TryPrepare 只读，执行入口重新核对再写入；返回 bool，不新增通用拒绝枚举。

| 方法 | 必要输入／输出 | 责任 |
| --- | --- | --- |
| CanOpenBubbleDialog | 元素、气泡 RuntimeId、now | 检查真实占位、Tile 完全解锁、效果存在／期限及其它限制；不检查玩家必须已经付得起费用 |
| BeginBubbleInteraction | 本次仍有效的元素／气泡身份与已确认开窗成功事实 | 内部记录有效交互键；不能因仅发出开窗请求就保护，由窗口发起 Command，Consumer 产生 Operation 写入，见 D62 |
| CanUnlockBubble／TryPrepareUnlock | 同一身份、交互键、条件凭据、now；bool 与具体费用等数据 | 重验当前 Tile 与效果、条件、保护中的过期处理；仅求解本次解除所需数据 |
| ApplyPreparedUnlock | 紧接本次准备的解除数据 | 完整执行必要扣费／条件消费，移除这一份气泡并结束交互；不重建 Owner |
| EndBubbleInteraction | 身份与匹配交互键、now | 普通关窗清理交互事实；已到期且 WaitPay=false 时同步销毁，再交付表现；整体 Release 不走此入口 |
| TryPrepareExpire | Effect 期限、now、当前交互事实、WaitPay | 到期且无窗口保护、WaitPay=false 才准备结束结果；不凭 View 是否可见判断 |

直接发起 Unlock 请求同样经过完全解锁检查，不能只靠隐藏按钮维护顺序。EffectTileLock 优先于 EffectBubble 的规则不自动暂停气泡期限或自动驱散气泡，其组合边界见 04。

### 解锁、到期和异步回调只处理一次

所有会写数据的入口在逻辑执行阶段顺序处理，并检查同一组身份：`Host 会话 + Element.InstanceId + Effect.RuntimeId`；弹窗请求再检查 ActiveDialogId；跨重启支付结果走持久支付关联，不要求旧窗口仍在。不能凭位置查“这个格子现在的元素”完成旧请求。

- 解锁先完成：气泡已不存在，旧到期／关闭／重复成功回调失效，不会销毁已解锁元素。
- 有有效交互或 WaitPay 时到期先到：到期不删除；匹配的成功结果仍作用于原元素与本次气泡。
- 无保护交互的到期已经完成：迟到的本次解锁结果不能复活原元素，也不能影响同格新元素或后来新加的气泡。
- 普通资源支付的校验、扣费、移除效果应作为完整业务一起准备和执行；不能先移除后发现余额不足。基础失败协议及 D45 的业务组合均按 02b，不宣称 Apply 自动回滚。
- 外部广告／支付结果只提供条件凭据，UI 不直接改集合。远端已成功支付但本地会话已结束，不能仅凭本地 RuntimeId 保证经济结算；正式接入须使用宿主的订单／凭据去重与恢复入口，不能再次扣费或静默丢弃已支付结果。

D58 已确认广告覆盖／临时后台保留仍有效交互，返回检查时间再开放操作；整体关闭二合直接由总管理器 Release 逐级释放，不额外提交关窗 Command，不结算到期，不删除气泡存档，不清 WaitPay。重开只恢复存档，不恢复窗口与运行交互。D60 下广告／支付等待期间的页面已阻止普通关闭，核心不再增加另一套关闭拦截。普通玩家关窗继续按 D36 执行业务；整体 Release 的 UI 清理不得误触发该业务，具体顺序见 06。

旧 R 的“选中即保护、到期替换指定物品”仅保留为来源事实，新方案采用上述弹窗保护与具体变体的结束逻辑，不将二者混用。时间接口见 [09](09_决策与接续记录.md) 的 Q10；实现与验证安排见 [08](08_实现顺序与验证.md)。
