## 三、追加提问：Function、Effect 与 State

我跟同事聊了他之前做三消游戏时的设计：冰冻、箱子、炸弹等很多种机关，是按“效果”设计的。

而我们上面这几套参考设计使用的是“状态结合 Function”。对于 Entity，我也想尝试引入“效果”。

请围绕以下问题分析、讨论：

### 问题 1：Function 与效果如何区分、兼容？

一个 Function 本身也是一种能力，而效果也是一种能力。

那么 Function 和效果如何区分？或者说，Function 和效果是否能够很好地兼容？

### 问题 2：效果能否替代状态？与 RPG 等游戏中的状态、Buff 有什么关系？

对于上面几个参考实现中的“状态”，如果删除这个概念，比如地块不能使用时，可以改成给地块加一个“锁”的效果，由这个效果令它无法进行操作、合成等。

这样的设计是否合适？这里的效果，是否类似 MMO／RPG／MOBA 中的状态、Buff 等？

这里是在提出一种待讨论的建模思路，尚未决定删除所有状态，也尚未确定 Function 与 Effect 的最终关系。

### 问题 3：公开的二合／三合设计有哪些可借鉴的思路？

请结合博客分享、开源代码，检索市面上常见的二合／三合玩法设计思路，并结合上面的参考实现与问题进行分析。
