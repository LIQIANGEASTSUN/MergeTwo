# 需求范围与历史实现差异

先建立产品规则基线，再决定如何实现。R 指原始 Word 需求，L 指旧二合源码，路径入口见 [00](00_参考资料与证据.md)。**R 描述设计意图，L 描述这份客户端实际写了什么，本文建议描述新实现的候选行为。三者不混同。**

## 范围与阶段

D01–D04 的已确认范围见 [09](09_决策与接续记录.md)。M0 准备、M1 最小闭环、M2 核心规则、M3 库存道具、M4 产品接入的唯一阶段表在 [08](08_实现顺序与验证.md)。下表负责需求追踪，不重复维护实施步骤；阶段均为建议。

## 必须裁定或纠正的差异

| 编号 | 需求与历史证据 | 本次建议／待决定 |
| --- | --- | --- |
| C01 锁编号 | R 的 1 级为深锁、2 级为浅锁；L 的 GridState 是 0 解锁、1 浅锁、2 深锁 | 文档和业务代码用语义枚举；只在旧配置导入器保留 0／1／2 映射 |
| C02 ID 规则 | R 的 2+2+2+2 位分段与“前 5 位是链”不一致；L 使用 groupId，且 ID 长度并不统一 | ID 为不透明配置键，以 nextId、groupId、level 为准，不从字符串截断推规则 |
| C03 多颗产出 | R 明确“次数 × 颗数”；L GenerateItem 把 generateNum 固定为 1 | M1 可明确只选单颗配置；完整支持前确定只有部分空格时全拒绝还是部分生成／如何收费 |
| C04 固定产出 | R 明确固定段每实例一份；文末循环表述位于“产出物品配置”，未明确指同一个 fixedOutput 字段，不能直接认定需求自相矛盾。L 用本轮 curCount+1 索引 fixedOutput，轮次重置后可能重复固定段 | 区分“每实例固定前缀”与“普通产出顺序循环”两种语义；推荐前者按 R 实现，扣费／次数／继承仍需定。需要独立游标，不照抄 curCount |
| C05 初始冷却 | L CreateItemData 将 historyCount／end 初始化为 0；OnGenerate 的非末轮分支 now>=end 会先递增轮次 | 新建与冷却到期用显式状态区分；这条本地构造路径有跳首轮风险，不据此断言服务端存档都触发 |
| C06 锁定产出 | R 要浅锁掉落和可用格阈值，阈值句子“非锁定（包含1级和2级）”本身含混；L 有 coverPro 字段，但主生成路径没执行 | 决定阈值统计解锁格总数还是空格数；仅锁新物品，是否同时锁格必须明确 |
| C07 概率单位 | R 用 1–100，Excel clonPro／coverPro 用万分比；L 克隆抽样 0..10000 且含端点 | 导入显式转换为统一单位；0 必不触发、最大值必触发，不沿用端点偏差 |
| C08 衍生 | L CheckDerivant 累加后清零总权重、命中后继续覆盖 | 重写有边界测试的权重抽样；非正 ID 的“不产出”含义显式转换 |
| C09 售出 | R 有正价售出和扣回货币撤销；L SelectArticleInfo.SetSaleShow 是空方法，Delete／Undo 路径没有实现该完整结算 | 不能把旧删除撤销当售卖闭环；新方案独立实现价格、余额和撤销校验 |
| C10 生成器保护 | R 保护最后一件最高等级生成器；L ArticleUnlock 仅按 saleRestrictions 与链解锁最高等级控制删除按钮 | 独立 CanRemove 业务规则，UI 和执行共用；“持有范围”是否含仓库需确认 |
| C11 剪刀 | 旧 Docs/01 称“剪刀拆分”；实际 ShearsFunction.DropProcess 调 MergeSuccess，并取目标 nextId 升级 | 这是本次核对发现的文档／代码冲突；以后实现前先确认道具真实用途，不按文件名实现拆分 |
| C12 合成生成器 | L MergeSuccess 创建全新 ItemData，不自动合并两份轮次／冷却／固定进度 | 新生成器重置还是继承尚未决定；必须同时考虑重复领取固定产物的经济影响 |
| C13 产物动画顺序 | R 要合成动画后播放气泡／衍生；L 在主合成动画调用之前已经 CheckClone／CheckDerivant | 新方案先完成逻辑，Graphic 显式安排主合成后出现附加物；不延迟业务提交 |
| C14 自动竞争 | R 大 ID 优先、同 ID 随机；L AutoGeneratorFunction 为各实例递归计时，没有在此函数看到统一竞争仲裁 | 新方案明确稳定候选集与逻辑随机，不能靠哪个回调先来 |
| C15 序列化 | L DataPack 编码用 ItemStatePackage，解码误用 DataPackage；Bubble=3 落到箱子包 | 不复用该协议，新增 Profile 的气泡时间往返测试 |
| C17 倍率 | L 2×／4×是 nextId 提升一／两级并扣倍数费用，仍一颗；条件不足回普通，不自动从4×降2× | 后续把语义写清，不能当作多颗产出字段 |
| C18 外圈落点 | R 示意图首圈编号 1–8 清楚，外圈仅标部分格；L SpiralMatrixIII 首圈后先访问左上外一格，而图中 9 标在正上两格；L 被动 FindOneRoundGrid 又按行扫描八邻 | 首圈可据图定，上述差异不能被“顺时针”一词掩盖；外圈／边角和被动顺序用完整坐标样例裁定，见 Q04／Q07 |

## 可先采用的设计基线

可以先讨论普通物品、单颗手动生成器、无真实商业货币的测试棋盘。它需要真实 Profile 保存，但测试资源／余额属于二合专用存档，是否正式复用宿主货币另行明确。

R 的“先选中，再点击使用／生成”和“点击空白不取消选中”已有明确文字，作为建议基线保留。对 C04、C06、C12 等冲突保留决策点，不通过默选旧代码消除歧义。

差异编号 C16 曾随订单范围移除而退役，保留编号空位以免后续引用错位。
