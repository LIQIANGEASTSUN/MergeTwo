# 需求范围与历史实现差异

先建立产品规则基线，再决定如何实现。R 指原始 Word 需求，L 指旧二合源码，路径入口见 [00](00_参考资料与证据.md)。**R 描述设计意图，L 描述这份客户端实际写了什么，本文建议描述新实现的候选行为。三者不混同。**

## 分阶段范围建议

用户已确认先独立验证棋盘、本地 Profile 和有限撤销。建议将核心棋盘分为两级，以免“先做核心”变成一次性实现全部功能。

| 阶段 | 可操作成果 | 主要范围 |
| --- | --- | --- |
| M0 准备 | 可校验的配置和状态样例 | 选定棋盘／链、定义语义、验证依赖闭包、确定 Profile 接入 |
| M1 最小闭环 | 可以打开、点击生成、拖拽合成、关闭再恢复 | 一张棋盘、普通物品、手动生成器、选中／移动／换位、费用与满盘拒绝、基础冷却、Profile、最小 UGUI |
| M2 完整核心 | 原始核心需求的边界可验证 | 深浅锁、生成器轮次与固定产出、气泡／衍生、使用与变更、售出／删除及撤销、离线时间与取消；被动生成可作为 M2 后半段单独验收 |
| M3 库存与道具扩展 | 可存取物品、领取奖励并使用宝箱 | 仓库、待领取、图鉴、宝箱 |
| M4 产品接入 | 可以作为活动交付 | 活动生命周期、商店、倍率、广告／付费、BP、任务、引导、埋点完整接线 |

M1 不代表“核心需求全部完成”；若某项会显著影响基础模型，设计在 M0 明确，功能可在 M2 开放。当前未确定验收棋盘 ID、最终 UI 载体和全部旧数据兼容范围。

## 原始核心需求追踪

以下仅列本次实现范围内的需求，范围以 09 中的用户决策为准。

| 编号 | R 的规则 | 新方案落点 | 阶段建议 |
| --- | --- | --- | --- |
| R01 | 可视化编辑棋盘和格子属性 | BoardDefinition／配置校验；编辑工具在运行模型稳定后实现 | M0 数据，后续 Editor |
| R02 | 1 级锁隐藏内容，2 级锁可见且可选中 | 命名统一为 DeepLocked／ShallowLocked，避免数字方向混淆 | M2 |
| R03 | 合成目标四邻深锁变浅锁；浅锁目标合成后解锁 | MergeItemsOperation 包含全部相关状态变化 | M2 |
| R04 | 一物一格，规则命中区域等于格子 | 整数 CellCoord，Graphic 做屏幕坐标转换 | M1 |
| R05 | 点击／拖动选择物品；空格和其它 UI 不取消选中 | Selection 属于会影响规则的运行时状态；缩放／框属于 Graphic | M1 |
| R06 | 空格移动、普通不同物品换位、非法目标回原位 | 一个 DropItemCommand 决定唯一分支 | M1 |
| R07 | 相同 ID 且有合并产物才普通合成；结果在目标格并选中 | 配置 nextId；不按 ID 加一 | M1 |
| R08 | 无下一等级不合成并显示链尾标识 | Logic 查询合成能力，Graphic 展示标识 | M1 |
| R09 | 正价售出、零价删除、负一不可删除 | RemovalPolicy 明确区分三者 | M2 |
| R10 | 生成器链售出门槛和最后一件最高等级保护 | 查询当前持有集合，执行时重新校验 | M2 |
| R11 | 售出／删除可恢复原格和完整状态；选中其它物品或原格占用后失效 | 单个 RemovalUndoRecord，专用 RestoreRemovedItemCommand | M2 |
| R12 | 已选中的生成器再次点击产出，消耗货币 | ActivateItemCommand；校验、求解、Apply 与显示分开 | M1 |
| R13 | 生成次数与每次颗数分别配置；空位不足提示 | OutputCount 和 UsesPerRound 分开；部分空位策略待定 | M1 单颗，M2 完整 |
| R14 | 从生成器上方开始顺时针找格 | 统一 PlacementRules，定义边缘和绕圈顺序 | M1 |
| R15 | 非末轮首次产出计时；末轮耗尽后计时；循环序号不按日期重置 | GeneratorState 和时间规则 | M1 基础，M2 全边界 |
| R16 | 固定产出每实例一份，完成前不计算冷却 | 独立 FixedOutputCursor；与文末另一段描述冲突，见 C04 | M2，需裁定 |
| R17 | 剩余冷却除以单位时间向上取整，可付费完成当前轮 | 加速命令，不在按钮回调里改结束时间 | M2 本地验证；付费接入后置 |
| R18 | 概率产出浅锁物品，可用格条件不足禁止生成 | ItemState 与 CellLock 分离；阈值定义见 C06 | M2 |
| R19 | 使用后销毁并获得资源；使用与点击生成互斥 | 配置校验和 UseItemOperation | M2 |
| R20 | 被动生成只到八邻；间隔 0.1 秒；大 ID 优先，同 ID 随机 | 明确逻辑调度，不依赖动画回调 | M2 后半段 |
| R21 | 冷却配置 -1 表示耗尽后消失或变更 | 转为显式 ExhaustionMode 与 ReplacementItemId | M2 |
| R22 | 合成概率出克隆气泡，占格，可付费解锁，到期变指定物品 | BubbleState、ExpireBubbleCommand、UnlockBubbleCommand | M2 |
| R23 | 选中气泡到期不消失，取消选中后处理 | Selection 参与到期规则，隐藏／恢复策略需明定 | M2 |
| R24 | 合成完成后播放气泡与衍生；空位优先级气泡＞衍生＞被动 | Logic 一次求解优先级；Graphic 控制先后播放 | M2 |
| R25 | 配置名称、描述、价值与美术资源 | 规则配置与显示映射分开；价值字段区分用途 | M0–M4 |
| R26 | 物品获取／消耗埋点 | 成功业务结果携带来源与数量；宿主边界上报 | M4，M1 保留本地诊断 |

仓库、BP、活动主城任务的大量细节来自 L，而不是 R 的完整需求。后续可以参考实现，但不能因文件存在就全量纳入首期。

## 必须裁定或纠正的差异

| 编号 | 需求与历史证据 | 本次建议／待决定 |
| --- | --- | --- |
| C01 锁编号 | R 的 1 级为深锁、2 级为浅锁；L 的 GridState 是 0 解锁、1 浅锁、2 深锁 | 文档和业务代码用语义枚举；只在旧配置导入器保留 0／1／2 映射 |
| C02 ID 规则 | R 的 2+2+2+2 位分段与“前 5 位是链”不一致；L 使用 groupId，且 ID 长度并不统一 | ID 为不透明配置键，以 nextId、groupId、level 为准，不从字符串截断推规则 |
| C03 多颗产出 | R 明确“次数 × 颗数”；L GenerateItem 把 generateNum 固定为 1 | M1 可明确只选单颗配置；完整支持前确定只有部分空格时全拒绝还是部分生成／如何收费 |
| C04 固定产出 | R 前段是每实例一次的开头序列且不计冷却；文末有顺序循环表述。L 使用本轮 curCount+1 索引 fixedOutput，轮次重置后可能再次取固定段 | 推荐“每实例一次引导固定段→普通轮次”，待用户确认；需要独立游标，不能照抄 curCount |
| C05 初始冷却 | L CreateItemData 将 historyCount／end 初始化为 0；OnGenerate 的非末轮分支 now>=end 会先递增轮次 | 新建与冷却到期用显式状态区分；这条本地构造路径有跳首轮风险，不据此断言服务端存档都触发 |
| C06 锁定产出 | R 要浅锁掉落和可用格阈值，阈值句子“非锁定（包含1级和2级）”本身含混；L 有 coverPro 字段，但主生成路径没执行 | 决定阈值统计解锁格总数还是空格数；仅锁新物品，是否同时锁格必须明确 |
| C07 概率单位 | R 用 1–100，Excel clonPro／coverPro 用万分比；L 克隆抽样 0..10000 且含端点 | 导入显式转换为统一单位；0 必不触发、最大值必触发，不沿用端点偏差 |
| C08 衍生 | L CheckDerivant 累加后清零总权重、命中后继续覆盖 | 重写有边界测试的权重抽样；非正 ID 的“不产出”含义显式转换 |
| C09 售出 | R 有正价售出和扣回货币撤销；L SelectArticleInfo.SetSaleShow 是空方法，Delete／Undo 路径没有实现该完整结算 | 不能把旧删除撤销当售卖闭环；新方案独立实现价格、余额和撤销校验 |
| C10 生成器保护 | R 保护最后一件最高等级生成器；L ArticleUnlock 仅按 saleRestrictions 与链解锁最高等级控制删除按钮 | 独立 CanRemove 业务规则，UI 和执行共用；“持有范围”是否含仓库需确认 |
| C11 剪刀 | 旧 Docs/01 称“剪刀拆分”；实际 ShearsFunction.DropProcess 调 MergeSuccess，并取目标 nextId 升级 | 这是本次核对发现的文档／代码冲突；以后实现前先确认道具真实用途，不按文件名实现拆分 |
| C12 合成生成器 | L MergeSuccess 创建全新 ItemData，不自动合并两份轮次／冷却／固定进度 | 新生成器重置还是继承尚未决定；必须同时考虑重复领取固定产物的经济影响 |
| C13 产物动画顺序 | R 要合成动画后播放气泡／衍生；L 在主合成动画调用之前已经 CheckClone／CheckDerivant | 新方案先完成逻辑，Graphic 显式安排主合成后出现附加物；不延迟业务提交 |
| C14 自动竞争 | R 大 ID 优先、同 ID 随机；L AutoGeneratorFunction 为各实例递归计时，没有在此函数看到统一竞争仲裁 | 新方案明确稳定候选集与逻辑随机，不能靠哪个回调先来 |
| C15 序列化 | L DataPack 编码用 ItemStatePackage，解码误用 DataPackage；Bubble=3 落到箱子包 | 不复用该协议，新增 Profile 的气泡时间往返测试 |
| C17 倍率 | L 2×／4×是 nextId 提升一／两级并扣倍数费用，仍一颗；条件不足回普通，不自动从4×降2× | 后续把语义写清，不能当作多颗产出字段 |

## 本轮可先采用的设计基线

可以先讨论普通物品、单颗手动生成器、无真实商业货币的测试棋盘。它需要真实 Profile 保存，但测试资源／余额属于二合专用存档，是否正式复用宿主货币另行明确。

R 的“先选中，再点击使用／生成”和“点击空白不取消选中”已有明确文字，作为建议基线保留。对 C04、C06、C12 等冲突保留决策点，不通过默选旧代码消除歧义。

## 实现顺序建议

1. **Step 1：确认 M1 样例。** 选棋盘尺寸、物品链、生成器和测试余额，列出配置引用闭包，确保不存在进入后不可交互的任务区域锁。
2. **Step 2：冻结 M1 规则。** 确认 C01–C03 的最小适用规则以及 C05 初始状态；映射到 04、05 的输入和预期状态。
3. **Step 3：逐项补 M2。** 先裁定 C04／C06／C09／C10／C12，再实现对应能力，不使用空值或 UI 特效来暗中决定规则。
4. **Step 4：再开外围讨论。** 用 07 明确仓库、道具和活动等范围；保留 R 编号、C 编号到测试记录，修正旧说明只在新文档登记，不直接覆盖历史证据。
