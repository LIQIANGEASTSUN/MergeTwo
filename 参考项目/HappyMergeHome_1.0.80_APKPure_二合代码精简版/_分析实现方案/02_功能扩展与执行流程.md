# 02　Happy Merge Home：功能与执行流程

版本：1.0.80（目录标识）｜复核日期：2026-09-26｜静态分析，未运行游戏。

## 1. 功能如何分派，操作如何进入

**已确认（静态证据）**：物品能力主要由配置判断，再进入对应代码分支。手动生产检查输出配置和产量；时间生产由 IsTimeProductItem 识别，明确条件是 timeOutput_cost 数组长度大于 1、首项为 2。同一份配置可以同时保存两类生产参数，当前记录再保存次数、时间和限制，没有单独生产能力实例的身份证据。

拖放进入 ProcedureHandle，按已登记顺序尝试处理器，遇到 true 停止。true 表示“这次输入已处理”，既可能完成操作，也可能只是拒绝后归位。注册代码中的委托目标未全部恢复，优先级不能由方法声明顺序推定。

通知也有不同用途：OnRefresh 重读业务记录并刷新 Grid；OnNewItem 转调可覆写方法，基类普通路径为空。ButterflyWorkShopMergeBoard 的覆写会转交活动模块，但基础合成、生产中也有活动调用。这是配置分派、处理器链和继承扩展的混合，未证实完整的能力添加、移除、保存和恢复体系。

以下流程中的可读调用与字段写入为**已确认（静态证据）**，推断和缺口另行注明。“业务生效”指内存数据变化；实际写盘节点未恢复。各流程也没有统一的“全部写完才开始表现”约定。

## 2. 打开棋盘：取得记录，建立运行格子和画面

1. **接入数据。** InitStorage 把外部存储对象交给 MergeManager。能确认取得数据，不能补出底层从哪份文件读取。
2. **必要时新建。** InitMergeBoard 的新建分支设置 7×9，先填空记录，再按初始格配置写入种类、状态，加入棋盘字典。配置值和旧存档迁移规则不全。
3. **建立格子。** MergeBoard.Awake 读取保存的宽高，计算矩形和格子尺寸；InitGrids 按位置建立 Grid，并读取物品记录。
4. **绑定显示。** RefreshGrid 处理旧 View 的回收，绑定种类、状态、位置与记录，调用 UpdateData 更新外观。可读局部包含“配置不存在则删除物品”，所以它并非纯绘制函数。
5. **注册交互并检查到期变化。** Awake 注册事件、输入、拖放处理器和提示处理器；OnEnable 调用 RefreshAllProduct，停止部分旧动画并刷新已有 View。重新打开界面可能修改生产记录。

这些局部先后可以确认，但外部存储初始化与 Unity 生命周期之间的完整启动次序、资源失败处理，以及“全部准备好才开放输入”的统一确认点仍待验证。

## 3. 拖动与合成：来源和目标分步变化

普通同种合成的关键业务顺序是：

~~~text
来源、目标定位
  → 处理器检查状态、种类与下一等级
  → 清空来源
  → 写入目标结果
  → 调整生产数据、解锁邻箱、处理附加产物
~~~

**定位与分派。** 按下、抬起计算格子编号；拖动时还读 Transform 位置寻找目标，随后由 ProcedureHandle 分派。输入依赖实时画面位置，不是纯逻辑坐标请求。

**匹配与特殊分支。** Procedure_SameGridItem 对普通同种合成要求来源通过 IsOpen，排除双方气泡和目标箱罩，再读取 next_level。没有有效下一等级时，不保证仍可合成：存在交换或归位等分支。配置 type=2 的箱子若一方已经使用过生产次数，会转向交换；类型 18、19、33 等工具还有累加强化值的特殊合并，不能套用普通升级规则。

**占位写入。** 来源先经 SetBoardItem 改为 Id=-1；随后 Merge 在目标位置调用 SetNewBoardItem 写入下一等级和开放状态，再设置生产计数、初始库存，尝试解锁邻箱，并按分支处理冰块、泡泡、经验等附加结果和活动逻辑。合成会先重置部分数据，再补入需要继承的量，并非完整复制旧物品。

**通知与动画。** SetBoardItem 本身可以派发通知，OnRefresh 再刷新和安排动画。因此通知可能位于多次写入之间，不能把上图理解成“所有业务都完成后才刷新一次”。动画完成回调会清除 isAnim；事件总线是否同步执行、是否允许嵌套业务调用仍待验证。

**交换与拒绝。** 交换入口先调用数据交换，再调整 View 的位置编号并播放归位动画；数据交换函数尾部反编译失真，尚不能核实两侧全部赋值。普通拒绝会归位，默认处理器还检查状态 10 和动画标志。中途异常、连续输入插入、重复执行和动画失败后的补偿未恢复完整。

### 权限按具体动作判断

| 动作 | 已确认的局部条件 | 不能外推的结论 |
| --- | --- | --- |
| 开始拖动 | IsGridUnlock 接受状态 1、2、3、6；网锁 0、箱罩 -1、状态 10 不通过该判断 | 气泡能通过此处，不等于允许气泡参与合成 |
| 普通同种合成 | 来源须开放；排除气泡和目标箱罩；局部条件未排除网锁目标 | 网锁作为目标的完整手势仍受更早处理器影响，属于较强推断 |
| 解除箱罩后继续操作 | 记录先改变，随后播动画 | 动画期间是否还有格子或整盘输入屏蔽未确认 |
| 时间生产 | 全盘扫描要求 IsOpen；点击入口另有时间分支 | 不能用扫描条件代表全部生产入口 |
| 出售、交换、生产 | 各处理器与界面分别判断 | 未恢复完整的“动作×状态×活动”权限表 |

配置能力与 State 分开存放，支持“能力仍存在，但某个入口暂不允许用”。没有证据证明项目会统一汇总所有独立限制，也不能由此认定现有玩法已发生权限错误。

## 4. 点击生产：检查、选择与写入交织

同格点击处理器可以调用 OperateItem。普通手动分支需要开放状态，并检查激活等待、是否仍需激活以及生产能力；**不满足这些条件时，代码可能转到时间生产分支**。手动与时间处理按条件分流，不是每次点击都先自动生产、再手动生产。

普通手动路径的关键步骤如下：

1. **检查资源与可用量。** 资源读取来自 UserData；GetLeftProductCount 先做 ResetProductCount，再求剩余量，所以查询就可能恢复到期次数和库存。
2. **寻找落点。** 有剩余次数而找不到空位时，普通产出分支不继续。无剩余次数则还可能进入耗尽处理，不能把“没有空位”当成整个方法绝不会改数据。
3. **选择产物。** 可读分支包含按生成次数取 level_box_produce、合成链规则、掉落间隔、限量、动态权重和一般输出池。它们依条件选择，并非每次全部执行。
4. **更新选择进度并处理费用。** 某些路径先记录掉落间隔、增加生产轮次；费用相关外部调用出现在 ProductOneItem 前，但被调用实现缺失，不能确认精确扣费、退费及失败补偿。
5. **记录生产并放物。** 普通 ProductOneItem 先更新次数、库存和参考时间，再检查有限生成器是否耗尽、是否移除或替换它，最后在落点写入产物。耗尽替换另有提前处理并返回的路径；释放时间缓存也会跳过普通生产记账。
6. **刷新后续状态。** 部分路径把物品设为计时状态 3；Board 组织动画，View 刷新产出状态和倒计时，未证实统一的异常恢复。

普通产物的 output_lock=1 时写网锁状态 0，否则写开放状态 1。一般输出选择会把 power 与额外权重交给未恢复名称的函数，因此“按权重抽取”属于**较强推断**；随机算法、种子及重启后的随机状态仍待验证。

生产字段需要区分：

| 数据 | 实际含义 |
| --- | --- |
| ProductCount | 普通生产路径会增加的已用次数；普通剩余量由配置输出量减去非负已用次数求得 |
| StoreMax | 库存型手动生成器直接读取的可用量 |
| TimeProductCount | 时间生产路径累计的已生产次数 |
| TimeStoreMax | 当前累积可使用的时间生产量；GetTimeProductCount 返回的是它，方法名容易误导 |
| ProductItems | 已选好、尚未放上棋盘的产物种类列表，不是剩余随机机会 |
| ProductTime、TimProductTime、InCdTime | 生产或冷却参考时间，不能一概称为截止时刻 |

output、power、output_amount、max_output_amount、cd_time，以及 produce_cost、output_cost 等参数属于物品配置；上述计数、库存和时标属于物品记录，可序列化。耗尽后可能冷却、删除或替换，新物品会重置部分生产状态，实际落盘仍是独立问题。

**返回 false 不等于毫无变化。** 它可能伴随到期恢复、耗尽替换；时间分支甚至可能已放出产物后返回 false。判断一次操作是否成功，要看具体分支的业务结果，不能只套一个布尔值。

## 5. 时间推进：三类等待与一个暂停机制

### 冷却结束：恢复手动生产资格

时间方法通常使用保存的参考时间和配置时长计算剩余时间，部分调用从外部时钟取值后除以 1000。符合条件时，ResetProductCount 把已用次数归零并刷新库存；View 更新倒计时。这里恢复的是生产资格，不等于已经生成物品。

### 激活或开启等待：另存起点时间

ClickTime 写入 ActiveTime，并把物品设置为状态 1；subTime 参数通过把起点向前移动来抵扣等待。GetLeftActiveTime 对激活类型 3、4 使用 active_cost 中的时长参数乘以 60，再减去经过时间。

类型 4 的启动分支还会用 IsHaveOpenBox 检查当前棋盘，已有符合条件的开启对象时返回。这说明开启等待有自己的数据和门槛，不能与拆除箱罩或普通生产冷却混写；具体配置对象仍待补证。

### 时间生产：先选产物，再尝试放入附近

时间配置包括 timeOutput、timeOutputPower、time_output_amount、time_max_output_amount 和 timeOutput_cost。

1. **触发。** OnEnable 调用 RefreshAllProduct；扫描对开放的时间生成器依次调用 TimeProductItem、FreeTimeProductItem。另有疑似周期调度调用，但函数名、字符串不全，不能断言精确每秒执行，也未证实统一到期队列。
2. **检查库存与缓存上限。** TimeProductItem 先检查缓存是否已满，再检查冷却，读取 TimeStoreMax 作为本轮可生产量。
3. **逐件选出并找位。** GetOneTimeOutput 先选产物，GetSudokuEmptIndex 再找附近 3×3 空位。有位时，生产动画调用可先于 ProductOneItem 的数据写入。
4. **无局部空位则缓存。** RecordTimeProductItem 再次检查上限，追加产物 ID，并记录本次生产：增加已生产次数、减少 TimeStoreMax、更新时间。因此缓存已经选定结果，不会在释放时重抽。
5. **有位后释放。** FreeTimeProductItem 先放入产物，再删除缓存项并刷新；无位则保留。它使用特殊参数跳过普通计次。

**缓存上限已经确认**：IsTimeProductMaxCount 比较 ProductItems.Count 与配置 time_max_output_amount。时间库存补充也有同一配置上限的约束。实际配置数值、完整离线与异常分支仍待验证。

限制落点的是附近区域，棋盘其他地方有空位也可能缓存。点击进入时间分支后，还可能使用向外扩圈的 FindEmptyGrid 放出新产物或缓存，范围与自动扫描不同。更需要注意：OperateItem 的非开放或激活等待分支也可转入时间处理；仅凭扫描处的 IsOpen 不能证明点击同样受限。受限物品能否实际走到这些路径，仍需结合处理器顺序和配置验证。

### 暂停、恢复与关闭重开

**项目已有分类型的暂停接口。** PauseCd 会按气泡、冰块或状态 1 的等待类型取得剩余时间，符合分支条件时写 PauseCDTime，再设 IsPause；ResumeCd 依据相应时间查询重设参考时标，清除暂停标记。入库与取出路径确实调用了这两个方法。

但不能直接说所有计时都被正确冻结：气泡查询会在暂停时返回 PauseCDTime，已查时间生产 CD 查询仍按时钟与 TimProductTime 计算，未见同样的暂停判断。两个批量方法 PauseAllCdTime / ResumAllCdTime 的普通路径也先筛选气泡或冰块剩余时间，不是无条件处理所有生成器。它们说明存在分类型暂停设计，完整覆盖和效果仍待验证。

时间库存查询中可见按经过时间补充并限制最大量，重开界面又会查询，因此离线补充库存是**较强推断**；这不证明离线期间逐周期生成并缓存了产物。OnApplicationPause 的恢复分支会收尾未完成手势，本身不是完整离线结算器。

还缺的主要是后台调度、进程关闭后的恢复、时钟校正与倒退、库存和缓存如何共同结算，以及配置变化后的处理。时间查询本身还可能修正参考时标，不能默认它们都是只读操作。

## 6. 箱罩、网锁与气泡：解除方式各不相同

### 箱罩解除先改变业务状态

箱体遮挡位于物品记录，区别于配置 type=2 的箱子物品。OpenBox 的顺序明确：

1. TryOpenBoxes 检查十字方向邻格。
2. 非空且 IsBox 接受的物品，将 State 改为 UnlockState；**这次字段写入就是内存中解除状态生效的时点**。
3. SetBoardItem 通知相关更新，随后播放破罩动画并刷新外观。
4. UnlockState=1 时继续尝试解除邻箱；如果是网锁 0，则拆罩后网锁仍在。

连锁主要依靠状态不再是箱罩而终止，这是基于可读分支的**较强推断**；没有通用去重集合或连锁上限的证据，配置合法性未确认。TryOpenBoxes 的可读返回值会被每次 OpenBox 结果覆盖，也不能直接理解为“是否曾开过任意一个邻箱”的汇总结果。

### 网锁已有一条明确的道具解除分支

Procedure_LockAndNoBubble 检查到来源为扫帚道具（配置 type=16）、目标为网锁后，会先移除扫帚，再保留目标种类并把状态设为 1，接着解锁邻箱、播放效果并刷新提示。该局部分支已确认。

普通同种合成处理器也没有在局部排除网锁目标，但完整输入仍可能被前面的处理器拦截。网锁付费解除、道具全部适用条件和活动例外尚未贯通。

### 气泡倒计时与显示回调共同参与

气泡使用 State=2、bubbleType、bubbleDiscount、OpenTime 等物品字段。当前普通 GetBubbleLeftCdTime 分支按 OpenTime 计算 60 秒倒计时；暂停时读取 PauseCDTime。这是保留原生路径的规则，不能外推到所有热更新或特殊气泡。

RefreshBubbleStatus 先比较 View 绑定的记录与当前格内记录，再查状态和时间。相关的两个生成回调读取**当前 View 的棋盘编号和位置**，把物品替换为配置指定种类，配置结果无效时使用 10203，再播放效果。回调会写业务是事实；安排它们的外部函数未恢复，不能认定只在动画结束后执行，也不能保证停止动画就阻止替换。

合成流程可进入生成气泡的方法，但完整概率与配置链尚未贯通。泡泡资源、动画、折扣显示可定位，实际透明度和命中范围未知。刷新时的引用比较并不等于延后回调执行时也有身份校验；移动、换绑、过期恢复和回池后的行为仍待验证。

## 7. 出售、撤销与显示回收

1. **准备出售表现。** SellItem 先调用 OnSellItem，克隆图标并取得位置，随后 SetUndoStatus 暂存恢复信息；表现准备早于删除。
2. **复制恢复字段。** 可见复制 Id、State、ProductCount、StoreMax、TimeStoreMax、ProductItems、ProductTime、TimProductTime、InCdTime；OpenTime 的反编译取值异常。此方法未见复制 TimeProductCount、ActiveTime、UnlockState、IsPause、UniqueId 等全部字段，不能称为完整快照；哪些可售物品真正需要它们仍待确认。
3. **删除业务占位。** RemoveBoardItem(out) 交出旧记录，把棋盘位置替换为空记录，再通知刷新。这是占位被腾出的时点。
4. **回收 View。** RefreshGrid 重置旧显示对象、回池并清格子引用；StopTweenAnim 和 OnDisable 还处理动画、协程、字典、气泡显示标志及位置。Reset 方法恢复质量差，无法确认全部订阅和延后动作都已取消。
5. **撤销恢复。** UndoOperate 检查出售冷却与资源；原位置为空时放回并选中，被占用时有转入奖励队列的分支。其控制流失真较重，金币扣回、重复点击和完整失败恢复仍待验证。

这是界面实例字段暂存的专用撤销，不是通用操作历史。连续出售如何覆盖、关闭后是否保留、实例身份怎样恢复均未完整确认。缺字段和反编译异常是核对重点，不能直接认定线上一定丢失数据。

延后动作还有两种不同引用：RefreshGrid 完成回调捕获格子、位置和动画对象，结束时清 isAnim；DoAnimation 的一个回调会读取物品 UserInfo，满足特定标记时播放效果并清除它。UserInfo 虽用于表现判断，却在可保存记录中。是否有完整的“旧绑定失效后拒绝回调”保障仍待验证。

## 8. 入库与取出：移动记录，也处理计时

**已确认（静态证据）**：主棋盘拖入背包的可读分支先比较背包数量与容量；通过后调用 PauseCd，把原记录引用加入背包，再用 RemoveBoardItem(out) 清空原棋盘位置。因此不是逐字段复制物品；但加入背包和清空占位仍是两次动作，中间可能有通知。

普通取出入口 UseBgItem 检查目标索引非负、背包非空，随后 RemoveBagItem 取出记录，SetBoardItem 把它放回棋盘，再调用 ResumeCd。建筑背包有近似路径。

这些入口足以确认记录迁移和暂停调用，尚不足以证明全链可靠：取出方法自身没有重新检查目标一定为空，目标选择依赖调用者；入库允许哪些类型、全部容量与输入条件、中途失败恢复，以及各种计时是否准确续接仍待验证。不能由 AddBagItem 的简单追加，推定整个搬移是一次不可分割的操作。
