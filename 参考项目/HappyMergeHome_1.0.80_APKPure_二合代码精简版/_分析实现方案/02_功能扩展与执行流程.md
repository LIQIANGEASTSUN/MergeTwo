# 一次点击、合成和解锁，内部怎样发生

版本：1.0.80（目录标识）｜分析日期：2026-09-25｜仅静态分析，未运行游戏。

## 阅读这些流程时，先记住两个区别

第一，**冷却结束不一定产生新物品**。手动生成器到期后可以恢复可用次数，等玩家再点；时间生成器则会选出产物并尝试放到棋盘上。还有一类“激活/开启等待”，使用ActiveTime和active_cost计算，属于另外的过程。（[E21](04_证据索引.md#E21)、[E22](04_证据索引.md#E22)、[E23](04_证据索引.md#E23)、[E25](04_证据索引.md#E25)）

第二，**数据已经改好，不等于动画播完，也不等于文件已保存**。以下流程把“业务生效”理解为内存中的物品、位置或次数发生变化；真正写盘的节点尚未恢复。动画与数据的关系也因流程而异：破罩先改数据，出售先准备表现，气泡则有回调参与业务写入。（[E25](04_证据索引.md#E25)、[E27](04_证据索引.md#E27)、[E31](04_证据索引.md#E31)、[E33](04_证据索引.md#E33)）

正文按六个常见场景展开。查某种能力的数据、触发、权限和保存方式，可直接看后面的[逐功能查阅表](#功能维度)。

## 功能是怎样分配给物品的

**已确认（静态证据）**：项目主要读取配置来判断物品能做什么，再进入相应代码分支。手动生产检查输出配置及可用量；时间生产有专门的识别条件，即timeOutput_cost数组长度大于1、首项为2。同一份物品配置可以包含两类生产字段，当前次数、时间和状态再决定此刻能否使用。（[E19](04_证据索引.md#E19)）

拖放的用途另由一串处理函数判断：某个函数返回true，后面的函数就不再处理本次输入。这里的true表示“已经处理”，可能是完成操作，也可能只是拒绝并移回原位。完整注册顺序因反编译缺符号而**待验证**，不能按方法在文件中的排列顺序推定。（[E13](04_证据索引.md#E13)）

活动棋盘有继承扩展。例如ButterflyWorkShopMergeBoard在收到新物品通知时，转给对应活动模块处理；但基础合成、生产方法中也直接调用了一些活动模块。它既有扩展入口，也有基础代码中的特殊分支，尚未证实一套通用的“能力添加、移除、保存、恢复”机制。（[E34](04_证据索引.md#E34)、[E37](04_证据索引.md#E37)）

## 1. 打开棋盘：先有记录，再建立画面

1. **取得棋盘数据。** InitStorage把外部存储对象接到MergeManager。外部服务的实现未恢复，因此目前只能看到“拿到数据”，不能补出“从哪份文件读取”的过程。（[E06](04_证据索引.md#E06)）

2. **没有棋盘时，建立初始记录。** InitMergeBoard的新建分支设置7列、9行，为每个位置建立记录，默认种类为-1，再根据初始格配置填入物品和状态，加入棋盘字典。配置值缺失，已有存档如何迁移或修复也未完整恢复。（[E06](04_证据索引.md#E06)）

3. **根据尺寸建立运行格子。** MergeBoard.Awake读取存档宽高，计算棋盘矩形和格子尺寸；InitGrids按位置读取物品种类、状态并建立Grid。此时，物品业务数据已经在Storage记录里。（[E06](04_证据索引.md#E06)、[E07](04_证据索引.md#E07)）

4. **把记录显示出来。** RefreshGrid处理旧显示对象的回收，绑定物品种类、状态和位置，再更新外观。该方法有截断；可读局部还包含“缺配置时删除物品”的分支，所以不能把它当成纯绘制函数。（[E28](04_证据索引.md#E28)）

5. **接入输入，并检查到期生产。** Awake注册事件、输入和处理函数；界面启用时还会扫描生成器、刷新已有显示。启用过程可能修改生产记录，并不是只把画面打开。（[E06](04_证据索引.md#E06)、[E24](04_证据索引.md#E24)）

**待验证**：真实启动调用次序、首次进入与重新进入的差别、资源加载失败，以及是否存在一个明确的“全部准备好，才开放输入”的确认点。

## 2. 拖动与合成：先清来源，再写目标

以普通的两个同种物品合成为例，已恢复的关键顺序是：

~~~text
找出来源格和目标格
  → 检查本次拖放能做什么
  → 检查种类、状态和下一等级
  → 清空来源格
  → 在目标格写入合成结果
  → 处理次数、邻箱和其他附带变化
  → 更新画面与动画
~~~

1. **先定位，再交给处理函数判断。** 按下和抬起时会计算格子编号；拖动时还会检查能否操作，并使用画面对象的位置寻找目标。输入因此依赖部分实时画面信息。ProcedureHandle随后逐个调用处理函数，首个“已处理”结果结束这次分派。（[E12](04_证据索引.md#E12)、[E13](04_证据索引.md#E13)）

2. **普通同种合成有自己的状态检查。** Procedure_SameGridItem要求来源物品处于IsOpen接受的状态，排除某些目标状态，再读取配置中的next_level。来源和目标的要求并不完全一样；具体区别见[权限查阅表](#权限查阅)。（[E15](04_证据索引.md#E15)）

3. **分两步修改占位。** 先调用SetBoardItem把来源种类改成-1，再由Merge在目标位置调用SetNewBoardItem，写入下一等级和开放状态。这两处写入就是本次合成的关键业务生效点；当前未看到先计算完整变化清单、再一次性应用的机制。（[E15](04_证据索引.md#E15)）

4. **继续处理附带结果。** 合成还会更新次数/库存，尝试解除邻近箱体遮挡，并执行附加产物或活动逻辑。这些结果会继续直接修改数据。（[E15](04_证据索引.md#E15)、[E25](04_证据索引.md#E25)、[E34](04_证据索引.md#E34)）

5. **通知显示刷新。** 已定位OnRefresh重读记录并调用RefreshGrid，随后组织动画，完成回调清除“正在动画中”的标志。全部事件监听者的执行顺序，以及通知是否会立刻引发另一轮业务调用，仍未恢复完整。（[E11](04_证据索引.md#E11)、[E28](04_证据索引.md#E28)、[E29](04_证据索引.md#E29)）

如果没有合成而是交换，入口顺序是“交换数据→更新显示位置编号→播放归位动画”。但负责交换两侧记录的方法尾部反编译不完整，不能据此确认全部赋值，也不能认定它漏写了一侧。（[E16](04_证据索引.md#E16)）

普通拒绝可把物品移回原位；默认处理器还会拒绝状态10或正在动画中的格子。（[E14](04_证据索引.md#E14)） **待验证**：清空来源后写目标失败怎么办、连续输入是否插入中间过程、同一操作被重复执行时怎样处理，以及动画失败后的业务补偿。

## 3. 点击生产：一次点击可能不只做一次检查

**已确认（静态证据）**的手动主路径如下，特殊物品仍可能另走分支。（[E20](04_证据索引.md#E20)、[E21](04_证据索引.md#E21)）

1. **先判断这件物品能否使用。** 同格点击进入OperateItem，读取配置和物品记录，检查当前状态以及是否还在激活等待。若物品同时有时间生产能力，还可能先结算自动产出或释放缓存。（[E20](04_证据索引.md#E20)）

2. **检查次数、资源和空位。** 手动分支查询剩余次数并找落点。有剩余次数却没有空位时，普通生产分支不会继续。但查询次数的方法GetLeftProductCount会先调用ResetProductCount，所以检查本身可能已经恢复了到期次数或库存。（[E20](04_证据索引.md#E20)、[E21](04_证据索引.md#E21)）

3. **决定这次产什么。** 它不只是调用一次普通随机。可读分支还包含按生成次数选择、按合成链选择、间隔规则、限量和动态权重等情况。不同物品进入不同分支，不能把这些方法名单当成固定的执行顺序。（[E20](04_证据索引.md#E20)）

4. **记录生产进度并处理费用相关调用。** 某些路径先记录掉落间隔或增加生产轮次；无次数时也可能替换耗尽生成器，然后返回false。因此，false不能解释为“这次什么都没改”。费用相关外部函数缺符号，精确扣费、退费和失败处理仍待验证。（[E20](04_证据索引.md#E20)）

5. **记次数，再放入产物。** ProductOneItem调用RecordProductInfo更新时间、次数和库存，然后处理有限生成器的移除/耗尽替换，最后用SetNewBoardItem放入产物。这些是分步写入，不是一次只读计算后的整批提交。（[E21](04_证据索引.md#E21)）

6. **更新画面和后续状态。** 某些路径会进入冷却状态3；刷新和动画也在这棵调用链中发生，尚未证实统一的异常补偿。（[E20](04_证据索引.md#E20)）

普通分支还可以产出带网锁的物品：output_lock=1时写状态0，否则写状态1。（[E20](04_证据索引.md#E20)） 常规产物选择会把基础power和额外权重传给一个未恢复名称的函数，因此“按权重抽取”是**较强推断**；实际算法、随机种子及跨重启保存方式待验证。（[E19](04_证据索引.md#E19)）

这条流程最值得留意的是：**没生产成功，也可能合法地恢复了冷却次数。** 判断错误不能只看“是否改过数据”，还要区分到期刷新、选择进度和真正扣费。

## 4. 时间到了：恢复次数，还是产生物品？

### 手动生成器：到期后重新变得可用

多个时间方法以保存的参考时间和配置时长计算剩余时间，部分方法会读取同一个外部时钟并除以1000。界面根据结果更新倒计时，次数查询也可能重置已到期的数据。这些字段不全是“截止时刻”，也包含开始或参考时刻。（[E21](04_证据索引.md#E21)、[E22](04_证据索引.md#E22)）

### 时间生成器：先选产物，再找附近的位置

**已确认（静态证据）**：

1. **界面启用时扫描生成器。** OnEnable调用RefreshAllProduct，对开放状态的时间生成器执行生产和缓存释放。另有看起来用于调度的调用，但函数名和字符串没有完整恢复，不能断言它精确每秒运行。（[E24](04_证据索引.md#E24)）

2. **计算当前可产出的数量。** TimeProductItem读取时间库存并循环。这里的“时间库存”可以理解为当前累积可使用的生产量，与已经选好但还没摆出的产物不是同一份数据。（[E22](04_证据索引.md#E22)、[E23](04_证据索引.md#E23)）

3. **先选出一件产物，再找周围3×3的空位。** 选择方法是GetOneTimeOutput，落点方法是GetSudokuEmptIndex。有位置便调用ProductOneItem；可读路径中，生产动画调用可出现在写入产物前。（[E23](04_证据索引.md#E23)）

4. **附近放不下，就记入缓存。** RecordTimeProductItem把产物ID放进ProductItems，同时记本次生产。缓存里保存的是“已选好的产物”，不是“以后再随机一次的机会”。（[E23](04_证据索引.md#E23)）

5. **以后有位置，再释放缓存。** FreeTimeProductItem放入产物后从缓存移除；没有位置就继续保留。释放走特殊路径，避免按普通生产重复记账。（[E23](04_证据索引.md#E23)）

注意限制的是**附近3×3区域**，不能简单说成“整张棋盘满了才缓存”。点击路径中的部分落点搜索会寻找更远的空位，和自动生产并不相同。局部找位的具体顺序仍有反编译疑点，见[落点搜索](01_架构与数据模型.md#坐标细节)。（[E17](04_证据索引.md#E17)、[E18](04_证据索引.md#E18)、[E20](04_证据索引.md#E20)）

### 关掉再打开，会补多少？

时间库存查询中可见按经过时间补充、按上限约束的逻辑，所以离线后补充库存属于**较强推断**。但这不证明“离线每过一个周期都完整生成并缓存了一件物品”。界面重开会再查询时间；暂停恢复入口还会收尾未完成手势，它本身不是完整的离线结算器。（[E22](04_证据索引.md#E22)、[E24](04_证据索引.md#E24)、[E35](04_证据索引.md#E35)）

**待验证**：后台是否继续扫描、进程关闭后的补算、时钟校正/倒退、暂停字段、缓存与补算上限，以及配置变化后的处理。也未证实使用统一的到期任务队列。

## 5. 解除箱体遮挡：规则先变化，动画随后开始

这里说的**箱体遮挡**，是物品记录上的限制状态；它不同于配置中type=2的“箱子物品”。

[OpenBox的可读代码](../code/Ghidra_native_pseudocode/2be6e1c.c#L35)给出了明确顺序，属于**已确认（静态证据）**：（[E25](04_证据索引.md#E25)）

1. 合成后检查十字方向的邻格。
2. 对非空且被判定为箱体遮挡的物品，把State改成UnlockState。
3. 调用SetBoardItem更新记录；**业务上的解除在这里已经发生**。
4. 随后播放破罩动画并刷新显示。
5. 如果恢复为状态1，还会继续尝试解除相邻箱体。

如果UnlockState是网锁状态0，解除外层箱体后仍有网锁。因此，“罩子消失了”不等于全部操作都开放。循环扩展主要依赖状态不再是箱体来终止；合理配置可让解锁持续向前推进，这是**较强推断**。当前缺少配置值，不能确认所有配置，也没见通用的去重集合或连锁次数上限。（[E02](04_证据索引.md#E02)、[E25](04_证据索引.md#E25)）

### 气泡的处理不完全相同

RefreshBubbleStatus先检查绑定记录、泡泡状态和剩余时间。相关的两个生成回调会读取**当前显示对象的棋盘编号和位置**，调用SetBoardItem替换物品，再播放后续效果。回调参与业务修改是事实；但安排回调的外部函数未恢复，不能断言它只会在动画结束后执行，也不能断言停止动画一定能阻止替换。（[E27](04_证据索引.md#E27)）

**待验证**：网锁主动解锁的完整付费/道具路径、破罩动画期间是否屏蔽输入，以及气泡回调在物品移动、显示对象复用后是否仍安全。覆盖资源的完整清理范围、实际透明度也未确认。（[E26](04_证据索引.md#E26)、[E29](04_证据索引.md#E29)）

## 6. 出售与撤销：删除记录和回收画面是两件事

1. **先准备出售表现和恢复记录。** SellItem先调用OnSellItem克隆图标、取得位置，再由SetUndoStatus记录待恢复物品，之后才删除。这里的表现准备早于业务删除。（[E31](04_证据索引.md#E31)）

2. **恢复记录按字段复制。** 已见种类、状态、次数、库存、缓存产物和部分时间字段的复制。OpenTime的反编译取值异常，所以完整性需要复查；不能把这个工具异常直接认定为原游戏Bug。（[E31](04_证据索引.md#E31)）

3. **真正腾出棋盘位置。** RemoveBoardItem交出旧记录，并把位置替换成种类-1、状态1的空记录，再通知刷新。这是删除在业务上的生效点。（[E30](04_证据索引.md#E30)）

4. **回收显示对象。** RefreshGrid清旧显示对象的编号，执行重置、回池并清格子引用。StopTweenAnim和OnDisable还有动画、协程、字典及位置清理；但重置方法恢复质量不佳，不能确认所有订阅和延后动作都已清理。（[E28](04_证据索引.md#E28)、[E29](04_证据索引.md#E29)）

5. **撤销时先判断还能放回哪里。** UndoOperate检查出售冷却和资源。原位置为空时放回并选中；已被占用时有转入奖励队列的分支。这个方法反编译失真较重，经济对账和重复点击处理仍待验证。（[E31](04_证据索引.md#E31)）

这是由出售界面的实例字段暂存恢复信息的**专用撤销**，不是让任意历史操作反向执行。退出界面后是否还保留、连续出售如何覆盖、所有生成器字段和UniqueId怎样恢复、金币如何扣回，都不能从当前代码完整确认。（[E31](04_证据索引.md#E31)）

还要留意延后回调：某个动画完成回调会清除格子的动画标志，另一个会清Storage.UserInfo；气泡回调则读当前View的位置。**已确认（静态证据）**的是这些引用和写入，完整的“旧绑定失效后拒绝回调”机制仍待验证。（[E27](04_证据索引.md#E27)、[E29](04_证据索引.md#E29)）

## 查阅：不同操作为什么要分别判断

“能操作”不能概括拖动、被合成、生产、出售的所有情况。下面只列已追踪的普通路径；活动例外未查全。

| 问题 | 已覆盖代码能确认什么 | 仍不能确认什么 |
| --- | --- | --- |
| 网锁物品主动拖动 | 拖动前检查格子；普通路径不允许网锁状态0开始拖动（OnHandle_Drag→IsGridUnlock） | 所有活动覆写和特殊道具输入是否例外 |
| 网锁物品作为普通同Id合成目标 | 同种合成处理器要求来源开放，排除目标气泡/箱罩；目标网锁状态0可通过这一局部条件 | 处理链更早的处理器是否截获；故实际完整手势为较强推断 |
| 罩中物品能否直接被普通合成 | 普通同种合成遇到箱体遮挡目标会移回原位，不进入合成 | 拆罩道具/活动的全部例外 |
| 已解锁仍在破罩动画 | 先改物品记录，再播破罩动画 | 下一次输入是否被isAnim/整盘屏蔽拦住；不能说动画期间必可再操作 |
| 能力是否仍在但被暂时限制 | 产出配置与State/时间独立存放，调用点额外判断 | 一般化可叠加冻结/封印模型是否存在 |
| 多限制解除是否只释放自身 | 单State加特殊字段/分支，未见通用限制令牌或计数聚合 | 不能据此指控现有玩法已发生“解除一个恢复全部”的运行缺陷 |
| 售出/交换/生成是否共用权限 | 各处理器和UI入口分别判断；默认处理器还检查Grid.isAnim | 缺完整动作×状态×活动矩阵 |

证据：[E04](04_证据索引.md#E04)、[E12](04_证据索引.md#E12)、[E14](04_证据索引.md#E14)、[E15](04_证据索引.md#E15)、[E25](04_证据索引.md#E25)。代码中的整数比较或位运算，不能单凭形式就解释成可叠加状态设计。

## 查阅：每种功能的十个问题

下面按功能分别列出数据归属、创建、触发、权限、执行、表现、组合、迁移和保存，便于只查自己关心的一项。字段和可读分支为**已确认（静态证据）**，推断与缺口保留在对应格内。

### 手动生产与次数冷却

依据：[E19](04_证据索引.md#E19)–[E22](04_证据索引.md#E22)。

| 要了解的问题 | 项目做法 |
| --- | --- |
| 数据属于谁 | Item记录+配置，无单独生产能力实例ID |
| 保存哪些数据 | output、power、produce_cost、output_amount、cd_time；ProductCount/StoreMax/ProductTime/InCdTime |
| 怎样获得这个功能 | 配置条件+OperateItem分支；SetNew重置次数 |
| 何时触发 | 同格点击处理器→OperateItem |
| 怎样判断允许操作 | IsOpen、激活等待、可生产、次数、空间、资源等分散判断 |

| --- | --- |
| 数据属于谁 | 同一Item，无单独任务实体身份 |

### 箱体遮挡与蜘蛛网

依据：[E04](04_证据索引.md#E04)、[E14](04_证据索引.md#E14)、[E15](04_证据索引.md#E15)、[E25](04_证据索引.md#E25)、[E26](04_证据索引.md#E26)。

| 要了解的问题 | 项目做法 |
| --- | --- |
| 数据属于谁 | Item.State/UnlockState；主路径非独立Cell覆盖对象 |
| 保存哪些数据 | State=-1/10表示OpenBox接受的罩；State=0为IsLockWeb；UnlockState决定罩后阶段 |
| 怎样获得这个功能 | 初始表state或生产output_lock等分支赋值；未见动态添加能力组件 |
| 何时触发 | 合成→TryOpenBoxes；网相关输入/合成处理器 |

| 由谁执行 | OpenBox及邻格递归（流程5） |

| 解除或移动后怎么办 | 解除罩恢复UnlockState；必要时递归开邻罩。网可作为某合成分支目标，完整手势待验证 |
| 怎样保存和恢复 | State和UnlockState保存；未见独立Cell锁层恢复 |

### 气泡

依据：[E02](04_证据索引.md#E02)、[E15](04_证据索引.md#E15)、[E27](04_证据索引.md#E27)。

| 要了解的问题 | 项目做法 |

| 数据属于谁 | Item.State=2及泡泡参数；View有气泡资源 |
