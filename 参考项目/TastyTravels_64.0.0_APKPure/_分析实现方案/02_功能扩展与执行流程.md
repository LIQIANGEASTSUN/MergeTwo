# Tasty Travels：能力怎样工作，一次操作怎样完成

物品的功能由能力组件提供，具体操作由棋盘方法组织。以下先说明各能力保存什么、受什么限制，再还原一次操作的先后顺序。**行为和顺序来自静态复核；故障是否能在正式配置中发生，另行标为推断或待验证。**

## 1. 能力是怎样加到物品上的

### 同一个物品，可以带多个不同功能

项目有一个组件登记表 `ItemComponentTable`，负责登记类型、编号、配置验证器和对象池。初始化物品时，`InitWithNormalItem` 读取物品及能力配置，清除旧组件，补入应常驻的组件，再启动它们。普通物品、生成器和宝箱由此可以共用 Item 结构。

动态添加时，`AddComponent` 先看该类型是否已经存在；不存在才创建组件、绑定物品、加入字典与缓存，再通知变化并交给世界后处理。移除时，`RemoveItemComponent` 解除绑定、移出字典与缓存并通知，但只是返回组件；不能认定这里已把它放回对象池。批量清理 `_ClearAllComponent` 才明确调用 Table.Free。

### 暂时不能使用，不必把能力删掉

一个 Item 可以有多种能力，同一种类型只保存一份。组件保留两个标志：`mEnable` 是显式开关，`mRuntimeEnable` 是刷新后的可用结果。`enabled` 查询返回后者，默认组件查询据此过滤；`includeDisable` 查询仍可取得对象。世界也保存禁用组件类型集合。

**“查不到可用能力”与“停止计时”不是同一个判断。** 组件的 `Update／UpdateInactive` 检查显式开关 `mEnable`；板上物品是否获得更新，还由 Item.active 等条件决定。刷新基类原实现只是返回显式开关，没有证据证明它统一合并了冻结、云或其它宿主限制。禁用不必删除进度，但不能笼统写成“运行时禁用就停止所有更新”。

这个机制尚不等于“多来源限制自动叠加”。例如两个不同原因都冻结同一物品，移除其中一个原因后是否仍冻结，需要额外数据和规则；现有每类型一份的结构不能自动回答这个问题。

### 多个能力响应同一次点击时，谁先执行

点击不是向所有能力逐一广播。`_UseItemImp` 按固定顺序检查，命中一种就返回：

```text
Bonus → TapBonus → Chest → ClickSource → MixSource
      → AutoSource → ToolSource → 各类 Box
```

这是实际条件分支的先后，不是按地址排列的调用清单。它能让少量能力的优先级清楚，但增加一种能力时，往往还要修改点击入口。拖放另有一套动作选择顺序。

时间更新、合成后能力回调和奖励处理器也不是同一套调度：奖励列表另有排序，组件更新后有 `mExecuteAfterUpdate` 延后列表。没有证据表明它们共享全局优先级、停止传播规则或防重入机制；延后执行列表本身也不能当成统一命令队列。

## 2. 六种机制分别怎样工作

每节先给出机制含义，再用同样十个问题核对实现。表中的 `active` 是代码里的业务资格：未冻结、未锁定、未被云覆盖；它不是“图片当前可见”。各机制还可能增加自己的检查。表中的“保存”均指形成存档记录，尚不代表已经写入磁盘。

### 2.1 普通合成：有合成能力，还要满足本次条件

合成能力负责提供“下一种物品是什么”，棋盘负责决定“这两个对象现在能否合成”，以及消费旧物、建立新物。结果物是新实例，不是把目标物直接换一个种类。

| 维度 | 实际实现 |
| --- | --- |
| 归属 | `ItemMergeComponent` 挂在 Item 上，没有独立持久 ID；两物之间的操作由 Board 负责。 |
| 数据 | 组件缓存下一种类；Item 保存种类、位置和基础限制，合成链来自配置。 |
| 创建与装配 | 登记表按配置装配，绑定后 `OnPostAttach` 调 `GetNextItem`。 |
| 触发 | 拖放结束选择合成动作后，`OnEndDrag` 调 `Board.Merge`。 |
| 规则权限 | 检查两物存活、源的 active、目标的锁／云、格类型、气泡、技能及合成结果。目标不要求与源完全相同的 active 条件。 |
| 执行 | 棋盘再次校验，消费两个旧物、创建新 ID 的结果，再做后处理。 |
| 表现 | 合成通知建立结果 View，其动画状态引用两个旧 View 播放；数据不等待动画结束。 |
| 组合与冲突 | 普通同种合成与特殊技能分支共用入口；气泡或格子限制可以先拒绝。能力回调和奖励排序各自处理。 |
| 解除与迁移 | 结果按新种类装配，再做 `ProcessPostMerge`；不能假定继承旧物所有状态。旧组件稍后清理。 |
| 保存与恢复 | 存档汇总记录新结果，不再记录两个旧占位；未证明每次合成都立即写入磁盘。 |

### 2.2 点击生成器：冷却结束后补次数，仍要再点击

它积累的是“接下来还能生成几次”。冷却结束会补充次数，不会因此主动把产物放上棋盘。真正产出要经过点击或相应的使用入口，再检查费用和空间。

| 维度 | 实际实现 |
| --- | --- |
| 归属 | `ItemClickSourceComponent` 挂在 Item 上，继承通用产出能力 `ItemSourceComponentBase`。 |
| 数据 | 可用／待补次数、输出与复活计数、总产出、耗尽、免冷却 NoCD、倍率 Boost、随机序列等。 |
| 创建与装配 | 使用 `ComMergeTapSource` 配置和组件登记表；产出选择复用 Source 基类。 |
| 触发 | 普通物品通常在选中后再次点击才使用；FeatureEntry 有直接使用特例。消耗型拖放也可进入同一生成方法。 |
| 规则权限 | 正常入口先查物品仍有所属容器、未死亡且 active，再查就绪、次数、费用、消耗物和空间；底层调用不保证包含全部界面检查。 |
| 执行 | Board 编排费用与落点，`ConsumeNextItem` 应用待定动作并推进输出。 |
| 表现 | 生成通知驱动动画，Charge／Content 控制器显示进度；具体图标和文案未核验。 |
| 组合与冲突 | 能与倍率、免冷却、有限输出配合；多能力点击按前述顺序选择，实际配置开放哪些组合待查。 |
| 解除与迁移 | 暂时用完与永久耗尽分别处理；后者可销毁生成器并产生末次掉落。合成后的继承要看具体 `OnPostMerge`。 |
| 保存与恢复 | `ComClickSource` 保存次数、进度与随机参数；恢复后继续原有序列。 |

### 2.3 自动产出：充好次数后，主动找格落物

这里分析的是普通 AutoSource，触发型 TrigAutoSource 是另一种能力。普通自动生成器先积累可用次数，再主动尝试产出。与点击型的重要区别是：它在找到合适空位后才消费次数；没位置时停止本次尝试，次数可以保留。自动触发只搜邻近范围，手动点击它时则可以搜索更远。

| 维度 | 实际实现 |
| --- | --- |
| 归属 | `ItemAutoSourceComponent` 挂在 Item 上；找格和创建实例仍由 Board 负责。 |
| 数据 | 可用次数 mItemCount、进度 mOutputCounter、总产出 mTotalOutput、新建标志 mJustCreate 和配置。 |
| 创建与装配 | `ComMergeAutoSource` 配置与登记表装配；`ComAutoSource` 恢复局部数据。 |
| 触发 | 时间更新调用组件 `OnUpdate`；玩家也能通过点击使用它。 |
| 规则权限 | `UseAutoItemSource` 检查组件、物品正常状态和下一产出是否就绪；当前找格参数只接受默认格，未传入本次产物种类。 |
| 执行 | 充能最多补至容量上限，有可用次数且允许生成时循环尝试；自动调用 `maxDist=1`，手动路径为 -1，搜索范围较大。 |
| 表现 | 成功落位后发送生成通知；未见显示资源失败后撤回业务的路径。 |
| 组合与冲突 | 棋盘只更新 active 物品，并应用邻接倍率；不能据此推出冻结期间继续累计离线产出。 |
| 解除与迁移 | 找格在消费次数前；失败保留次数。有限生成器耗尽还可能在原位置替换或掉落。 |
| 保存与恢复 | 保存局部状态；库存更新调用 `OnUpdateInactive`，可补次数但不落物。板上被锁／被冻结的物品不会自动改走这个入口。 |

### 2.4 锁、冻结和云：限制可以共存，但不是同一个东西

锁和普通冻结属于 Item，云与地块条件属于棋盘。解除锁时，代码保留原来的冻结状态。一个值得注意的规则是：**不能主动拖出的普通冻结物，仍可能作为合成目标**，只要通过其它条件；这不适用于气泡组件中同样叫 Frozen 的子类型。

| 维度 | 实际实现 |
| --- | --- |
| 归属 | locked／frozen 属于 Item；云、区域和格类型属于 Board／Grid；Bubble.Frozen 是另一项组件条件。 |
| 数据 | 布尔限制、stateConfType／stateConfParam、云标记数组及 Cloud／Area；没有统一效果实例列表。 |
| 创建与装配 | 初始化、加载和 `SetState` 写物品状态，能力组件按自己的配置存在。 |
| 触发 | 合成后尝试四邻解锁；云进度另有刷新流程。本篇完整追踪的是邻接解锁。 |
| 规则权限 | active 要求非冻结、非锁、非云覆盖；可移动还要配置允许拖动。合成源与目标检查不同。 |
| 执行 | `_UnlockItem` 用 `SetState(false, 原 frozen)` 解锁，再通知；是否继续传播另查冻结和触发型自动生成能力。 |
| 表现 | Content 按锁、冻结、气泡等条件选择遮挡；isInBox 是显示缓存，DelayUnlock 可让解除动画晚于数据变化。 |
| 组合与冲突 | 锁与冻结独立，但没有通用多来源／层数计算；等级门槛还读取界面 `IsLevelDirty`。 |
| 解除与迁移 | 物品限制随对象，云和格类型留在位置；这不代表受限物可以自由拖动。 |
| 保存与恢复 | Item.State 保存基础标志，StateConf 保存附加条件；云／区域另存和重建，全部变化路径尚未覆盖。 |

### 2.5 宝箱与箱子：相似外观可能对应三种实现

这里至少要分清：等待开启的 Chest、提供产物的 Box、仅表示锁定的箱形遮挡。Chest 的开启等待还占用世界里的一个共享槽位，所以多个宝箱并非各自完全独立计时。

| 维度 | 实际实现 |
| --- | --- |
| 归属 | Chest／Box 是不同的 Item 能力；当前等待宝箱 `currentWaitChest` 在世界层；锁外壳属于显示。 |
| 数据 | Chest 存 opened、usedCount；世界存等待物品 ID 与累计等待量。Box 另有输出列表和使用计数。 |
| 创建与装配 | 各自配置通过登记表装配，分别使用 `ComChest／ComBox` 存档。 |
| 触发 | 点击优先检查 Chest；不能使用且世界没有等待宝箱时可 `StartWait`，随后 `UpdateChest` 推进。 |
| 规则权限 | 先检查物品所属容器、存活和 active，再由 `canUse` 与世界等待槽决定能否领取／等待。 |
| 执行 | 等待时间乘以棋盘时间倍率；达到配置时长后设 opened、更新等待状态并标记显示刷新。领取走 `UseChest`。 |
| 表现 | 等待开始／结束事件更新 Charge、ChestTip 等控制器；美术和各阶段动效未核验。 |
| 组合与冲突 | 一个共享等待槽形成跨物品约束；点击优先级中 Chest 先于 ClickSource。 |
| 解除与迁移 | 普通销毁通过 `FinishDisposeItem` 清等待关联；领取耗尽后全部配置变体未逐一验证。 |
| 保存与恢复 | 局部 opened／used 与世界 WaitChest／WaitChestStart 一起保存，恢复后继续推进；配置变化时如何修复关联待查。 |

### 2.6 气泡：它有寿命和交互规则，不只是一张遮罩

气泡能力保存自己的类型、寿命和破泡条件。倒计时还受广告等待、引导和当前交互影响。广告可能晚到，所以成功回调会先检查它是否仍对应当前棋盘中的那个组件，再执行解除。

| 维度 | 实际实现 |
| --- | --- |
| 归属 | `ItemBubbleComponent` 挂在原 Item 上，没有独立的通用效果身份。 |
| 数据 | bubbleType、lifeTime／lifeCounter、breakCost、广告标志，以及请求时物品／棋盘标识。 |
| 创建与装配 | 配置和组件机制装配，Bubble／Frozen 等子类型在内部区分。 |
| 触发 | 更新时间时检查到期；也可经破泡入口或广告完成触发。交互中的物品可能延后过期处理。 |
| 规则权限 | 合成判断专门读取 Bubble，单靠 Item.active 不能覆盖它的条件。 |
| 执行 | 到期调用 `KillBubbleItem`，广告成功分支调用 `UnleashBubbleItem`；广告等待保护部分到期路径。 |
| 表现 | Content 选择气泡资源和遮挡；视觉特效不负责保存寿命。 |
| 组合与冲突 | 气泡、锁和普通冻结是不同事实；外观有优先级，权限判断分散，引导还影响计时。 |
| 解除与迁移 | Board 处理到期／解除后的替换和清理；广告回调先核对当前宿主。 |
| 保存与恢复 | `ComBubble` 记录类型、期限／计数，统一由 Item 委托保存；单位及引导保护下的离线含义尚未完整核对。 |

广告完成的具体保护是：组件仍绑定当前 Item、引用匹配，物品未死亡且有所属棋盘，该棋盘仍是当前活动棋盘，并且物品仍处于气泡条件。保存过 ID 字段不代表成功分支逐一比较了所有 ID；可确认的是这些引用和宿主检查。它也不能证明所有资源加载、动画、广告取消和重试都安全。

## 3. Effect 和 State 在这里分别表示什么

读代码时不能把这些英文词当成同一种架构概念。项目同时使用**业务事实、局部进度、显示阶段、视觉特效和专门的规则效果**：

| 要表达的事情 | 实际表示 |
| --- | --- |
| “这个物品被锁住／冻结” | Item 的布尔标志与 StateConf，可以并存。 |
| “宝箱已打开／生成器充了几次” | Chest.mOpened、充能及复活计数，由对应能力保存。 |
| “现在正在拖动／合成／消失” | ItemLifecycle／MergeItem*State，属于显示阶段。 |
| “播放闪光和提示” | MBItemEffect，属于视觉特效（VFX）。 |
| “范围内有加速影响” | SpeedEffect／IEffectReceiver 的专门数据，以及 Board 的邻接时间倍率。 |

**加速有两条不同路径。** `EffectUtility.CalculateMilliBySpeedEffect` 的原实现把输入毫秒原样返回；另一条 `Board.CalcTimeScale → Item.Update` 路径确实应用邻接倍率，宝箱时间也使用它。不能由 SpeedEffect 类存在就认定通用速度链已经生效。

邻接倍率的合并规则已确认：没有有效来源时返回 1；在符合条件的 type=6 技能来源中，取配置倍率的最大值，不相加或相乘。来源可按目标类别筛选，带启用 Skill 组件的目标直接返回 1；结果按格和物品种类缓存。实际配置启用了哪些来源、热补丁是否改变规则仍待验证。

## 4. 按时间顺序走完六条流程

以下重点区分数据何时生效、画面何时变化，以及失败发生在修改之前还是之后。

### F1. 载入：先建立业务世界，再绑定画面

1. **区分新游戏与已有存档。** `MainMergeMan.SetData` 先创建世界；没有 Merge 记录时走初始库存和棋盘初始化，有记录时先初始化棋盘，再 `World.Deserialize`。最外层账户数据或磁盘读取尚未贯通。
2. **建立格子和地块条件。** `MergeBoardMan.InitializeBoard` 调棋盘重置、参数设置、区域及云初始化；不同入口选择初始物品排列。原地图数据缺失。
3. **恢复物品及能力。** 世界和 Item 恢复身份、种类、状态、组件位图及局部进度；`Board.Deserialize` 绑定所属棋盘、格子，并恢复邻接倍率注册。
4. **处理异常输入。** 越界、重复占位以及能力验证失败会进入警告分支，再继续相应流程。警告本身不证明所有坏档都能正确修复。
5. **把业务对象显示出来。** `OnBoardEnter` 设置世界／棋盘并装配显示接口；`Holder.Setup` 准备显示格、建立物品 View、订阅事件，`CreateView／SetData` 刷外观。部分间接调用由接口与调用者交叉定位，并非运行追踪。
6. **接收输入并推进时间。** 抓取和使用入口继续检查 Item 与 View，时间由 `SyncBoard／World.Update` 推进。引导、弹窗和资源就绪的全部限制尚未覆盖，不能声称存在一个已验证的统一“准备完成”时点。
7. **再次保存当前数据。** 后续汇总从运行对象生成记录，不把动画的播放位置作为恢复依据。

### F2. 拖拽与合成：真正变化发生在动画之前

1. **抓起物品。** `CanGrabItem` 要求物品 active、未死亡、已有 View，并通过显示可拖动检查。拖动过程中首先改变的是图片位置，不是棋盘占位；也不是所有动画阶段都禁止拖动。
2. **寻找动作。** `MergeHelper` 检查候选格，按 Merge→Consume→Mix→Feed→Stack→Skill 短路选择；后两项另需技能组件。没有特殊动作才尝试移到最近格。具体拖动手感需运行确认。
3. **落手时再校验。** `OnEndDrag` 调 `Board.Merge`，再次经过 `CanMerge／GetMergeState`，从目标合成组件取得结果种类 `PeekMergeResult`。预览允许不代表最终直接跳过检查。
4. **消费旧物并建立结果。** 先消费源、目标，再在目标坐标生成新物；接着处理两次旧物消费奖励、新物生成奖励、合成后能力、环境通知、奖励处理器和邻接解锁。旧组件此时尚未最终释放，仍可供后处理读取。
5. **开始合成动画。** 最后的 `onItemMerge` 通知 Holder，取两个旧 View、清显示占位、建结果 View，并传入合成上下文。如果缺必要旧 View，已读分支没有撤销前面的业务修改。
6. **动画结束或离开状态。** 完成回调只设一个标志，随后转到空闲；`OnLeave` 停止 Tween 动画并按两个旧 ID 释放 View。动画结束没有再创建一次结果物。

**如果最终是移动或交换**，`GetMoveState` 先检查双方，交换时先移目标、再移源，两次都可发通知。失败后的 `MoveBack` 是图片回位，不能等同业务回滚。

**保存与中断边界**：存档汇总读取已经改变的数据；内部进入／离开事件早于最终合成通知。所追踪主链未见整体回滚或重入排队。中间事件可见是代码事实；异常或嵌套操作是否造成故障仍需实验。

### F3. 点击产出：费用、次数与落点并非同时确认

这条链需要区分**空格计数预检、产出消费和落点搜索**。它们发生在不同时间；找格参数也没有使用本次产物种类。

1. **检查能否使用。** 点击经 Holder 和物品使用分派进入业务；外层查所属容器、存活及 active，生成方法再查组件和 `IsNextItemReady`。未就绪时返回。
2. **准备费用和输出。** 有费用配置时，识别能源或消耗物成本，重置输出准备并做智能能量预计算，再检查资源。不足时发相应通知、清待执行动作并返回。准备缓存可能已经改变，不能泛称拒绝操作绝无写入。
3. **检查空格计数并消费。** 预检阈值随成本和输出配置变化：部分路径要求至少一格，消耗物路径可能允许零格，因为随后会移除输入物。费用配置列表为空的分支也只要求计数不小于 0，并没有拒绝满盘。通过后先扣能源或消费输入物，再由 `ConsumeNextItem` 推进次数、输出和随机位置。
4. **找格并创建产物。** 仅在产物种类为正值时搜索；参数传入生成器，却把目标种类设为 0。当前格匹配规则因此只接受默认格。成功后创建产物、处理生成奖励并通知显示；有限生成器还会处理耗尽及末次掉落。数据落位先于动画。
5. **找不到格时继续到哪里。** 失败分支记录警告，当前方法没有就地退费、恢复次数或回退随机位置；后续可返回成功状态而产物引用为空。**顺序和局部缺少补偿已确认，正式配置是否可达仍待验证。** 适当的实验是“只剩非默认格空位”或“无费用生成器在满盘时使用”，再核对外围入口是否提前拦截。
6. **保存和显示。** 汇总读取已经改变的次数、随机位置与棋盘；外部钱包是否与棋盘一起保存，尚无证据。显示失败也未见本方法撤回业务修改。

### F4. 时间推进：先补时间，再更新各自的机制

1. **取得本次要推进多久。** `SyncBoard／_SyncBoard` 进入 `World.Update`；世界从 Env 取时间，合入跳过的秒数及存档时间差，清补时标志。恢复时间差为负时不倒扣进度；恢复分支将合入后的推进量限制为最多 1,073,741,823 毫秒，约 12.43 天。这是数值保护，不能直接解释成统一的离线收益政策。后台／隐藏时调用频率和服务器时间策略尚未查全。
2. **必要时分成多段。** Board 根据邻接效果的下一检查点切段；每段先更新宝箱，再扫描格子。这样可以在效果改变的时间点重新处理倍率，但不能据此证明所有周期事件都等价于逐帧执行。
3. **更新符合资格的物品。** 只扫描未死亡且 active 的板上物品。Item 应用倍率，经组件虚方法收窄时间步，再逐项 Update，最后执行延后列表。被锁或被冻结的板上物品不会自动转入 `OnUpdateInactive`。
4. **各机制各自处理。** 点击型 `_TickRecharge` 累加毫秒，按间隔批次把待补次数转成可用次数，并保留余数；`_UpdateRecharge` 还处理复活阶段。自动型补充可用次数但不超过容量上限，随后尝试落格，找格成功才消费。宝箱推进世界等待，气泡还受广告、引导和交互保护。
5. **更新库存和其它世界状态。** `World.Update` 随后更新库存及专用世界功能。库存经 `InventoryBag.Update → Item.UpdateInactive` 推进组件，因此自动生成器在库存中可以补充次数，但不主动落物。该循环不更新售出暂存槽。最后清理待销毁物品；计时中产生的销毁可以在同次更新末尾完成，不必等下一帧。
6. **保存后重新打开。** 保存最后活动时间与组件进度，恢复后再补时间差；画面重新显示当前数据。尚不清楚杀进程前是否已写盘，也没有完整验证长离线、时钟倒退、配置变更和高级倍率组合。

**不能推出的结论**：一次补进很长时间，不等于会无限补发离线期间所有产物。自动生成有容量上限和空间约束，分段顺序也可能影响结果。应比较“逐秒推进”与“一次推进相同总时间”，再决定是否等价。

### F5. 邻接解锁：数据先解除，遮挡稍后退出

1. **合成后查四邻。** `Board.Merge` 后段调用 `_TriggerUnlockAround`，按上、下、左、右尝试 `_UnlockItem`。
2. **检查资格并修改状态。** `CanUnlock` 检查存活、锁定、云和等级等条件；通过后 `SetState(false, 原 frozen)` 解除锁。**规则从这一刻生效**，后续 active／movable 查询重新计算；冻结不会被顺手清掉。
3. **通知并继续传播。** 发出 `TriggerItemStateChange`，再由 `CanUnlockAround` 决定是否继续：仍被冻结，或带有启用的 TrigAutoSource 组件时停止传播。移除 locked 为普通有限棋盘提供了自然终止条件；若事件订阅者重新加锁，是否安全尚未验证。
4. **更新遮挡。** Holder 按上下文进入 `SetDelayUnlock` 或立即刷新；Content 刷新资源前先 `ClearCoverState` 清旧遮挡，关闭时走 ClearData。被筛掉的 DelayUnlockState 缺完整方法体，所以延迟多久、期间怎样接收输入、取消时是否总清干净仍待验证。

存档汇总记录已改变的逻辑状态，不等动画结束。不过解锁资格仍会读界面 `IsLevelDirty`，因此“数据先改”不等于整个解锁过程已完全脱离界面。

### F6. 退出棋盘：消费、售出和显示回收是三件事

**普通消费／销毁：先退出业务，再释放组件。** `_DisposeItem` 清掉仍指向该物的占位，`FinishDisposeItem → BeginDispose` 标记死亡并放入待清理列表，随后世界更新的清理阶段调用 EndDispose。死亡事件可以受参数控制，但离开事件与世界物品事件仍可能发出；显示经死亡或特殊合成状态退出，不要求动画先确认。

**售出：先移出棋盘，暂存原对象。** `SellItem` 校验占位和售出配置，清格并处理消费奖励，解除 parent，发离开／世界事件，经 `Env.SellItem` 处理售价，再 `SetSoldItem` 保留原对象并通知售出。物品及能力状态仍在，尚未走普通死亡路径；外部经济操作中断时未见整体回滚。

**撤销售出：有条件地取回同一个物品。** `UndoSellItem` 先找近空格；`GrabSelledItem` 检查能否扣回售价，成功才清暂存槽、返回原对象，再恢复棋盘关系并发 `SpawnContext(type=7)`。钱已花掉可以拒绝；没有近空格时还会检查原格。原格若是合适的普通占位物，备用分支可按其种类把它加入奖励后销毁，再放回售出物；生成器或不活跃占位物则被拒绝。按种类转成奖励不保证保留被移物的全部实例状态，这项替位政策不宜直接照搬。

**显示回收：解除绑定和监听，再放回对象池。** 单项 `ReleaseItem` 按 ID 找 View，`ClearData` 退出显示状态、清各控制器及上下文，再回池并移出字典。清全盘时 mIsClearing 防止嵌套单项释放；`Holder.Cleanup` 还退订事件、清队列并释放显示格。合成动画的停止路径已核对，所有异步加载的迟到回调则未全审。

**撤销窗口已有两个明确终点。** 离开棋盘时 `OnBoardLeave` 清槽；信息刷新选中了一个现存棋盘物品时，`_RefreshInfo` 也清槽。新售出会替换单槽内容，成功撤销则取走并清空它。`SetSoldItem` 本身只更换引用和通知，没有替旧对象调用完整死亡清理，不能把“清槽”与普通销毁等同。

**保存与回调边界**：Merge 存档没有售出暂存槽，世界常规更新也不推进它。结合上述清槽入口，较强推断这是当前棋盘交互期间的单次撤销，不能当成跨重开的操作历史。独立删除入口及其它外部处理尚未全审；同 ID 撤销或显示对象换绑后，也未定位统一绑定版本来隔离旧回调。
