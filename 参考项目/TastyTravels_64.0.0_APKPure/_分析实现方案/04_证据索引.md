## 看来源时，先分清材料种类

| 材料 | 能支持什么 | 不能直接推出什么 |
| --- | --- | --- |
| C# 类型结构 `.cs` | 有哪些字段、继承关系和方法签名 | 空方法或默认返回，不代表原游戏没有实现。 |
| 原生伪 C `.c` | 反编译出的分支、访问和调用，需交叉核对 | 反编译“成功”不保证高级语义正确。 |
| ARM 指令 `.s` | 底层实际指令，可核对伪 C 丢失或失真的路径 | 高级字段含义仍可能需要类型资料辅助。 |
| 配置／存档类型 | 字段和记录关系 | 当前目录缺原表，字段不能证明实际掉率、时长和资源值。 |
| 原提取记录、历史分析 | 来源、查找线索及待纠正的说法 | 历史分析不能用来循环证明本轮的新结论。 |

## 怎样打开一个精确位置

源码链接末尾的 `L3184` 表示文件第 3184 行；若阅读器不自动跳行，可以按这个行号打开。伪 C 条目同时列函数全名和 **RVA（原生方法相对地址）**，便于与方法索引对照；若没有另列“方法头”，链接行就是方法头。

链接标签只省略重复目录。下面的前缀加上标签剩余部分，就是完整的仓库相对路径；点击链接仍直接到原文件。

## 核验范围和技术注意事项

- 初次分析已校验原材料清单中的 1,073 个文件全部一致；此次整理仅修改本分析目录的报告，未改动原代码或共同设计文档。
- 行为结论针对包内原实现，即 IFix 未替换的方法分支；运行热补丁是否覆盖它尚待核验。本文“已确认”均限定为静态证据。
- 本次查找范围是目标包保留的 scripts、pseudo_c、方法／调用索引及相关 ARM 段。“未定位”不表示被筛掉的客户端、服务器或动态资源没有该功能。
- 已重点交叉核对 ARM 的路径包括坐标索引、合成消费／生成顺序、点击消费早于找格、点击恢复和速度工具；其余主要依据类型结构、伪 C 与调用关系，没有逐条审完全部 ARM。
- 查匿名调用时，用 native_method_index.csv 和 native_direct_calls.csv 对齐地址。本包加载后的地址 `VA = RVA + 0x10000`，不能把 Ghidra 显示的 VA 当作 RVA。
- 调用 CSV 按地址整理，只证明调用关系，不证明执行先后；虚调用和委托还要核对接口或订阅者。Ghidra 的尾调用恢复可能混入其它方法或漏掉后续代码。
