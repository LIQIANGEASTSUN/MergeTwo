# 逆向过程、精简范围与完整性

## 获取方法

- 原包：Unity 2022.3.62f2、IL2CPP 元数据版本 31，arm64-v8a。按安装包中的 `libil2cpp.so` 和 `global-metadata.dat` 逆向；输入及关键二进制 SHA-256 见 [source_manifest.json](source_manifest.json)。
- 实际运行 AssetRipper 1.3.14 / Cpp2IL 得到 C# 类型结构。导出的空方法体是工具生成占位，不能据此判断玩法行为。
- Il2CppDumper 提供类型、字段、继承、接口、方法签名和 RVA。Capstone 4 解码对应 arm64 字节。Ghidra 12.1.2 对部分地址生成伪 C。
- arm64 函数长度按 `script.json` 相邻地址推断；自动边界与显式限定边界均可能有误。虚调用、事件派发、反射及间接跳转不能由 `native_calls.csv` 的直接 `bl` 完整覆盖。

## 精简范围

本轮逐一检查了结果目录的扩展名、路径和类型索引。原目录文件类型为 `{'.md': 3, '.csv': 4, '': 5, '.json': 2, '.c': 1959, '.s': 1153, '.txt': 1400, '.cs': 1046}`，没有图片、音频、模型或动画文件；删除了 Finder `.DS_Store`、下载链接和旧版冗长索引/反编译尝试日志。保留文件类型为 `{'.md': 3, '.csv': 4, '.json': 2, '.c': 1868, '.s': 1114, '.txt': 1355, '.cs': 1008}`。

以旧棋盘、新棋盘、合成判定、生成、消耗、锁定、解锁、库存、队列、状态恢复、同步、交互为核心；通过类型声明补入基类/接口，并保留同一生成脚本中的全部嵌套类与方法。保留泡泡、能量、PowerBoost、限时物品、出售/撤销、跳过冷却等直接影响棋盘物品的机制。移除了卡牌、商店、活动、奖励展示、纯表现动画、分析埋点、安装器、模拟类与无关 UI 的逆向文件。本轮进一步按实际方法检查了库存槽位展示、队列滑移动画、棋盘格提示、生产者贴图下载与生成的 JSON 缓存，并删除对应的独立脚本。仍有少数纯展示类型名称出现在保留脚本的字段或签名中，但其实现不是分析二合规则所必需的，因此没有单独保留；当前材料不是可直接编译的工程。某些带通用名称的类型因直接继承/接口关系而保留；[code_index.csv](code_index.csv) 逐项标明原因。

类型选择是人工依据名称、字段、方法签名和已知直接调用作出的分析性筛选，不表示能证明每个未保留方法与玩法完全无关。未保留类型的调用签名也从 `native_calls.csv` 中删去；如后续发现间接依赖，需从原包重新增补。所有保留的 `.cs`、元数据块、反汇编与伪 C 均按原文件字节复制，未删改脚本内部其他类或方法。

## 实现覆盖

| 层级 | 当前保留 | 含义 |
|---|---:|---|
| 元数据类型 | 1355 | 类/结构/接口/枚举声明 |
| 元数据方法声明 | 7578 | 签名、字段上下文；其中 1707 个无直接 RVA |
| 常规原生地址 | 5871 | 对应 arm64 指令，长度为推断值 |
| 泛型专门化地址 | 1044 | 对应独立原生实例，可能关联无直接 RVA 的声明 |
| 自动边界伪 C 文件 | 1760 | Ghidra 工具生成，不是 C# 实现 |
| 显式推断边界伪 C 文件 | 108 | Ghidra 工具生成，不是 C# 实现 |
| 至少一种伪 C 的原生地址 | 1791 | 可读程度和语义准确性需逐方法核查 |

`method_index.csv` 和 `generic_instantiations.csv` 对每个保留方法列出 `native_status`、原生字节 SHA-256、可用的伪 C 路径。无 RVA 的声明仅有签名；有 RVA 但伪 C 路径为空的方法保留了反汇编，不能把 C# 空方法当成实现。由于编译优化、共享泛型、缺失运行时类型和边界推断，伪 C 可能有变量/类型/控制流误判。

## 文件完整性

当前目录仅包含 `.cs`、`.txt`（元数据代码块）、`.s`、`.c` 及用于定位和审计的 `.csv`、`.json`、`.md`。各类型的 `generated_csharp_sha256` 可与保留脚本核对；原包和逆向工具未修改。
