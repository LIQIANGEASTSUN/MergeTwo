## 从这里开始：这个棋盘是怎样工作的

**本报告重点还原的新棋盘实现采用 ECS：一件物品是一个实体，组件保存它的数据，共享系统执行玩法规则。**物品的画面对象另外管理，接收规则执行后的结果。你可以先记住这四个角色，再进入源码细节。[E04–E06](04_证据索引.md#e04)、[E10](04_证据索引.md#e10)、[E19–E20](04_证据索引.md#e19)

例如，两件同种物品各有自己的身份、位置和合成数据。玩家把它们拖到一起后，规则系统判断能否合成；成功时创建新物、标记旧物退出，再通知界面显示结果。**业务数据先改变，动画随后呈现。**这个先后关系比记住类名更重要。[E14–E19](04_证据索引.md#e14)

它的功能组合也沿用这一思路：生成器保存产物队列和次数，周期系统处理时间，锁或箱子数据限制操作。一次点击可能由几个系统共同完成。解除一种限制，只应修改对应的数据，其它能力和进度仍有自己的归属。[E23–E28](04_证据索引.md#e23)、[E31–E33](04_证据索引.md#e31)

阅读时保留两个范围判断：目录里同时有旧、新两套实现，尚不能确定主棋盘实际启用哪套；新路径虽把业务和显示对象分开，找空位和邻格仍会读取界面布局坐标。因此，“采用 ECS”并不等于已经完全不依赖画面。[E03](04_证据索引.md#e03)、[E07–E09](04_证据索引.md#e07)
