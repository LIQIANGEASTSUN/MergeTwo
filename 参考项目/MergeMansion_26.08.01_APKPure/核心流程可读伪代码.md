# 核心流程可读伪代码

这是对 **Ghidra 原生伪 C、Cpp2IL 方法地址、AssetRipper 类型/枚举** 的人工释读，便于阅读，不是原始 C#，也没有替换任何工具导出文件。省略了 IL2CPP 类型初始化、空指针异常路径及底层对象布局。只写下能从下方证据对上的分支；未写出的分支不表示游戏中不存在。

## 合成、移动与交换分派

证据：`native/Ghidra-C/0x03679224.c`；`native/Ghidra-C/0x0367930C.c`；`source/AssetRipper/Metacore.MergeMansion.SharedLogic/MergeResult.cs`；`伪C调用地址映射.csv`。

```text
ProcessMergeOrMoveAttempt(from, to, time, player, ...):
    result = GetMoveResult(player, from, to, time)
    if result == Swap:          ProcessSwap(from, to, time, player, false)
    else if result == MergeHappens: ProcessMerge(from, to, time, player, ...)
    else if result == Move:     ProcessMove(player, from, to, time)
    return result
```

`0x0377930c`、`0x0377986c`、`0x03779dcc`、`0x03779798` 分别映射到 `GetMoveResult`、`ProcessSwap`、`ProcessMerge`、`ProcessMove`。数值 4/3/2 对应 `MergeResult.Swap`/`MergeHappens`/`Move`。这是可核对的**分派片段**；不能据此认为 `GetMoveResult` 的所有判定分支都已人工还原。

## 坐标与移动结果的部分判定

证据：`native/Ghidra-C/0x036839A8.c`、`native/Ghidra-C/0x0367930C.c`；`MergeBoard.cs`、`Coordinate.cs` 的签名与 `MergeResult.cs` 枚举。

```text
InvalidOrSameCoordinates(from, to):
    return !board.IsValid(from) || !board.IsValid(to) || from.Equals(to)
```

`GetMoveResult` 的伪 C 中可直接辨认的返回分支：

| 观察到的条件 | 返回的 MergeResult | 依据 |
| --- | --- | --- |
| 起点或终点无效 | `InvalidPosition` (1) | 两次 `IsValid` 调用后返回 1 |
| 起点和终点相同 | `Nothing` (0) | `Coordinate.Equals` 后返回 0 |
| 起点无物品，或起点物品不能移动/不可见 | `Nothing` (0) | `get_Item`、`IsMovable`、`get_IsVisible` 后返回 0 |
| 终点无物品 | `Move` (2) | 终点 `get_Item` 为空后返回 2 |
| 满足一条已识别的双方合成条件 | `MergeHappens` (3) | `SupportsMerge`、`MeetsMergeChainLevelForMerge` 与 `CanBeMergedWithItem` 调用后返回 3 |
| 已对目标拍照 | `PhotoOfItemAlreadyTaken` (10) | `CheckPhotoOfItemAlreadyTaken` 后返回 10 |

此表是**部分判定**。同一函数还涉及可见性、消耗物、神器物品、等级限制和移动/交换回退；其条件组合需结合间接调用与异常路径继续验证，不能把上表当成完整判定顺序。

## 玩家移动动作入口

证据：`native/Ghidra-C/0x0372A9B0.c`，对应 `TryMergeBoardMove.Execute(PlayerModel player, bool commit)`；地址 `0x0367263C`、`0x0377930C`、`0x03779798` 分别映射到 `TryGetMergeBoard`、`GetMoveResult`、`ProcessMove`。

```text
board = player.TryGetMergeBoard(boardId)
if board 存在且 commit:
    result = board.GetMoveResult(player, from, to, actionTime)
    if result != Move: 返回某个 MetaActionResult 常量（名称未还原）
    movedCoordinate = board.ProcessMove(player, from, to, actionTime)
    若 returnList 存在：加入 movedCoordinate
返回 MetaActionResult 常量（成功/失败名称需继续核对）
```

伪 C 能确认 `commit` 分支、`Move` 枚举值比较和这两个方法调用；静态 `MetaActionResult` 字段的具体语义目前没有据此命名。

## 手动生成到棋盘

证据：`native/Ghidra-C/0x03680064.c`、`source/AssetRipper/Metacore.MergeMansion.SharedLogic/BoardStepResult.cs`，以及调用地址映射。`0x037c7a80`、`0x03774f00`、`0x034ba710`、`0x034ba7d8` 分别映射到 `PlacementExtensions.TryGetEmptySpot`、`MergeBoard.AddItem`、`MergeBoardAct` 两个构造函数。

```text
SpawnToBoard(player, definition, spawnedFrom, time, bubbled, generationContext, source):
    if placement.TryGetEmptySpot(spawnedFrom, board, out spot):
        board.AddItem(player, spot, definition, generationContext, time, ..., bubbled)
        return new MergeBoardAct(ManualSpawned, spawnedFrom, spot, time, ..., source)
    else:
        return new MergeBoardAct(spawnedFrom)
```

`ManualSpawned` 来自构造函数实参 3 与 `BoardStepResult` 枚举。省略号代表 Ghidra 未恢复出的参数类型/默认值，不能用来推断完整参数语义。

## 移动与从棋盘移除

证据：`native/Ghidra-C/0x03679798.c`、`0x036789BC.c`、`0x036868CC.c`。相关调用地址分别指向 `MergeBoard.get_Item`、`PlacementExtensions.TryGetEmptySpot`、`MergeBoard.set_Item`、`RemoveItem`、`DoRemoveItem`、`ItemAttachmentsState.ConsumeAttachments`、`UpdateListOfBoostedCoordinates` 和 `ApplyBoosts`。

```text
ProcessMove(player, from, to, time):
    resolvedTo = to
    if board[to] 为空，或 placement.TryGetEmptySpot(to, board, out resolvedTo):
        board[resolvedTo] = board[from]
        RemoveItem(player, from, time, consumeAttachments=false)
        更新受增强效果影响的坐标并重新应用增强效果
        记录棋盘变动时间
        return resolvedTo
    return from

DoRemoveItem(coordinate, player, consumeAttachments):
    item = board[coordinate]
    if item 存在且 consumeAttachments 且其附件状态存在:
        调用 ItemAttachmentsState.ConsumeAttachments(...)
    board[coordinate] = null
    return item

RemoveItem(player, coordinate, time, consumeAttachments):
    item = DoRemoveItem(coordinate, player, consumeAttachments)
    更新增强效果与棋盘变动时间
    return item
```

`DoRemoveItem` 中获取附件状态的调用地址尚未匹配到保留方法索引，所以这里只按返回对象和后续 `ConsumeAttachments` 调用描述该分支；不把未知调用擅自命名为某个 getter。

## 继续阅读时的边界

- `native/Ghidra-C/*.c` 是工具原样输出；`伪C质量初筛.csv` 标记明显跨出 Cpp2IL 指令范围或异常膨胀的结果。初筛通过也**不是**正确性证明。
- 例如 `WouldBeValidSinkAttempt` 的 Ghidra 输出含大量“不可达块被删除”警告，主体近似坐标检查；不能把它当作完整的吞噬判定实现。
- 3 个未得到伪 C 的方法仍可在 `native/Cpp2IL-ISIL/` 中查看关联指令。对这些方法和所有被初筛标记的函数，应优先以原生指令及调用证据继续核对。
