# 二合设计与实现思路

这个样本最值得学习的不是某个类或某段算法，而是它把二合玩法拆成了三层：**可复用的棋盘规则、带局部能力的物品、按活动变化的规则与配置**。主棋盘和多个活动棋盘共用移动、合成、生成、占位等基础机制，再分别决定棋盘尺寸、能否售出、解锁方式和溢出物品去向。这样做让新棋盘主要增加差异规则，不必重写整套合成；代价是扩展点必须明确，否则例外会散在各处。

## 它如何组织一局二合

**物品身份与位置分开。** 配置类型决定物品是什么，实例 ID 标识棋盘上的这一件物品，位置由棋盘占位关系记录。创建时按配置装配生成、领取、吞入、变换等局部能力，能力自己保存次数、时间和阶段。生成器仍有互斥的开启阶段；“组件化”负责组合行为，“状态机”负责同一行为的生命周期，两者解决的问题不同。

**一次拖放由棋盘统一裁决。** 先检查被拖动的是否仍是原实例、目标位置是否可用，再按既定优先级判断移动、特殊作用、合成、吞入、交换或拒绝。这个顺序本身就是玩家可感知的玩法规则。合成会消耗旧物、在目标格产生新物，并让四向邻物响应冲击；蛛网、纸箱等包装物可以因此解除。包装物保存的是内部物品的创建描述，解除时再替换成内部物品，所以它适合“未解锁前内部物品无需继续运行”的设计，不能直接等同于给原实例叠加多个可独立解除的效果。

**产物不是只靠一次随机数决定。** 生成器分别管理当前可产出量、储备量、短恢复和长恢复；选产物、找落点、扣费是不同步骤。一种被命名为“固定”的产物策略，实际是按物品类型共享的有限权重池：每抽中一项便扣减剩余份数，整池耗尽后重置并保存进度。基础配置里有一个 35／2／5 的例子：完整一池的 42 次产出数量受约束，但顺序仍随机。它既不是每次独立抽样，也不是每个生成器实例开头播放固定序列。这个设计的关键在于**分布由谁拥有、何时重置**，两个同类型生成器可能共享同一池。

**空间不足时保留玩家已获得的价值。** 不同棋盘把放不下的物品暂存为“完整物品”或“物品创建描述”：前者保留实例状态，后者只保留重新创建的资格。活动棋盘滚屏时，也会按物品性质选择暂存、领取或移除；满盘判定并非只看格子占满，还要看是否有可合成的一对或可领取物。生成器加成产生的额外产出在没有空位时可记为待兑现状态；有些棋盘在合成生成器时，会把旧生成器未吐出的有限产物送入暂存。这些处理共同解决了“满盘、升级、切场景时不凭空吞掉价值”的问题，但究竟保留对象还是仅保留产物资格，需要明确产品规则。

**活动改规则，但不另造一套棋盘。** 活动棋盘可选择按合成线等级或迷雾解锁来滚屏，也可重定售出限制、障碍处理和物品暂存顺序；部分限时加成会切换生成器配置，另用有限池控制“额外产出”的出现次数。配置切换与剩余池存档一起使用，能让活动节奏变化而不重造基础机制；与此同时，配置变更后的旧实例和旧池如何迁移必须设计清楚。

## 我认为值得借鉴与值得改进的地方

| 主题 | 可借鉴的设计思想 | 用到你的方案时要补上的约束 |
| --- | --- | --- |
| Function／Effect／State | 用能力组件组合行为，用局部状态机描述阶段；包装物用于解除前无需保留内部实例运行状态的机制。 | 同类多个效果、不同来源叠加、独立解除和身份连续性需要单独定义。先问限制附着在物品还是格子，再决定是包装、Effect 还是 State。 |
| 合成结算 | 统一入口保证一次拖放只有一个主结果；模型先产出业务变化，旧物视图随后退场，动画不阻塞规则。 | 样本在附加产物全部结算前已发出合成消息，且可见代码没有证明整批回滚。你的无界面核心宜先求完整结果，再一次提交和发布。 |
| 生成器经济 | 把次数恢复、产物分布、落点和费用分开；有限池可压低短期随机波动。 | 固定序列、独立概率和有限池语义不同。明确池属于实例、类型还是棋盘，以及满盘时是否保留额外产出资格。 |
| 棋盘扩展 | 共享基础交互，棋盘变体只实现尺寸、解锁、限制和产物回收等差异。 | 保持扩展点少而明确；同一规则在主棋盘与活动棋盘不能因为覆盖顺序而悄悄分叉。 |
| 保存与撤销 | 保存物品的运行进度，并把物品身份与占位关系分开；售出撤销保留待恢复对象。 | 不能仅凭客户端代码认定跨物品、占位、货币的原子存储。样本对原格被占会尝试迁位，与你倾向的“原格被占即撤销失效”不同。 |

还有两点应当视为**样本的取舍，而非最佳实践**。一是气泡到期由模型计时，但界面选中时会改写“暂不破裂”的业务标记；如果你要求无 Graphic 也能算出同样结果，选中保护应由逻辑输入决定。二是自动跑盘工具会按权重尝试操作、记录日志并在失败时停止，适合发现长局面问题；但它不能替代针对身份、数量、占位和存档恢复的不变量验证。

对三合的迁移也有边界：物品身份、能力组合、存档、空间暂存与棋盘变体都可复用；**参与集合、一次消耗多少件、产出多少件、落点和效果继承**必须作为新的合成规则整体求解，不能把二合连续执行两次。

以上是对客户端可见实现的归纳与我的设计判断。锁属于物品还是格子、生成器升级后进度是否继承、多产物遇到一个空位如何结算、售出撤销期间时间是否流逝，仍应由你的玩法规格决定。
