# Gossip Harbor 3.99.0：它怎样实现二合玩法

> Gossip Harbor 3.99.0（版本号308）｜2026-09-25｜依据恢复的Lua代码做静态分析，未运行游戏。

## 先看三个关键发现

**它把“棋盘上实际有什么”和“画面怎样播放”分开了，但并非所有玩法都分得彻底。** 普通合成时，旧物品先从棋盘数据中删除，新物品先建立，画面随后播放合成动画。可是批量吞入要等物品飞到目标，才真正消费物品；某些活动障碍也等动画回调后才解除区域锁。因此，不能仅凭代码分成Model和View，就认定所有规则都能脱离画面运行。[E10](04_证据索引.md#e10)、[E19](04_证据索引.md#e19)、[E31](04_证据索引.md#e31)

**纸箱、蛛网和气泡主要靠“替换物品”实现。** 看起来像是在同一个物品上去掉遮挡，代码却是删除外层物品，再根据内部编码创建新物品。原先并没有一个持续运行的内部生成器。这种做法适合初始地图中的待解锁物；如果要临时冻结一个已有生成器，并保留其身份和冷却进度，就需要不同的处理。[E06](04_证据索引.md#e06)、[E17](04_证据索引.md#e17)、[E18](04_证据索引.md#e18)

**“有生成能力”和“现在能生成”是两件事。** 同一个生成器可以处于未开启、开启中或可用阶段，还可能因为次数、空间、费用不足而暂时不能产出。代码同时保留能力和这些状态，这正好说明：组合能力并不意味着应当取消所有业务状态。[E12](04_证据索引.md#e12)、[E13](04_证据索引.md#e13)

## 资料能证明到哪里

本次追读了主棋盘载入、拖放、合成、生成、售出撤销，以及物品创建、显示和回收路径；抽查了活动迷雾、区域障碍、容器、时间和同步代码。**没有逐行读完当前保留的376个模块**。

事件总线、底层存储、编号生成器、钱包和资源加载等部分实现已不在保留资料中。因此，异常发生后如何恢复、何时真正写入磁盘、整个应用怎样调度，仍不能完整确认。[E36](04_证据索引.md#e36) 材料版本和752项哈希核对记录见[04检查记录](04_证据索引.md#checks)。

本次只修改分析报告；对[既有分析](../二合设计与实现思路.md)的修正说明见[03末节](03_借鉴评估与待验证问题.md#historical-review)。
