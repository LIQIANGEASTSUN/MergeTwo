# Merge Cooking 是怎样实现二合棋盘的

本报告分析目录标注为 **Merge Cooking 1.59.0** 的恢复代码，整理日期为 **2026-09-25**。先说明它实际怎么工作，再讨论哪些做法适合我们的设计。版本尚无原包元数据核对；本次只读代码，没有运行游戏。

## 先看这个项目最重要的特点

这个项目把“物品记录”“物品行为”和“物品画面”分成了不同的类，但它们的职责仍有交叉。规则代码和界面代码往往拿着**同一份物品记录**，界面不仅显示状态，也能修改状态。因此，有独立的数据类，并不意味着关掉界面后规则就能独立运行。[E04](04_证据索引.md#e04)/[E09](04_证据索引.md#e09)

合成和生成的大部分常规流程会先改数据，再播放相应动画。例如，普通合成先把目标格换成新物品、清空原格，再播放合成动画。不过，有一种转换器会等进度动画结束后才补充可用次数。两种顺序在同一项目里并存，分析时需要逐条流程判断。[E11](04_证据索引.md#e11)/[E19](04_证据索引.md#e19)

最值得借鉴的是它对几件事情的区分：**位置上的锁与物品自身的限制、恢复生成次数与真正生成物品、修改内存与写入磁盘**。需要谨慎借鉴的，则是界面参与规则、多个步骤分别修改数据，以及动画和回收后的旧回调问题。[E13](04_证据索引.md#e13)/[E16](04_证据索引.md#e16)/[E17](04_证据索引.md#e17)/[E23](04_证据索引.md#e23)/[E29](04_证据索引.md#e29)

这些实现细节有源码支持；其中风险能否在真实游戏中触发，仍需配置或运行验证。

## 文中几个常用词

| 用词 | 本报告中的意思 |
| --- | --- |
| 物品记录（VO） | 保存某一个物品的编号、状态、次数、时间等数据；代码名为 GameGoodsVo。 |
| 行为对象／能力（Attribute） | 执行产出、冷却等规则的代码对象。这里的 Attribute 不只是一个数值属性。 |
| 界面对象（View） | 屏幕上的格子、图标、遮挡和动画，以及管理它们的代码。 |
| 实例编号／种类编号 | 实例编号区分“这一件”和“另一件”；种类编号表示它们是什么物品。 |
| 补间动画（Tween）／回调 | 前者让位置、进度等随时间变化；后者是在动画完成等时点执行的一段代码。 |
| 回收／对象池 | 物品画面用完后保留起来，供下一个物品重复使用，因此必须防止旧动画影响新绑定。 |
| 冷却（CD）与次数库存 | 冷却是等待补充次数的过程；次数库存是当前还能生成几次，不是已经生成的物品。 |
| 实验分支（AB） | 根据实验配置选择不同实现；看到分支代码不代表所有玩家都走这条路径。 |
| 预制资源（Prefab） | Unity 中预先制作的界面或物品模板，决定节点、材质和部分输入绑定。 |
| 恢复 C#／IL | 前者是便于阅读的恢复代码，后者是用于核对分支和写入顺序的中间指令；两者来自同一份材料。 |
| 标脏 | 记下“数据已改，需要保存”；此时不一定已经写入磁盘。 |
| 批量执行（Batch／Apply） | 我方设计中集中应用一组数据修改的阶段；它不自动提供失败回滚。 |

结论标记也有不同含义：**已确认（静态证据）**表示代码里直接可见；**较强推断**表示依据代码作出的判断，仍有条件；**待验证**表示还缺关键材料。正文中的 E 编号可点击查看源码证据，[C01](04_证据索引.md#c01) 用于查我方设计背景。
