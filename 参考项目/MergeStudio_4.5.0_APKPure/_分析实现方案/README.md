# Merge Studio 4.5.0：它的二合棋盘是怎样实现的

这份报告想回答一个具体问题：**玩家拖动、合成或点击生成器时，游戏怎样修改棋盘，又怎样把变化显示出来？** 阅读时不必先记住类名；正文会先解释作用，再给出对应代码名称。

## 先看结论

**它把棋盘数据和画面对象分开存放，但经常由同一个 Unity 脚本同时修改数据和处理画面。** 例如，物品记录保存位置、剩余生成次数和覆盖状态；物品控制器处理点击、拖动和动画，同时也会扣次数、解除限制。因此，它有数据与画面的区分，却还不是可以直接脱离 Unity 运行的规则核心。这是已确认的静态结论。[架构证据 MS02、MS04](04_证据索引.md#ms02)、[扣除证据 MS22](04_证据索引.md#ms22)

几个值得学习的做法很具体：格子只保存位置和地块状态；“能不能拖动”和“能不能作为合成目标”分别判断；生成器到期恢复次数，与到期自动放出物品分开处理。拆箱时还有一个有用的细节：如果物品仍带 Jelly 限制，拆掉箱子也不会立即恢复移动能力。[权限证据 MS19](04_证据索引.md#ms19)、[时间证据 MS25–MS26](04_证据索引.md#ms25)、[拆箱证据 MS29](04_证据索引.md#ms29)

最需要谨慎的地方是一次操作涉及多次修改：物品坐标、格子里的物品、生成次数和费用分别更新。我们能看到这些写入顺序，但还不能证明失败时一定会留下错误状态。合成最终提交、实际保存到磁盘、对象回收后的旧动画处理，也缺少关键实现，暂时不能判断是否可靠。
